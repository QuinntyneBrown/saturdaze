The anchor: the upcoming Saturday

/// <summary>Saturday itself, the Saturday of a Sunday, or the next Saturday on a weekday.</summary>
public static DateOnly ResolveUpcomingSaturday(DateOnly today)
{
    return today.DayOfWeek switch
    {
        DayOfWeek.Saturday => today,
        DayOfWeek.Sunday => today.AddDays(-1),
        _ => today.AddDays((int)DayOfWeek.Saturday - (int)today.DayOfWeek)
    };
}

IngestionRunner.RunAsync puts this date into IngestionContext.ThisWeekend.

WebJob and singletons

  • run.sh hard-codes --type all: events-only needs a second WebJob folder or a script change.
  • One scheduler per catalog. There is no distributed lease across replicas.
  • The WebJob's "is_singleton": true and a single Worker replica keep passes from overlapping.

The weekly workflow

  1. Earlier in the week, only after a prompt or setting change: saturdaze ingest --type events --dry-run
  2. Friday 08:00 UTC: the scheduled pass runs
  3. Friday morning: read the newest IngestionRuns rows
  4. Before Friday evening: clear the moderation queue at /review-submissions
  5. Only if step 3 found a problem: fix the cause, rerun by hand

Dry run: deliberate, not a habit

Does

  • Calls Claude with the real prompts
  • Parses and counts valid / rejected rows

Does not

  • Write catalog rows or audit rows
  • Count against the daily budget
  • Cost nothing: it still spends tokens

Recovering a failed pass

  1. Read ErrorMessage on the Failed row.
  2. Transient (timeout, 429, 5xx): the client already retried once after 30 s. Wait, then saturdaze ingest --type events.
  3. Configuration (missing key, endpoint): fix it first, then rerun.
  4. MaxRunsPerDayPerType defaults to 48; a few manual reruns never hit it.

Trust the audit rows, not the green tick

Run-once exits cleanly even when a catalog fails

Pitfalls

  • Moved event = new row. The start date is part of the natural key.
  • No pruning. Past events stay; the date filter hides them. Row count ≠ this weekend.
  • Moving home. Old rows keep drive times measured from the old home.
  • Dry run skips the database. Field-length problems surface only on a real pass.

Things to remember

Twice-seen weekends. One pass covers two weekends, so weekly is enough.
Friday 08:00 UTC. After organizers publish, before families plan.
Split cadence. Events weekly · activities monthly + season change · restaurants quarterly.
Read the audit rows. Zero items is an alert.
Safe reruns. Natural key upserts; the daily budget guards the bill.
