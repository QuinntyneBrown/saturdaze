A function that records its calls

matchers read ittoHaveBeenCalledWith

Two forms

vi.fn()

Does nothing, returns undefined, records every call

vi.fn(impl)

Runs impl, returns its result, still records every call

A bare mock as an output subscriber

  it('writes the value to the clipboard and emits copied', async () => {
    const spy = vi.fn();
    fixture.componentInstance.copied.subscribe(spy);

    button().click();
    await flush();

    expect(writeText).toHaveBeenCalledWith('https://saturdaze.app/s/abc123');
    expect(spy).toHaveBeenCalledWith('https://saturdaze.app/s/abc123');
  });

Subscribe, act, check

  • A listener that remembers; nothing programmed
  • 14 component specs, 25 output subscriptions
  • output() still supports subscribe, so no host component is needed

Two details worth copying

The fake does real work

load sets the signal that list() returns: loading → ready, no HTTP

list is not a mock

Interface-driven services make the seam

export const SAVED_SERVICE = new InjectionToken<ISavedService>('SAVED_SERVICE');
    { provide: SAVED_SERVICE, useExisting: SavedService },
  private readonly saved = inject(SAVED_SERVICE);

The page injects the token, never the class: a fake is one provider line.

The trade-off

Cheap and flexible

Program any shape with mockReturnValueOnce (video 10)

Unchecked

The fake is not checked against the contract; saved is any and implements 6 members

Choose deliberately

Strict Mock<…>

Small, stable callbacks: forms onChange, the clipboard

Loose ReturnType<typeof vi.fn>

Large fake services where a test touches a few members

Pitfalls

  • Wrapping every member in vi.fn
  • Building a fake in the describe body without resetting it
  • Reaching for vi.mock instead of a provider
  • Awaiting a bare mock's undefined result

Things to remember

A mock records its calls on .mock
Bare for listeners, vi.fn(impl) for results
Fakes via tokens and useValue
No vi.mock on relative imports
Strict Mock for small callbacks, loose for big fakes
