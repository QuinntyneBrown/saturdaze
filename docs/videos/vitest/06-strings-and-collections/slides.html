Pitfalls

  • toContain for objects in an array: it compares references
  • classList.contains(…) then toBe(true): an unhelpful failure
  • Unanchored patterns when you mean the whole value
  • Stacked toContain calls when order matters

Things to remember

toContain: substring · class · === member
Pass the class list or string itself
.not.toContain proves nothing leaked
toContainEqual: a deeply equal member
Anchored toMatch for generated values
toHaveLength over .length + toBe
Order matters? Map and toEqual
