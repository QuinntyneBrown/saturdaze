vi.setSystemTime

Move the clock without running a single timer.

Half of advancing

vi.advanceTimersByTime(ms)

Moves the clock and runs every timer due on the way

vi.setSystemTime(time)

Moves the clock. Nothing fires.

One call in the repo: components/src/lib/tooltip/tooltip.spec.ts

Each test starts a minute after the previous one started, beyond anything a test advances.

Right after you install fake timers, a time relative to Date.now() is relative to real time, not to the previous test's fake time.

Separate tests by moving the clock monotonically, or reset the module state.

Pitfalls

  • Using setSystemTime when timers need to fire
  • Assuming Date.now() + n separates one test from the next
  • Module-level state surviving between tests (isolate: false)
  • Order-dependent tests: run one alone, or last, to check

Things to remember

setSystemTime: clock moves, no timer runs
Fake clock starts at the real time
Module state outlives a test
Move the clock monotonically to separate tests
