How fake timers work

vi.useFakeTimers()install fake clock
→
setTimeout(cb, ms)queued, not run
→
vi.advanceTimersByTime(ms)runs due timers, in order
→
vi.useRealTimers()real functions back

advanceTimersByTime(ms)

  • Moves the fake clock forward by ms
  • Runs every timer due inside that window, in order
  • Synchronously, before the call returns
  • Timers scheduled by those callbacks run too, if due in the window

Defaults (Vitest 4.1)

What is faked

Every timer API it knows (setTimeout, setInterval, Date, …) except nextTick and queueMicrotask

So promises still work

Microtasks are never faked. The clock starts at the real current time.

A one-minute cooldown

  protected async resend(): Promise<void> {
    if (this.resent() || this.submitting()) return;
    this.submitting.set(true);
    try {
      await this.session.forgotPassword({ email: this.email() });
    } catch {
      // Same as above: no account-existence leak.
    } finally {
      this.submitting.set(false);
      this.resent.set(true);
      setTimeout(() => this.resent.set(false), 60_000);
    }
  }

Two ways to always restore

afterEach

Copy field, tooltip: every test in the file

try … finally

Reset password: the one test that fakes

Both run when an assertion fails, so the fake clock can't leak (isolate: false).

Synchronous or async?

advanceTimersByTime

Runs due callbacks synchronously. Enough when a callback just sets a signal: all three here.

advanceTimersByTimeAsync

Lets promises settle between timers. For a callback that awaits, then schedules again.

Not used in this repo: the async variant, runAllTimers, runOnlyPendingTimers.

Pitfalls

  • Installing fake timers after the timer was scheduled
  • Not restoring real timers (use afterEach or finally)
  • Awaiting settle() (a 0 ms setTimeout) while timers are fake
  • Testing only one side of a delay
  • Forgetting detectChanges() after the callback changes state
  • Faking more than you need

Things to remember

Fake clock: nothing runs until you advance
Advance runs due timers, synchronously, in order
Boundary from both sides: 1999, then 1
Install before scheduling; narrow with toFake
Restore in afterEach or finally
