Pitfalls

  • toBeFalsy / not.toBeTruthy for a missing element — '' passes too
  • Mixing null and undefined for absence — normalize with ?? null
  • Relying on toBeDefined, which passes for null
  • A truthy rejection as the only check when the error is the behaviour
  • Assertions in loops without a message

Things to remember

toBeNull for absent elements
?? null: one kind of absent
toBeUndefined when it means something
toBeTruthy proves something, not what
toBeTypeOf · toBeGreaterThan: kind and direction
A message for every looped assertion
