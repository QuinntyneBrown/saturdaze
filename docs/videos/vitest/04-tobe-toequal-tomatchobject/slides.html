What toEqual ignores

toEqual

Ignores undefined properties and class types

{ a: 1, b: undefined } equals { a: 1 }

toStrictEqual

Checks both

Not used here: view models are plain objects

Choosing

toBe

A primitive, or the very same object

toEqual

The whole structure must match

toMatchObject

Only some properties matter to this test

Pitfalls

  • toBe with an object or array literal
  • toEqual on a large view model when two fields matter
  • Expecting toMatchObject to treat arrays as subsets
  • not when you could state the expected value

Things to remember

toBe = Object.is: value or identity
toEqual: contents, recursively
Map a list, then toEqual
toMatchObject: a subset of properties
Nested arrays must match in length
not sparingly
