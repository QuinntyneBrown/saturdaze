Spy on, or fake?

vi.fn()

The code receives the dependency: a fake service through an injection token

vi.spyOn(obj, 'method')

The code reaches for a real object: a global, or a service the test bed created. Remembers the original.

Spying on the router

  it('routes a plain click on an in-app href through the router', () => {
    const router = TestBed.inject(Router);
    const navigate = vi.spyOn(router, 'navigateByUrl').mockResolvedValue(true);
    fixture.componentRef.setInput('href', '/weekend');
    fixture.detectChanges();

    expect(click(inner())).toBe(true);
    expect(navigate).toHaveBeenCalledWith('/weekend');
  });

No chained call → the spy calls through to the real method.

Who owns the object?

Test bed owns it

Router: TestBed resets between tests, the next test injects a fresh one. The spy dies with the old instance.

Nobody resets it

console, window: a spy lives until you restore it.

Why silence console.error?

  async loadCurrent(): Promise<void> {
    try {
      const dto = await firstValueFrom(
        this.http.get<WeekendDto>(`${this.baseUrl}/api/weekends/current`),
      );
      this.apply(dto);
    } catch (err) {
      if (err instanceof HttpErrorResponse && err.status === 404) {
        this.apply(null);
        return;
      }
      console.error('WeekendPlanService.loadCurrent failed', err);
      throw err;
    }
  }

Replace for the test, then remove

vi.spyOn(console, 'error').mockImplementation(() => undefined);
  • The original is replaced while the spy is in place
  • console is a global and isolate is false
  • Not restored → later tests and files lose their error output

Style 1 · afterEach (robust)

  beforeEach(() => {
    vi.spyOn(console, 'error').mockImplementation(() => undefined);
    TestBed.configureTestingModule({ ... });
    service = TestBed.inject(WeekendPlanService);
    httpMock = TestBed.inject(HttpTestingController);
  });

  afterEach(() => {
    httpMock.verify();

Spying without replacing

  it('removes the window listener when destroyed', () => {
    const remove = vi.spyOn(window, 'removeEventListener');
    fixture.destroy();
    expect(remove).toHaveBeenCalledWith('scroll', expect.any(Function));
    remove.mockRestore();
  });

No implementation → the real method still runs. The spy only records.

What restore actually does

spy.mockRestore()

Clears recorded calls and puts the original method back on the object

vi.restoreAllMocks()

Does that for every spy created with vi.spyOn

As of Vitest 4.1

Restore all mocks skips vi.fn

function createMockInstance(options = {}) {
  const { originalImplementation, restore, /* … */ } = options;
  if (restore) {
    MOCK_RESTORE.add(restore);
  }
}
function restoreAllMocks() {
  for (const restore of MOCK_RESTORE) {
    restore();
  }
  MOCK_RESTORE.clear();
}

Only spyOn passes a restore.

Spies instead of module mocks

vi.mock('./x')

Not supported on relative imports by the Angular unit-test builder (dev-state.spec.ts)

Inject or spy

Fake what you inject with vi.fn + a provider; spy on what you can't inject

Pitfalls

  • A spy with no implementation calls through
  • Restoring at the end of the test body instead of afterEach
  • Expecting vi.restoreAllMocks() to clear a vi.fn
  • Spying on a global without restoring it (isolate: false)

Things to remember

spyOn wraps a real method; vi.fn is new
Chain a mock to stop the real method
Test bed objects reset; globals don't
Restore in afterEach
restoreAllMocks restores spies only
