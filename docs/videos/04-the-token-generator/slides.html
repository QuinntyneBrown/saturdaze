The generator: generate-tokens.mjs

How ~90 lines of Node turn a TypeScript theme into a stylesheet — and keep CI honest.

Why generate at all?

Performance

Static CSS: first paint already has every token. No flash, no waiting on script.

One source

The TS theme is the only place values are written. CSS is an output.

Typed object

tokens.ts for free — TS code never copies a hex value.

Two npm scripts, one file

"tokens": "node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON scripts/generate-tokens.mjs",
"tokens:check": "node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON scripts/generate-tokens.mjs --check",
  • npm run tokens — regenerate
  • npm run tokens:check — fail if stale

The header says it all

// Token pipeline: renders the TypeScript theme in
// projects/components/src/lib/tokens/ into the two generated files the rest
// of the workspace consumes —
//
//   src/lib/styles/_tokens.scss   the `:root` custom properties (+ responsive retunes)
//   src/lib/tokens/tokens.ts      the typed `tokens` object (`var(--name)` per key)
//
// Usage (from frontend/):  npm run tokens          regenerate
//                          npm run tokens:check    fail if either file is stale (CI)
//
// Node strips the token sources' TypeScript types natively; the resolve hook
// only adds the `.ts` extension Angular-style imports leave off.

Node runs the real TypeScript

Type stripping

On by default from Node 22.18. CI pins NODE_VERSION: '22'.

The snag

Sources import Angular-style, without extensions:

import type { Theme } from '../types';

A six-line resolve hook

registerHooks({
  resolve(specifier, context, next) {
    if (specifier.startsWith('.') && !/\.[cm]?[jt]s$/.test(specifier)) {
      return next(`${specifier}.ts`, context);
    }
    return next(specifier, context);
  },
});

Relative + no extension → retry with .ts. Everything else passes through.

Top-level await: .mjs is an ES module.

themeToCssVariables

/** `{ colorBrandBackground: '#e07856' }` → `{ '--colorBrandBackground': '#e07856' }`. */
export function themeToCssVariables(theme: PartialTheme): Record<string, string> {
  const vars: Record<string, string> = {};
  for (const [key, value] of Object.entries(theme)) {
    if (value !== undefined) vars[`--${key}`] = value;
  }
  return vars;
}

Shared: the generator at build time, [sdThemeProvider] at run time.

block and themeToCss

function block(selector: string, theme: PartialTheme, indent: string): string {
  const body = Object.entries(themeToCssVariables(theme))
    .map(([name, value]) => `${indent}  ${name}: ${value};`)
    .join('\n');
  return `${indent}${selector} {\n${body}\n${indent}}`;
}

export function themeToCss(
  theme: PartialTheme,
  overrides: ThemeOverride[] = [],
  selector = ':root',
): string {
  return [
    block(selector, theme, ''),
    ...overrides.map((o) => `@media ${o.media} {\n${block(selector, o.tokens, '  ')}\n}`),
  ].join('\n\n');
}

Format with the repo's Prettier config

const content = await prettier.format(source, {
  ...(await prettier.resolveConfig(file)),
  filepath: file,
});

CI also runs prettier --check. Formatting inside the generator means it never fights the formatter — and two runs give identical bytes.

Write mode and check mode

const check = process.argv.includes('--check');
let stale = false;
for (const [file, source] of outputs) {
  const content = await prettier.format(source, { /* … */ });
  let current = '';
  try {
    current = readFileSync(file, 'utf8');
  } catch {
    // missing counts as stale
  }
  if (current === content) continue;
  if (check) {
    stale = true;
    console.error(`${file} is out of date — run \`npm run tokens\` in frontend/.`);
  } else {
    writeFileSync(file, content);
    console.log(`wrote ${file}`);
  }
}
if (stale) process.exit(1);

Changing a token

  1. Edit the TypeScript in tokens/
  2. npm run tokens from frontend/
  3. Read the diff of the two generated files
  4. Commit source + generated files together
  5. Forgot? CI tells you what to run

Things to remember

Static CSS: first paint never waits
Node imports the real TS (strip types + resolve hook)
Serialiser in the library, pinned by a test
Typed var(--…) object generated alongside
Prettier inside the generator → stable output
One script, two modes; exit 1 when stale
