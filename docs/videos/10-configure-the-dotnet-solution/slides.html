How the settings are bound

services.AddOptions<ClaudeWebSearchOptions>()
    .Bind(configuration.GetSection(ClaudeWebSearchOptions.SectionName))
    // Secret comes from the environment in production (never the repo).
    .PostConfigure(o => o.ApiKey =
        ClaudeWebSearchOptions.ResolveApiKey(o, Environment.GetEnvironmentVariable));

services
    .AddHttpClient<IWebSearchClient, ClaudeWebSearchClient>(
        ClaudeWebSearchClient.HttpClientName, (sp, http) =>
    {
        http.BaseAddress = ClaudeWebSearchOptions.ResolveBaseUri(
            sp.GetRequiredService<IOptions<ClaudeWebSearchOptions>>().Value);
        http.Timeout = TimeSpan.FromMinutes(5);
    });

Bind the section · inject the key from the environment · base address from the provider · five-minute timeout.

One provider, one variable

public static string ApiKeyVariable(ClaudeProvider provider)
    => provider == ClaudeProvider.Foundry ? FoundryApiKeyVariable : AnthropicApiKeyVariable;

public static string ResolveApiKey(ClaudeWebSearchOptions options, Func<string, string?> environment)
{
    var fromEnvironment = environment(ApiKeyVariable(options.Provider));
    return string.IsNullOrWhiteSpace(fromEnvironment) ? options.ApiKey : fromEnvironment;
}

Where the base URL comes from

public static Uri? ResolveBaseUri(ClaudeWebSearchOptions options)
{
    var url = options.BaseUrl?.Trim();
    if (string.IsNullOrEmpty(url))
    {
        url = options.Provider switch
        {
            ClaudeProvider.Anthropic => "https://api.anthropic.com/",
            _ when !string.IsNullOrWhiteSpace(options.FoundryResource)
                => $"https://{options.FoundryResource.Trim()}.services.ai.azure.com/anthropic/",
            _ => null
        };
    }
    if (url is null) return null;          // unconfigured: fail lazily, on first search
    if (!url.EndsWith('/')) url += "/";    // v1/messages must not replace /anthropic
    return new Uri(url, UriKind.Absolute);
}

Running locally

  1. Provision (video 09). eng/Deploy-Foundry.ps1 wrote the key to the gitignored .deploy/azure.env.
  2. Load the key into the shell. Never echo it, never paste it into a settings file.
  3. Run. JSON → environment → command line, in that order.
# bash
export ANTHROPIC_FOUNDRY_API_KEY="$(grep '^ANTHROPIC_FOUNDRY_API_KEY=' \
    .deploy/azure.env | cut -d= -f2-)"
dotnet run --project backend/src/Saturdaze.Cli -- ingest --type events --dry-run

# PowerShell
$env:ANTHROPIC_FOUNDRY_API_KEY =
    (Select-String '^ANTHROPIC_FOUNDRY_API_KEY=' .deploy\azure.env).Line.Split('=', 2)[1]

Configuring the Worker

cd backend
docker build -f src/Saturdaze.Worker/Dockerfile -t saturdaze-worker .
docker run --rm -e SATURDAZE_CONNECTION="Server=...;Database=Saturdaze;..." \
  -e ANTHROPIC_FOUNDRY_API_KEY="<foundry-key>" saturdaze-worker

# one-shot job for Kubernetes CronJob / Azure Container Apps Job
docker run --rm -e SATURDAZE_CONNECTION="..." -e ANTHROPIC_FOUNDRY_API_KEY="..." \
  -e Saturdaze__Ingestion__Schedule__RunOnceThenExit=true saturdaze-worker

Exposed to the process as environment variables; prefer Key Vault references.

Caveat: the deploy workflow publishes the API only. Add the Worker or WebJob packaging step before the schedule is live.

Switching to Anthropic and back

export Saturdaze__Ingestion__Claude__Provider=Anthropic
export ANTHROPIC_API_KEY="<anthropic-key>"
# optional, if the Anthropic model id differs from the Foundry deployment name
export Saturdaze__Ingestion__Claude__Model="<anthropic-model-id>"

Same request body, same headers, now sent to https://api.anthropic.com/v1/messages. Remove the variables to switch back. No rebuild, no code change: what ADR-011 promised.

Things to remember

One section. Saturdaze:Ingestion:Claude, bound by AddIngestion; key from the provider's own variable, never checked in.
Locally. Provision → load ANTHROPIC_FOUNDRY_API_KEY → saturdaze ingest --dry-run.
Hosts. Worker and WebJob take the same two variables; override the rest with __ names.
Fallback. Provider swap is two settings, no rebuild.
Failures land in the console and in IngestionRun; the message names the fix.
