One managed home for every email

Today

The API drafts verification and reset emails; their wording lives in no editable place, and no provider sends them (G01, video 18).

This feature

Administrators write, preview, version and retire templates in Saturdaze Admin.

Later

A sender looks an Active template up by its key.

A template and its revisions

  • Version: starts at 1, +1 on every change, the concurrency token
  • One template, many revisions: EmailTemplateRevision
  • Action: Create · Edit · Status; time in UTC
  • AdminUserId is null for the seeder
  • Written, never updated; deleted with the template

Create: one check, two sources

Validated first: key pattern, name, category (400 naming the field)

Key exists

409 template_key_exists

New key

  • Content from duplicateOf or EmailTemplateStarters.For(category)
  • Draft, version 1, IsSystem = false
  • Write(template, Create), one SaveChangesAsync
  • 201 EmailTemplateDto → the editor opens

Preview (top) · debounce 300 ms → EmailTemplateLiquid checks → CheckHtml → EmailTemplateRenderer: sample data over built-ins, HtmlEncoder, MaxSteps 10 000 · nothing saved

Save (bottom) · version check, then the same checks plus required placeholders · L2-133, L2-134, L2-136

Save: optimistic concurrency

PUT /api/admin/email-templates/{id} with the content and the version the editor loaded

Version differs

409 template_stale; the editor says someone else changed the template and offers to reload

Version current

  • Liquid and HTML checks, then CheckRequired
  • Version + 1, UpdatedAt (UTC), UpdatedByEmail
  • Write(template, Edit), one SaveChangesAsync

Version is the EF Core concurrency token: EmailTemplateConcurrency turns a lost race into template_stale

Status POST …/{id}/status { status, version } · system template stays Active, else 400 system_template · stale → 409 · L2-135, L2-136

ADR-017: Liquid, rendered with Fluid

Why Liquid

Widely known (Shopify, Jekyll, many email platforms), designed for untrusted authors, and plain {{name}} placeholders are already valid Liquid.

What it adds

  • {{ name }} outputs a value
  • {% if %} and {% for %}: conditions and loops
  • Filters such as upcase or date

Fluid.Core, pinned in Directory.Packages.props (ADR-004) · docs/adr/ADR-017-liquid-email-templates.md

Three layers keep HTML inert

1 · Deny-list

  • <script> <iframe> <object> <embed> <form> <base>
  • on…= attributes
  • javascript: vbscript: data:text/html

EmailTemplateRules

2 · Encoding

HTML body rendered with HtmlEncoder.Default; subject, preheader and text body with NullEncoder

3 · Sandbox

  • <iframe sandbox>
  • No allow-scripts
  • No allow-same-origin
  • CSP: only HTTPS images and fonts

Things to remember

One home for every email; a sender finds an Active template by key.
Version is the concurrency token: stale means template_stale.
Every create, save and status change writes a revision.
Restricted Liquid, a deny-list, encoding and a sandbox keep HTML inert.
