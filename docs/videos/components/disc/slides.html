Coding sd-disc

An icon in a coloured circle: host bindings, one computed signal, token pairs.

Where it is used

<sd-disc slot="leading" [icon]="commitment.icon" tone="accent" />
<sd-disc slot="leading" icon="calendar" tone="primary" />
<sd-disc slot="disc" icon="mail" tone="primary" size="xl" />
<sd-disc [icon]="icon()" [tone]="tone()" size="xl" />

Inputs stay inputs

  • No [attr.icon], [attr.tone], [attr.size] on the host
  • Only classes and ARIA state go on the host
  • Nothing read the reflected attributes — ADR-009 records the rule

Three inputs, one computed()

export class Disc {
  readonly icon = input<string>('sparkle');
  readonly tone = input<DiscTone>('default');
  readonly size = input<DiscSize>('md');

  protected readonly iconSize = computed(() =>
    this.size() === 'xl' ? 26 : this.size() === 'sm' ? 16 : 20,
  );
}

Why these choices

  • No input.required — every disc has a sensible default
  • No transform — string unions, not attribute booleans/numbers
  • computed() — recalculated only when size changes
  • protected — only the template reads it

Mock: .disc--xl .icon { width: 26px; height: 26px; }

The template: one line, no wrapper

<sd-icon [name]="icon()" [size]="iconSize()" />

Every tone, every size

mirrors the size to a host class and scales the glyph with it — --_size 16px · 20px · 26px, and disc--lg removed again

Pitfalls

  • Meaning only in the disc — it is aria-hidden
  • A fill token without its paired ink
  • New tone: update the type, the host binding and the SCSS together

Things to remember

Union types make inputs type-safe
Host class bindings read signals
Static aria-hidden: decorative
computed() scales the glyph
Tones = fill + ink token pairs
The host is the circle
