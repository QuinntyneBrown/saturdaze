Coding sd-chip-input

A tag editor built on signals and the forms contract.

Inputs, an id, and three signals

  readonly label = input<string>('');
  readonly tone = input<ChipTone>('leaf');
  readonly placeholder = input<string>('Add one, press Enter');

  protected readonly id = `sd-chip-input-${nextChipInputId++}`;
  protected readonly values = signal<readonly string[]>([]);
  protected readonly draft = signal<string>('');
  protected readonly disabled = signal<boolean>(false);

What each member is

memberkindwhy
label · tone · placeholderinput()configuration from the parent
idplain stringnever changes — no need to be reactive
values · draft · disabledsignal()owned and written by the component

The value is not a model(): the form owns it.

Keyboard handling

  protected onDraft(event: Event): void {
    this.draft.set((event.target as HTMLInputElement).value);
  }

  protected onKey(event: KeyboardEvent): void {
    if (event.key === 'Enter' || event.key === ',') {
      event.preventDefault();
      this.commit();
    } else if (event.key === 'Backspace' && !this.draft() && this.values().length) {
      this.removeAt(this.values().length - 1);
    }
  }

Commit and remove

  protected commit(): void {
    const v = this.draft().trim();
    if (!v) return;
    const exists = this.values().some((x) => x.toLowerCase() === v.toLowerCase());
    if (!exists) this.set([...this.values(), v]);
    this.draft.set('');
  }

  protected removeAt(index: number): void {
    if (this.disabled()) return;
    this.set(this.values().filter((_, i) => i !== index));
  }

One way out, one way in

  private set(next: readonly string[]): void {
    this.values.set(next);
    this.onChange([...next]);
    this.onTouched();
  }

  writeValue(value: readonly string[] | null): void {
    this.values.set(value ? [...value] : []);
  }

Copy arrays across the forms boundary — neither side can mutate the other.

Signals best practice

No effect(): every change happens in an event handler, so there is nothing to synchronise afterwards.

The template: label and chips

@if (label()) {
  <label class="field__label" [attr.for]="id">{{ label() }}</label>
}
<div class="chip-input">
  @for (value of values(); track value; let i = $index) {
    <sd-chip [tone]="tone()" removable [removeLabel]="'Remove ' + value" (remove)="removeAt(i)">{{
      value
    }}</sd-chip>
  }

track value is safe: values are de-duplicated.

The template: the bare input

  <input
    class="chip-input__field"
    [id]="id"
    type="text"
    [value]="draft()"
    [attr.placeholder]="placeholder()"
    [disabled]="disabled()"
    (input)="onDraft($event)"
    (keydown)="onKey($event)"
    (blur)="commit()"
  />
</div>

Pitfalls

  • Values as a model() or input
  • Sharing arrays across the forms boundary
  • Forgetting preventDefault() on Enter and comma
  • A fixed id shared by every instance
  • An effect() where a handler would do

Things to remember

Signals: values, draft, disabled
One private set()
Handlers, not effects
Chip (remove) → removeAt(i)
Generated id links the label
:focus-within draws the ring
