Coding sd-event-card

A typed card built from smaller parts: media, date tile, chips, footer.

Where it is used

        <sd-event-card
          [title]="event.title"
          [meta]="event.meta"
          [mon]="event.tile.mon"
          [day]="event.tile.day"
          [muted]="event.pending"
          [url]="event.url ?? ''"
          [media]="event.media"
          [addable]="event.addable"
          (addToDay)="addToDay(event)"
        >
          @for (chip of event.chips; track chip.label) {
            <sd-chip slot="chips" [tone]="chipTone(chip.tone)">

One anatomy for every typed card

    class: 'card card--media',

BEM block + modifier from the mock (ADR-009); card--muted from muted(). Inputs are not reflected to host attributes.

Ten inputs, one output

  readonly cardTitle = input<string>('', { alias: 'title' });
  readonly meta = input<string>('');
  /** ISO date for the tile. */
  readonly date = input<string>('');
  /** Pre-split tile parts; when given they win over `date`. */
  readonly mon = input<string>('');
  readonly day = input<string>('');
  readonly muted = input(false, { transform: booleanAttribute });
  readonly url = input<string>('');
  /** The event's primary photo; null shows the fallback tile (L2-106). */
  readonly media = input<CardMedia | null>(null);
  readonly mediaTone = input<MediaTone>('sky');
  /** Offer "Add to day" — this weekend's events only (L2-107). */
  readonly addable = input(false, { transform: booleanAttribute });
  /** "Add to day" was pressed. */
  readonly addToDay = output<void>();

Pitfalls

  • Business logic in the card — emit and let the page decide
  • A Details link on a muted suggestion
  • Copying card styles instead of @include card-host
  • One @if around several chips

Things to remember

Composes media, date tile, button, icon
Aliased title, booleanAttribute
output() reports Add to day
Footer only when it has content
Unique label per Add to day button
One mixin for every typed card
