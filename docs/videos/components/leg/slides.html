Host metadata, read from signals

Do

host: { '[attr.aria-label]': 'ariaLabel() || null' }

Avoid

@HostBinding decorators and empty-string attributes

OnPush + signals: the host re-renders only when a signal it reads changes.

Three signal inputs

export class Leg {
  /** "45 min · 52 km". */
  readonly label = input<string>('');
  /** "Travel: 45 minutes, 52 kilometres to Lavender fields". */
  readonly ariaLabel = input<string>('');
  /** Directions for the leg; empty hides the link. */
  readonly directionsUrl = input<string>('');
}

What it doesn't need

  • input.required — an empty leg still renders
  • booleanAttribute — there are no flags
  • computed() — nothing is derived
  • output() — the link is a plain anchor

New tab, no back door

target="_blank" always travels with rel="noopener", so the maps page can't reach window.opener.

What a spec should prove

  1. Host has .leg and role="listitem"
  2. aria-label mirrors the input; empty → no attribute
  3. Label renders in .leg__text beside the car icon
  4. No URL → no link; URL → href, _blank, noopener
  5. The rail is aria-hidden

Pitfalls

  • A wrapper div breaks the grid and mock parity
  • aria-label="" leaves an unnamed list item
  • A new-tab link without rel="noopener"
  • Dropping the empty first span — the rail shifts left

Things to remember

The host is the BEM block, role="listitem"
Nullable aria-label from a signal
Three plain inputs, nothing derived
Decorative rail is aria-hidden
Colours from tokens by role
No spec yet — you know what it should test
