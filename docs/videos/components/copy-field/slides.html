One input, one output, one signal

export class CopyField {
  readonly value = input<string>('');
  readonly copied = output<string>();

  protected readonly justCopied = signal(false);

output<string>()

Emits the copied text — the parent never reads the input back

signal(false)

Short-lived state the component sets and clears itself

The copy method

  protected async copy(): Promise<void> {
    const text = this.value();
    try {
      await navigator.clipboard?.writeText(text);
    } catch {
      // Clipboard access can be denied (insecure context, permissions); the
      // value stays visible so the user can select it by hand.
    }
    this.justCopied.set(true);
    this.copied.emit(text);
    setTimeout(() => this.justCopied.set(false), 2000);
  }

Three deliberate choices

  1. Read the signal once, before the await — copied text = emitted text
  2. clipboard?. — the API may not exist in an insecure context
  3. Empty catch — failure is not fatal; the value stays selectable
OnPush + signals

A setTimeout that sets a signal is enough to re-render. No ChangeDetectorRef, no markForCheck(), no zone tricks.

Pitfalls

  • Reading the input again after an await
  • Letting a clipboard failure throw
  • The timeout isn't cleared on destroy or a second click — fine here; use DestroyRef for longer timers
  • Icon swap without a live region
  • Faking all timers, or not restoring real ones

Things to remember

One input · one output · one signal
Async copy, forgiving catch
Timeout + signal re-renders under OnPush
