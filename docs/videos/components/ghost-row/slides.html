Coding sd-ghost-row

One slot, two elements: the dashed add row as a button or an in-app link.

Where it is used

            <sd-ghost-row slot="footer" icon="bag" (pressed)="addErrand()"

            >

The decorator

@Component({
  selector: 'sd-ghost-row',
  standalone: true,
  imports: [Icon, NgTemplateOutlet],
  templateUrl: './ghost-row.html',
  styleUrl: './ghost-row.scss',
  changeDetection: ChangeDetectionStrategy.OnPush,
})

No host class: .ghost-row is on the inner <a>/<button>; the host is display: contents. No host object: icon and href are not reflected (ADR-009).

Optional inject(), two inputs, one output

export class GhostRow {
  private readonly router = inject(Router, { optional: true });

  readonly icon = input<string>('plus');
  readonly href = input<string>('');
  readonly pressed = output<void>();

  protected onAnchorClick(event: MouseEvent): void {
    if (this.router) navigateInApp(this.router, event, this.href());
  }
}

The shared in-app link helper

export function isPlainClick(event: MouseEvent): boolean {
  if (event.defaultPrevented) return false;
  if (event.button !== 0) return false;
  if (event.metaKey || event.ctrlKey || event.shiftKey || event.altKey) return false;
  return true;
}

/** Absolute, same-origin, in-app paths only (`/weekend`, `/ideas/food`). */
export function isInAppHref(href: string): boolean {
  return href.startsWith('/') && !href.startsWith('//');
}

Real links, SPA navigation

export function navigateInApp(router: Router, event: MouseEvent, href: string): void {
  if (!isPlainClick(event) || !isInAppHref(href)) return;
  event.preventDefault();
  void router.navigateByUrl(href);
}

Also used by sd-button, sd-list-item, sd-menu, sd-page-header.

One content template, two elements

<!-- One content template for both elements; see button.html for why. -->
<ng-template #content>
  <sd-icon [name]="icon()" [size]="16" />
  <ng-content />
</ng-template>

@if (href()) {
  <a class="ghost-row" [attr.href]="href()" (click)="onAnchorClick($event)">
    <ng-container *ngTemplateOutlet="content" />
  </a>
} @else {
  <button class="ghost-row" type="button" (click)="pressed.emit()">
    <ng-container *ngTemplateOutlet="content" />
  </button>
}

Why not one slot per branch?

Slot in each @if branch

Angular projects each ng-content into one place at compile time — the other variant renders empty.

Slot in one ng-template

Declared once, stamped into whichever branch is active. Same in sd-button and sd-list-item.

Pitfalls

  • ng-content repeated per @if branch
  • Hijacking modifier clicks or external links
  • A required router (breaks Storybook and bare tests)
  • Giving the host a box

Things to remember

One ng-template, two elements
Optional router + shared helper
pressed only for the button
No host bindings: inputs stay inputs
Tokens by role, dashed border
44px touch target
