Coding sd-filter-chip

A toggle that shows its pressed state but doesn't own it.

Where it is used

<sd-filters class="filters" label="Filters">
  @for (chip of view().windowChips; track chip.label) {
    <sd-filter-chip
      [tone]="filterTone(chip.tone)"
      [pressed]="chip.active"
      (pressedChange)="setWindow(chip)"
      >{{ chip.label }}</sd-filter-chip
    >
  }

Also: ideas-activities and past pages

Type and decorator

export type FilterChipTone = 'default' | 'leaf' | 'indoor' | 'sky' | 'sun' | 'accent' | 'primary';

@Component({
  selector: 'sd-filter-chip',

The host adds no box

<sd-filter-chip>display: contents
→
<button class="filter-chip">the real flex item

BEM class on the button, matching the mock's .filter-chip. No host object: inputs are not reflected to host attributes (ADR-009).

Inputs in, an output out

export class FilterChip {
  readonly pressed = input(false, { transform: booleanAttribute });
  readonly tone = input<FilterChipTone>('default');
  readonly disabled = input(false, { transform: booleanAttribute });
  /** Emits the next pressed state on click; the page owns the truth. */
  readonly pressedChange = output<boolean>();

Why not model()?

pressed = model(false)

The chip writes its own value and flips on click — before the page decides.

input() + output()

The chip requests; the page (here the events service) decides which chip is on.

  protected setWindow(chip: FilterChipView): void {
    this.service.setWindow(chip.label as EventsWindow);
  }

computed() classes + a guarded toggle

  protected readonly classes = computed(() => ({
    'filter-chip': true,
    [`filter-chip--${this.tone()}`]: this.tone() !== 'default',
  }));

  protected toggle(): void {
    if (this.disabled()) return;
    this.pressedChange.emit(!this.pressed());
  }

A real toggle button

<button
  [class]="classes()"
  type="button"
  [attr.aria-pressed]="pressed()"
  [disabled]="disabled()"
  (click)="toggle()"
>
  <ng-content />
</button>

The ownership rule, as a test

  it('emits the next pressed state on click without owning the truth', () => {
    const spy = vi.fn();
    fixture.componentInstance.pressedChange.subscribe(spy);

    button().click();
    expect(spy).toHaveBeenLastCalledWith(true);
    fixture.detectChanges();
    expect(button().getAttribute('aria-pressed')).toBe('false');

    fixture.componentRef.setInput('pressed', true);
    fixture.detectChanges();
    button().click();
    expect(spy).toHaveBeenLastCalledWith(false);
  });

Guard and slot

  • disables the button and swallows clicks when disabled
  • projects the chip text inside the button

Pitfalls

  • model() — the chip would flip itself
  • A parallel "is-on" class instead of [aria-pressed='true']
  • Dropping type="button" (submits forms)
  • Giving the host a box

Things to remember

The page owns the pressed state
booleanAttribute on pressed/disabled
computed() class object
aria-pressed drives a11y and style
Tones: background/border/foreground triples
Host is display: contents
