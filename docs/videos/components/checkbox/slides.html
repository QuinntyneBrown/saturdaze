Coding sd-checkbox

A native box that speaks reactive forms: signals for state, a value accessor for the form.

Where the app uses it

      <sd-checkbox name="terms" required formControlName="terms">
        I agree to the <a class="sd-link" routerLink="/legal">Terms</a> and
        <a class="sd-link" routerLink="/legal" fragment="privacy">Privacy Policy</a>.
      </sd-checkbox>
      <sd-checkbox name="fridayPreview" formControlName="fridayPreview">
        Send me the Friday preview. A draft of the weekend in my inbox at 6pm.
      </sd-checkbox>

The decorator

@Component({
  selector: 'sd-checkbox',
  standalone: true,
  templateUrl: './checkbox.html',
  styleUrl: './checkbox.scss',
  changeDetection: ChangeDetectionStrategy.OnPush,
  /* providers … */
})

No host object: inputs stay inputs; state lives on the native input (ADR-009).

The value accessor provider

  providers: [
    {
      provide: NG_VALUE_ACCESSOR,
      useExisting: forwardRef(() => Checkbox),
      multi: true,
    },
  ],
  • NG_VALUE_ACCESSOR: how formControlName and ngModel find the component
  • forwardRef: the class is used inside its own decorator, before it is defined

Inputs vs. local signals

export class Checkbox implements ControlValueAccessor {
  readonly required = input(false, { transform: booleanAttribute });
  readonly name = input<string>('');

  protected readonly checked = signal<boolean>(false);
  protected readonly disabled = signal<boolean>(false);

Why not input() or model() for checked?

checked = model()

Parent binding and form control both own the value — two sources of truth

checked = signal()

The form writes in through the accessor; the template reads the signal

protected: visible to the template, not part of the public API.

OnPush + signals

Setting a signal the template reads schedules the re-render. No ChangeDetectorRef, no markForCheck().

The forms contract

  private onChange: (value: boolean) => void = () => {};
  private onTouched: () => void = () => {};
  protected handleChange(event: Event): void {
    const v = (event.target as HTMLInputElement).checked;
    this.checked.set(v);
    this.onChange(v);
    this.onTouched();
  }
  writeValue(value: boolean | null): void {
    this.checked.set(!!value);
  }
  /* … registerOnChange / registerOnTouched store fn … */
  setDisabledState(isDisabled: boolean): void {
    this.disabled.set(isDisabled);
  }

Two directions

FormControlsetValue / reset / disable
→

→
template[checked] · [disabled]
user click(change)
→

→
onChange(v) · onTouched()value + touched

The template

<label class="check">
  <input
    class="check__input"
    type="checkbox"
    [attr.name]="name() || null"
    [checked]="checked()"
    [disabled]="disabled()"
    [attr.aria-required]="required() ? 'true' : null"
    (change)="handleChange($event)"
  />
  <span class="check__label"><ng-content /></span>
</label>

Accessibility for free

  • Wrapping <label>: the whole text toggles the box, no for/id pair
  • Native input type="checkbox": keyboard, focus and checked state
  • aria-required="true" only when required
  • One content slot: the label can carry links

The forms contract

  it('reports a user toggle to the form and marks it touched', () => {
    const onChange = vi.fn();
    const onTouched = vi.fn();
    component.registerOnChange(onChange);
    component.registerOnTouched(onTouched);

    input().checked = true;
    input().dispatchEvent(new Event('change'));
    expect(onChange).toHaveBeenCalledWith(true);
    expect(onTouched).toHaveBeenCalledTimes(1);
  });

Pitfalls

  • checked as an input or model — two sources of truth
  • Missing forwardRef in the provider
  • Not coercing null in writeValue
  • Calling onChange without onTouched
  • Replacing the native input with a styled div

Things to remember

Inputs configure; signals hold owned state
NG_VALUE_ACCESSOR + four methods
Change handler: signal, then form
Label + native input + aria-required
display: contents host
Tokens by role · one slot
