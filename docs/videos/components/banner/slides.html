The decorator

@Component({
  selector: 'sd-banner',
  standalone: true,
  imports: [Icon],
  templateUrl: './banner.html',
  styleUrl: './banner.scss',
  changeDetection: ChangeDetectionStrategy.OnPush,
  host: {
    class: 'banner',
    '[class.banner--info]': 'tone() === "info"',
    '[class.banner--warn]': 'tone() === "warn"',
    '[class.banner--success]': 'tone() === "success"',
    '[attr.role]': 'role()',
    '[attr.aria-live]': 'role() === "alert" ? "assertive" : "polite"',
  },
})

One input, two ARIA attributes

role inputrolearia-liveuse for
'status' (default)statuspolitesaved notices, hints
'alert'alertassertiveerrors that block the user

Derived in one place — a page can't pair alert with polite.

Tone and role

  • mirrors the tone to a host class
  • becomes an assertive alert for errors
fixture.componentRef.setInput('role', 'alert');
fixture.detectChanges();
expect(host.getAttribute('role')).toBe('alert');
expect(host.getAttribute('aria-live')).toBe('assertive');

Icon and projection

  • renders a leading glyph only when an icon is given
  • projects the message into the text span
fixture.componentRef.setInput('icon', 'lock');
fixture.detectChanges();
expect(glyph(host.querySelector('sd-icon'))).toContain('M8 11V8a4 4 0 0 1 8 0v3');
fixture.componentRef.setInput('icon', '');
fixture.detectChanges();
expect(host.querySelector('sd-icon')).toBeNull();

Pitfalls

  • Setting aria-live on the page
  • role="alert" for good news
  • An empty banner left on screen — wrap it in @if
  • Hard-coded colours instead of tone

Things to remember

Host is the banner, class per tone
role drives role + aria-live
alert → assertive, status → polite
Message in one default slot
Paired background + foreground
No outputs, no state
