Coding sd-skeleton-row

A decorative loading placeholder: no inputs, all shape.

Where it is used

  @case ('loading') {
    <div class="sd-grid-days" aria-busy="true">
      @for (day of days; track day) {
        <sd-day [title]="day" [actions]="false">
          @for (i of skeleton; track i) {
            <sd-skeleton-row />
          }
        </sd-day>
      }
    </div>
  }

No inputs is a design

  • Nothing varies, so nothing is configurable
  • No input(), signal() or output() to invent
  • OnPush: checked once, then left alone

The shimmer

  position: relative;

  border-radius: var(--borderRadiusSmall);

.skeleton::after {
  content: '';

  inset: 0;
  transform: translateX(-100%);
  background: linear-gradient(90deg, transparent, rgba(255, 255, 255, 0.6), transparent);
  animation: sd-shimmer 1.4s var(--curveEasyEase) infinite;
}

Respect reduced motion

@keyframes sd-shimmer {
  to {
    transform: translateX(100%);
  }
}

@media (prefers-reduced-motion: reduce) {
  .skeleton::after {
    animation: none;
  }
}

Pitfalls

  • No aria-busy on the container — nobody hears "loading"
  • Text inside the row — use sd-status-row for messages
  • Dropping the reduced-motion rule

Things to remember

No inputs when nothing varies
Static host: class + aria-hidden
Match the real row's geometry
Pseudo-element shimmer, off for reduced motion
Spec proves shape and silence
