Coding sd-cover

A photo header with a readable scrim, a tinted fallback and an aliased input.

Where the app uses it

  <sd-cover
    [media]="weekend().cover?.media ?? null"
    [eyebrow]="weekend().dateRange"
    [title]="headline()"
    [subtitle]="subtitle()"
  >
    <sd-button slot="edit" variant="quiet" size="sm" (click)="changeCover()">
      <sd-icon name="edit" />
      Change photo
    </sd-button>
  </sd-cover>

The decorator

@Component({
  selector: 'sd-cover',
  standalone: true,
  imports: [Icon],
  templateUrl: './cover.html',
  styleUrl: './cover.scss',
  changeDetection: ChangeDetectionStrategy.OnPush,
  host: {

Two design promises

/**
 * The weekend cover — `.cover` in docs/mocks/pages/weekend.html (L2-108). The
 * cover photo, eagerly loaded since it is above the fold, with its label as a
 * credit chip; the date range, the page's `h1` and the summary sit on a
 * gradient scrim that keeps white text at 4.5:1 over light and dark photos.
 * With no photo it is a tinted tile and the text stays readable. Project the
 * "Change photo" control into `[slot=edit]`.
 */

Five inputs, no outputs

export class Cover {
  readonly media = input<CardMedia | null>(null);
  /** "16 – 17 May". */
  readonly eyebrow = input<string>('');
  readonly coverTitle = input<string>('', { alias: 'title' });
  readonly subtitle = input<string>('');
  readonly tone = input<MediaTone>('sky');
}

CardMedia (media/media.ts): src · alt · width · height · credit

An alias for the public name

Page writes

[title]="headline()" — the mock's vocabulary

Class reads

coverTitle() — unambiguous inside the component

Use alias sparingly, for public naming like this.

@let + @if: read once, narrow the type

@let m = media();
@if (m) {
  <img
    class="cover__img"
    [src]="m.src"
    [alt]="m.alt"
    [attr.width]="m.width"
    [attr.height]="m.height"
    loading="eager"
    fetchpriority="high"
  />
  @if (m.credit) {
    <span class="media__credit">{{ m.credit }}</span>
  }

Fallback, body and the edit slot

} @else {
  <div class="cover__fallback" [class]="'cover__fallback--' + tone()" aria-hidden="true">

Contrast by design

// The scrim's dark end sits under the text, so it reads at 4.5:1 or better
// whatever the photo (L2-108 AC4).
.cover__body {
  position: absolute;
  inset: auto 0 0 0;
  padding: 48px 16px 16px;
  background: linear-gradient(to top, var(--sd-cover-scrim) 55%, transparent);

Responsive without a magic number

@include respond-to(tablet) {
  :host {
    aspect-ratio: 21 / 8;
  }

  .cover__body {
    padding: 64px 24px 20px;
  }
}

720px lives in styles/_breakpoints.scss, not here.

No cover.spec.ts — what one should prove

  • With media: src, alt, width, height, eager + high priority; credit chip only when set
  • Without media: cover--fallback on the host, tone class, aria-hidden, no img
  • The aliased title fills the h1 in both states
  • Empty eyebrow and summary render nothing
  • A host component projects a button into [slot=edit]

Not existing tests — a checklist for writing one.

Covered end to end today

e2e/tests/weekend-cover.spec.ts

  • the cover leads with the photo, its credit, the dates, the title and the summary
  • 16:9 under 720px, 21:8 from 720px, with the actions below
  • with no stop photos the cover shows the fallback and keeps the title as the h1
  • Change photo offers each stop's photo and switches the cover

Pitfalls

  • Dropping width/height — layout shift
  • Lazy-loading the hero image
  • Rendering the h1 in one branch only
  • Hard-coding 720px
  • Exposing the decorative fallback to assistive tech
