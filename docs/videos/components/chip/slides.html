The decorator imports what it renders

@Component({
  selector: 'sd-chip',
  standalone: true,
  imports: [Icon],
  /* templateUrl, styleUrl */
  changeDetection: ChangeDetectionStrategy.OnPush,
  host: {
    class: 'chip',
    '[class.chip--sun]': 'tone() === "sun"',
    /* … sky, leaf, indoor, accent, primary, warn, ink … */
    '[class.chip--sm]': 'size() === "sm"',
    '[class.chip--count]': 'count()',
  },
})

Classes only — inputs are not reflected as host attributes (ADR-009).

Five inputs, one output

export class Chip {
  readonly tone = input<ChipTone>('default');
  readonly size = input<ChipSize>('md');
  /** Centred numeric badge (the "3" beside Review submissions). */
  readonly count = input(false, { transform: booleanAttribute });
  /** Trailing × button; `remove` emits when it is pressed. */
  readonly removable = input(false, { transform: booleanAttribute });
  /** Accessible name for the × (defaults to "Remove"). */
  readonly removeLabel = input<string>('Remove');
  readonly remove = output<void>();
}

output(): report, don't decide

Child

remove = output<void>()
emits when × is pressed

Parent

(remove)="removeAt(i)"
owns the list, decides

Typed, mirrors the signal input API — no @Output() new EventEmitter().

Not needed here

  • computed() — every binding is one comparison
  • model() — nothing flows both ways
  • signal() — no local state

<ng-content />
@if (removable()) {

Pitfalls

  • Letting the chip remove itself — emit, the parent decides
  • Generic “Remove” labels in a list — use 'Remove ' + value
  • Dropping type="button"
  • Splitting fill/ink pairs
  • Forgetting imports: [Icon]

Things to remember

The host is the chip
Inputs + booleanAttribute
output() for events
One slot, conditional native button
Tone pairs → contrast by construction
Spec: tones, label, emitted event
