Coding sd-strength

A three-segment password meter from two signal inputs.

Where it lives

<sd-strength [level]="strength().level" [label]="strength().label" />

create-account

Under the password field

reset-password

Same binding, same helper

One exported type

export type StrengthLevel = 'weak' | 'ok' | 'strong';
import { StrengthLevel } from 'components';

export interface PasswordStrength {
  readonly level: StrengthLevel | null;
  readonly label: string;
}

The decorator

@Component({
  selector: 'sd-strength',
  standalone: true,
  templateUrl: './strength.html',
  styleUrl: './strength.scss',
  changeDetection: ChangeDetectionStrategy.OnPush,
  host: {
    class: 'strength',
    'aria-live': 'polite',
    /* … */
  },
})

The host is the block and a live region

  host: {
    class: 'strength',
    'aria-live': 'polite',
    '[class.strength--weak]': 'level() === "weak"',
    '[class.strength--ok]': 'level() === "ok"',
    '[class.strength--strong]': 'level() === "strong"',
  },

B E M parity with the mocks (ADR-009) · aria-live="polite" announces label changes

Host bindings read the signal

    '[class.strength--weak]': 'level() === "weak"',
    '[class.strength--ok]': 'level() === "ok"',
    '[class.strength--strong]': 'level() === "strong"',
  • One modifier class per level
  • Inputs stay inputs: no [attr.level] on the host
  • Only ARIA state and classes go on the host (ADR-009)

Two signal inputs

export class Strength {
  readonly level = input<StrengthLevel | null>(null);
  readonly label = input<string>('');
}
  • null default: an empty password shows no colour
  • Signal inputs + OnPush: re-render only when an input changes

What it doesn't need

Not here

@Input(), setters, ngOnChanges, computed(), output()

Instead

Host bindings call level(); the page computes the level

  protected readonly strength = computed(() => passwordStrength(this.password()));

The contract and the defaults

  • creates a polite live meter with three hidden segments — class, aria-live, aria-hidden, 3 segments
  • has no level and no label until told — base class only, no label

mirrors the level to a host class

    for (const level of ['weak', 'ok', 'strong']) {
      fixture.componentRef.setInput('level', level);
      fixture.detectChanges();
      expect(host.classList.contains(`strength--${level}`)).toBe(true);
    }
    expect(host.classList.contains('strength--weak')).toBe(false);

    fixture.componentRef.setInput('level', null);
    fixture.detectChanges();
    expect(host.classList.contains('strength--strong')).toBe(false);

Plus announces the label text.

Pitfalls

  • A live region must exist before its content changes — keep it on the host
  • Colour only through level, never page classes
  • Segments stay decoration: no focus, no roles

Things to remember

Two signal inputs + host bindings
Host = B E M block + polite live region
Modifiers + nth-child fill the segments
Status and palette roles, never hex
Spec: setInput, then check rendered classes
