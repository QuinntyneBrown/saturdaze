Coding sd-section

A titled region with an action slot: two signal inputs, two host bindings and one slot each.

Where it is used

      <sd-section title="Home">
        <sd-button slot="action" variant="quiet" size="sm" (click)="editHome()">
          <sd-icon name="edit" />
          Edit
        </sd-button>
        <sd-list card>
          <sd-list-item [title]="view().home.location" [subtitle]="view().home.hint">
            <sd-disc slot="leading" icon="pin" />
          </sd-list-item>
        </sd-list>
      </sd-section>

Also: the three Ideas pages (one section per group) and Weekend ("Planned around").

What you will build

  • A heading, optional subtitle, optional action, then the body
  • Labels itself with its own heading (aria-labelledby)
  • Keeps the mock's BEM classes: .section, .section-header__*
  • Declares each ng-content slot exactly once

The decorator

let nextSectionId = 0;

@Component({
  selector: 'sd-section',
  standalone: true,
  templateUrl: './section.html',
  styleUrl: './section.scss',
  changeDetection: ChangeDetectionStrategy.OnPush,
  host: {
    class: 'section',
    '[attr.aria-labelledby]': 'sectionTitle() ? headingId : null',
  },
})

Host bindings read signals

  host: {
    class: 'section',
    '[attr.aria-labelledby]': 'sectionTitle() ? headingId : null',
  },
  • class: 'section' — the host is the mock's block element
  • aria-labelledby only when there is a heading; null removes it

Inputs stay inputs

Removed

'[attr.title]' and '[attr.subtitle]' on the host: nothing read them, and a host title is a native tooltip

The rule

Only classes and ARIA state go on the host

docs/adr/ADR-009-v2-responsive-shell.md

Best practice: the host property

Avoid

@HostBinding('attr.aria-labelledby') getters scattered through the class

Prefer

One typed host: {} block next to the selector, reading signals

Two signal inputs

export class Section {
  readonly sectionTitle = input<string>('', { alias: 'title' });
  readonly subtitle = input<string>('');

  protected readonly headingId = `sd-section-${nextSectionId++}`;
}

Consumers write title="Members"; the class keeps sectionTitle.

What it doesn't need

input.required

An untitled section is valid

signal / computed

headingId never changes; nothing to derive

output()

The section reports nothing back

The template

@if (sectionTitle()) {
  <div class="section-header">
    <div class="section-header__text">
      <h2 class="section-header__title" [id]="headingId">{{ sectionTitle() }}</h2>
      @if (subtitle()) {
        <p class="section-header__sub">{{ subtitle() }}</p>
      }
    </div>
    <div class="section-header__action"><ng-content select="[slot=action]" /></div>
  </div>
}
<ng-content />

Each slot declared once

[slot=action]

Once, inside @if (sectionTitle()) — no title, no action

default slot

Once, outside any condition — the body always renders

Proving projection

  it('projects the action into the header and the body below it', () => {
    const wrapper = TestBed.createComponent(HostCmp);
    wrapper.detectChanges();
    const el = (wrapper.nativeElement as HTMLElement).querySelector('sd-section') as HTMLElement;
    expect(el.querySelector('.section-header__action .edit')?.textContent).toBe('Edit');
    expect(el.querySelector('.section-header .body')).toBeNull();
    expect(el.querySelector(':scope > .body')?.textContent).toBe('Quinn, Sara, Eli, Mae');
    expect(el.querySelector('.section-header__title')?.textContent?.trim()).toBe('Members');
  });

Pitfalls

  • An action in an untitled section is never rendered
  • One @if around several slotted nodes loses the slot (NG8011) — one per node
  • Don't add your own heading to the body — the section's h2 labels it

Things to remember

Two signal inputs, one aliased to title
Host carries only .section + aria-labelledby
Module counter → unique heading ids
Each slot once; empty action hidden by :has
Host component proves projection
Tokens by role, never hex
