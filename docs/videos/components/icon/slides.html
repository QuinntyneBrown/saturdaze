Coding sd-icon

One source of truth for every glyph: inline SVG, currentColor, no network.

Everywhere

<sd-icon name="heart" [filled]="favourite()" />
<sd-icon name="star" [size]="iconSize()" [filled]="step <= rating()" />

The decorator

Inputs stay inputs

Before

[attr.name], [attr.size], [attr.filled]
CSS: :host([filled]) svg

Now

[class.icon--filled] — the mock's own class
CSS: :host(.icon--filled) svg

Only classes and ARIA state go on the host (ADR-009).

A private knob

--sd-…

Public component knob, part of the API (e.g. --sd-btn-h)

--_size

Private: set on the host, read by icon.scss

inject() and four inputs

export class Icon {
  private readonly sanitizer = inject(DomSanitizer);

  readonly name = input<string>('sparkle');
  readonly size = input<number>(20);
  /** Solid glyph (stars, favourite heart). */
  readonly filled = input(false, { transform: booleanAttribute });
  /** Stroke weight; chips use 2 at 13px, the default 1.7 elsewhere. */
  readonly stroke = input<number>(1.7);

No numberAttribute — bind numbers

templatesize receives
[size]="13"13 (number) ✓
size="16"a string — type error under strictTemplates

computed(): look up, fall back, sanitize

  protected readonly path = computed<SafeHtml>(() =>
    this.sanitizer.bypassSecurityTrustHtml(ICONS[this.name()] ?? ICONS['sparkle']!),
  );
Safe only because the markup is constant

name can only pick a key. Accept SVG from an input, an API or a CMS, and the bypass becomes an XSS hole.

The tests

  • creates and renders a decorative inline svg
  • exposes the sprite names
  • renders name, size and filled through the glyph, size variable and host class
  • accepts the attribute form of filled
  • draws the named glyph
  • falls back to the sparkle glyph for an unknown name
  • forwards the stroke weight to the svg

Assert the rendered DOM

    fixture.componentRef.setInput('name', 'check');
    fixture.componentRef.setInput('size', 14);
    fixture.componentRef.setInput('filled', true);
    fixture.detectChanges();

    expect(svg.innerHTML).toContain('M5 12l5 5 9-11');
    expect(host.classList.contains('icon--filled')).toBe(true);
    expect(host.style.getPropertyValue('--_size')).toBe('14px');

Fallback, proven

  it('falls back to the sparkle glyph for an unknown name', () => {
    fixture.componentRef.setInput('name', 'sparkle');
    fixture.detectChanges();
    const sparkle = host.querySelector('svg')?.innerHTML;

    fixture.componentRef.setInput('name', 'does-not-exist');
    fixture.detectChanges();
    expect(host.querySelector('svg')?.innerHTML).toBe(sparkle);
  });

Pitfalls

  • External markup through the sanitizer bypass
  • Meaning carried only by an icon (it is aria-hidden)
  • size="16" instead of [size]="16"
  • New glyph → update the spec's count of 40

Things to remember

One constant map; ICON_NAMES derived
computed() looks up, falls back, sanitizes
Bypass safe only for constant markup
Private --_size knob from the host
Decorative, currentColor
.icon--filled swaps to solid
