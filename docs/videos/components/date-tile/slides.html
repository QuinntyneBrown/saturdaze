A constant and the decorator

@Component({

Inputs and one computed signal

  readonly date = input<string>('');
  /** Pre-split parts ("May" / "17"); when given they win over `date`. */
  readonly mon = input<string>('');
  readonly day = input<string>('');

  protected readonly parts = computed(() => {
    if (this.mon() || this.day()) return { mon: this.mon(), day: this.day() };
    const m = /^(\d{4})-(\d{2})-(\d{2})/.exec(this.date());
    if (!m) return { mon: '', day: '' };
    return { mon: MONTHS[Number(m[2]) - 1] ?? '', day: String(Number(m[3])) };
  });

Why computed()?

optionverdict
template expressionre-parses on every check
effect() writing a signalsecond state that can drift
computed()memoised, recalculated only when an input changes
No new Date()

Reading the digits from the string means a local date can never shift by a day in the viewer's time zone.

Pitfalls

  • Parsing with new Date() — time zones move the day
  • Deriving in the template or an effect()
  • Dropping aria-hidden, or not saying the date in text
  • Reformatting away the whitespace trick
