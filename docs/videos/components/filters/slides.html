Coding sd-filters

The decorator

@Component({
  selector: 'sd-filters',
  standalone: true,
  templateUrl: './filters.html',
  styleUrl: './filters.scss',
  changeDetection: ChangeDetectionStrategy.OnPush,
  host: {
    role: 'group',
    '[attr.aria-label]': 'label()',
    '[class.scroller-x]': 'scroll()',
    '[class.filters]': '!scroll()',
  },
})

One signal, two mock classes

scroll()host classmock rule
true (default)scroller-xfull-bleed scroller, wraps from 720px
falsefiltersalways wraps

Both from docs/mocks/styles/app.css (ADR-009). No scroll attribute on the host: inputs stay inputs.

Two inputs

export class Filters {
  readonly label = input<string>('Filters');
  readonly scroll = input(true, { transform: booleanAttribute });
}

  • creates as a labelled group

  • uses the label input as the accessible name

Projection order

  it('projects chips and dividers in order', () => {
    const wrapper = TestBed.createComponent(HostCmp);
    wrapper.detectChanges();
    const group = (wrapper.nativeElement as HTMLElement).querySelector('sd-filters') as HTMLElement;
    expect(group.getAttribute('aria-label')).toBe('Kind');
    const children = Array.from(group.children).map((c) => c.tagName.toLowerCase());
    expect(children).toEqual(['sd-filter-chip', 'span', 'sd-filter-chip']);
    expect(group.querySelectorAll('.filter-chip').length).toBe(2);
  });

Pitfalls

  • A group without a name
  • A wrapper element inside the host
  • A fixed number instead of --layoutGutter for the bleed
  • Dividers inside chips instead of between them

Things to remember

role="group" + label input
booleanAttribute picks the layout
Host bindings read signals directly
Full bleed with the gutter token
