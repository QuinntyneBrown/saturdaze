Coding sd-past-card

A stateless card where every control emits.

Six inputs in, six outputs out

          <sd-past-card
            [title]="card.title"
            [dateRange]="card.eyebrow"
            [rating]="card.rating || null"
            [favourite]="card.favourite"
            [highlights]="card.highlights"
            [cover]="card.cover?.media ?? null"
            (addPhoto)="addPhoto(card)"
            (favouriteToggle)="favourite(card, $event)"
            (rename)="rename(card)"
            (rate)="rate(card)"
            (remix)="remix(card)"
            (repeat)="repeat(card)"
          />

The decorator

@Component({
  selector: 'sd-past-card',
  standalone: true,
  imports: [Button, Icon, Media, Stars],

No mirrored title, rating or favourite (ADR-009).

Inputs and outputs

export class PastCard {
  readonly cardTitle = input<string>('', { alias: 'title' });
  /** "10 – 11 May 2026". */
  readonly dateRange = input<string>('');
  readonly rating = input<number | null>(null);
  readonly favourite = input(false, { transform: booleanAttribute });
  readonly highlights = input<string>('');
  /** The weekend's cover; `null` shows "Add a photo to {title}" (L2-110 AC2). */
  readonly cover = input<CardMedia | null>(null);
  readonly addPhoto = output<void>();
  readonly favouriteToggle = output<boolean>();
  readonly rename = output<void>();
  readonly rate = output<void>();
  readonly remix = output<void>();
  readonly repeat = output<void>();

Input + output, not model()

model()

The card flips its own state; card and server can disagree if the save fails

input() + output()

The page is the single source of truth and writes the value back

Labels from computed()

  protected readonly ratingLabel = computed(() => {
    const r = this.rating();
    return r ? `${r} of 5` : 'Rate it';
  });

  protected readonly rateLabel = computed(() => {
    const r = this.rating();
    return r ? `Rate this weekend, currently ${r} of 5` : 'Rate this weekend';
  });

The heart is a pressed toggle

<div class="card__row">
  <span class="card__eyebrow">{{ dateRange() }}</span>
  <sd-button
    variant="ghost"
    size="sm"
    icon
    btnClass="fav-btn"
    label="Favourite this weekend"
    [pressed]="favourite()"
    (click)="favouriteToggle.emit(!favourite())"
  >
    <sd-icon name="heart" [filled]="favourite()" />
  </sd-button>
</div>

Every control is a named button

<h3 class="card__title">
  <button
    class="card__title-btn"
    type="button"
    [attr.aria-label]="'Rename: ' + cardTitle()"
    (click)="rename.emit()"
  >
    {{ cardTitle() }}
  </button>
</h3>
<button class="card__rate" type="button" [attr.aria-label]="rateLabel()" (click)="rate.emit()">
  <sd-stars [rating]="rating() ?? 0" [label]="ratingLabel()" />
</button>
@if (highlights()) {
  <p class="card__highlights">{{ highlights() }}</p>
}

Six tests

  1. creates an unrated, unfavourited card
  2. shows the favourite heart as a pressed toggle
  3. reflects the rating in the stars and the rate button name
  4. renders the highlights line
  5. emits the next favourite state
  6. emits rename, rate, remix and repeat from their buttons

The next value, not the current one

  it('emits the next favourite state', () => {
    const spy = vi.fn();
    fixture.componentInstance.favouriteToggle.subscribe(spy);
    favBtn().click();
    expect(spy).toHaveBeenLastCalledWith(true);

    fixture.componentRef.setInput('favourite', true);
    fixture.detectChanges();
    favBtn().click();
    expect(spy).toHaveBeenLastCalledWith(false);
  });

Not covered here

  • The "Add a photo" tile and addPhoto
  • The cover branch — sd-media has its own spec

Pitfalls

  • Local favourite state in the card
  • A heart without label and aria-pressed
  • Click handlers on plain text instead of buttons
  • Not writing results back into the inputs

Things to remember

Stateless: inputs in, six outputs out
favouriteToggle emits the next value
No model(), no local signal()
Two computed() labels
Named buttons; heart uses aria-pressed
card-host mixin + --sd-btn-w
