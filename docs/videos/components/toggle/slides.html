Coding sd-toggle

A switch built on a real checkbox.

The design in one comment

A real <input type="checkbox" role="switch"> (visually hidden) inside a label, so keyboard, focus and assistive tech come for free.

components/src/lib/toggle/toggle.ts

The decorator

@Component({
  selector: 'sd-toggle',
  standalone: true,
  /* templateUrl, styleUrl */
  changeDetection: ChangeDetectionStrategy.OnPush,
  providers: [
    {
      provide: NG_VALUE_ACCESSOR,
      useExisting: forwardRef(() => Toggle),
      multi: true,
    },
  ],

No host object: inputs stay inputs. Checked and disabled live on the real checkbox (ADR-009).

Inputs and local state

  readonly label = input<string>('');
  /** Accessible name when no visible label is rendered. */
  readonly srLabel = input<string>('');
  readonly checked = input(false, { transform: booleanAttribute });

  protected readonly internalChecked = signal<boolean>(false);
  protected readonly disabled = signal<boolean>(false);

  private formBound = false;
  private onChange: (value: boolean) => void = () => {};
  private onTouched: () => void = () => {};

Seed until a form binds

  constructor() {
    effect(() => {
      const c = this.checked();
      if (!this.formBound) this.internalChecked.set(c);
    });
  }
  writeValue(value: boolean | null): void {
    this.formBound = true;
    this.internalChecked.set(!!value);
  }

The constructor and writeValue are not adjacent in the file.

Three writers, one signal

Input

checked seeds

Form

writeValue takes over

User

handleChange

formBound is a plain field: flipping it must not re-run the effect.

Reporting to the form

  protected handleChange(event: Event): void {
    const next = (event.target as HTMLInputElement).checked;
    this.internalChecked.set(next);
    this.onChange(next);
    this.onTouched();
  }

The template

<label class="toggle">
  <input
    class="toggle__input"
    type="checkbox"
    role="switch"
    [checked]="internalChecked()"
    [disabled]="disabled()"
    [attr.aria-label]="label() ? null : srLabel() || null"
    (change)="handleChange($event)"
  />
  <span class="toggle__track"></span>
  @if (label()) {
    <span class="toggle__label">{{ label() }}</span>
  }
</label>

Spec setup and structure

  it('creates an unchecked switch inside its label', () => {
    expect(component).toBeTruthy();
    const label = host.querySelector('label.toggle') as HTMLLabelElement;
    expect(label).not.toBeNull();
    expect(label.contains(input())).toBe(true);
    expect(input().type).toBe('checkbox');
    expect(input().getAttribute('role')).toBe('switch');
    expect(input().checked).toBe(false);

Naming

  • renders the visible label and drops any aria-label
  • uses srLabel as the accessible name when there is no visible label

lets a bound form take over from the static input

    component.writeValue(true);
    fixture.detectChanges();
    expect(input().checked).toBe(true);

    fixture.componentRef.setInput('checked', false);
    fixture.detectChanges();
    expect(input().checked).toBe(true);

Also: seeds the state from the static checked input

The form contract

  • reports a user toggle to the form and marks it touched
  • disables the switch from the form

Pitfalls

  • Keep the native checkbox — keyboard, focus, announcements
  • Unlabelled toggle? Always set srLabel
  • No changed output exists despite the doc comment — use the form / ngModelChange

Things to remember

Real checkbox, role="switch", inside a label
Exactly one accessible name
Input seeds; writeValue wins once bound
effect() + plain flag for several writers
Styles key off the real input's states
