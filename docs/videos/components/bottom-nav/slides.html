Coding sd-bottom-nav

A navigation landmark and a protected offset.

Rendered once, by the shell

  <main
    id="main"
    class="sd-frame"
    …
  >
    <router-outlet />
  </main>
  @if (shell() === 'app') {
    <sd-bottom-nav [active]="nav()" />
  }

Below 720px only — from 720px sd-top-bar takes over (ADR-009).

The host is the landmark

@Component({
  selector: 'sd-bottom-nav',
  standalone: true,
  imports: [Icon, RouterLink],
  templateUrl: './bottom-nav.html',
  styleUrl: './bottom-nav.scss',
  changeDetection: ChangeDetectionStrategy.OnPush,
  host: {
    class: 'bottom-nav',
    role: 'navigation',
    'aria-label': 'Primary',
  },
})

One nullable input

export class BottomNav {
  readonly active = input<NavKey | null>(null);

  protected readonly items = NAV_ITEMS;
}
export type NavKey = 'weekend' | 'ideas' | 'past' | 'family';

Constant data stays constant

export const NAV_ITEMS: readonly NavItem[] = [
  { key: 'weekend', label: 'Weekend', icon: 'home', route: '/weekend' },
  { key: 'ideas', label: 'Ideas', icon: 'sparkle', route: '/ideas' },
  { key: 'past', label: 'Past', icon: 'star', route: '/past' },
  { key: 'family', label: 'Family', icon: 'user', route: '/family' },
];
  • Never changes at runtime → no signal()
  • Shared with sd-top-bar → the two navs can't disagree

The whole template

@for (item of items; track item.key) {
  <a

The protected line

:host {
  position: fixed;
  left: 12px;
  right: 12px;
  z-index: var(--zIndexBottomNav);
  // ADR-005 (BUG-047 + BUG-049). The bottom nav must clear whichever
  // bottom-edge obstruction is currently present:
  //   - `env(safe-area-inset-bottom)` for the home indicator (~34px on
  //     Face-ID iPhones in PWA / standalone mode).
  //   - `var(--sd-chrome-bottom)` for iOS Safari's *current* bottom URL/tab
  //     bar height — set by `trackBottomChrome()` in main.ts using the
  //     VisualViewport API. …
  // These are NOT additive — … we take the larger of the two and
  // add a 12px visual floor. …
  // Do not simplify without re-reading ADR-005.
  bottom: calc(12px + max(env(safe-area-inset-bottom, 0px), var(--sd-chrome-bottom, 0px)));

Measuring the bottom chrome

  const update = (): void => {
    const layoutHeight = root.clientHeight;
    const visibleBottom = vv.offsetTop + vv.height;
    const bottomChrome = Math.max(0, layoutHeight - visibleBottom);
    root.style.setProperty('--sd-chrome-bottom', `${bottomChrome}px`);
  };
  vv.addEventListener('resize', update);
  vv.addEventListener('scroll', update);
  window.addEventListener('resize', update);
  update();
}

trackBottomChrome();

Pitfalls

  • Simplifying the bottom calc, or adding the insets
  • A separate active class instead of aria-current
  • Rendering the nav per page
  • Wrapping constant items in a signal

Things to remember

Host is the navigation landmark
active: NavKey | null
Shared constant items, tracked by key
aria-current drives the style
Bottom offset follows ADR-005
Regression spec guards it
