A token is a named design decision

PartExampleUsed by
NamecolorBrandBackgroundcode
Value#e07856the browser
Rolefill of the primary buttonpeople

Components never mention values

Not this

.btn--primary {
  background: #e07856;
  color: #ffffff;
}

This

.btn--primary {
  background: var(--colorBrandBackground);
  color: var(--colorNeutralForegroundOnBrand);
}

The value lives in one place; changing it changes that role everywhere — and nothing else.

Delivered as CSS custom properties

:root {
  --colorBrandBackground: #e07856;
}

.btn--primary {
  background: var(--colorBrandBackground);
}
  • Declared once on :root
  • They cascade — any element can override them (that's theming)

The golden rule

Components read alias tokens and ramp tokens (spacing, radius…). Never a raw palette value.

Things to remember

A token is a named decision: name, value, role
Name by role, not by value
Three layers: global → alias → theme
Components read alias and ramp tokens only
TypeScript is the source; a script generates the CSS
CI rejects stale generated files
