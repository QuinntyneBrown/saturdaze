The one place AI is used

Catalog ingestion uses Claude

  • LocalEvents — festivals, markets, seasonal openings
  • Activities — parks, trails, museums, indoor play
  • Restaurants — family-friendly lunch and dinner

Refreshed weekly by a grounded web search that returns strict JSON.

Weekend planner deterministic

  • Reads the catalogs, weather, commitments, preferences
  • Builds the itinerary with plain C# rules
  • Never calls a model

If the model is down or wrong, the existing plan still works.

AI is a data supplier at the edge of the system,
not the decision maker in the middle.

What comes back

  • text blocks → concatenated into RawText
  • server_tool_use blocks → counted as searches
  • usage → input_tokens, output_tokens, web_search_requests
  • stop_reason pause_turn → replay and continue, at most MaxContinuationTurns (3) times

Why Microsoft Foundry

docs/adr/ADR-011-claude-via-microsoft-foundry.md

  • Same API. Foundry serves the Claude Messages API at https://<resource>.services.ai.azure.com/anthropic/v1/messages; same body, same headers, same response.
  • One bill. Saturdaze already lives in Azure (saturdaze-rg); Claude traffic joins the same cost view.
  • Region. Claude is not offered in canadacentral, so the Foundry resource sd-ai-uofnt2 sits in eastus2.
  • Hosting. Deployment claude-sonnet-5, model version 2: hosted on Azure end to end.

Things to remember

One place. AI means catalog ingestion; the planner is deterministic.
One flow. Trigger → runner → prompts → Claude + web search → parser → upserter → audit row.
One bill. Microsoft Foundry by default, Anthropic one setting away.
One contract. IWebSearchClient in Application, provider in Infrastructure.
Five rails. Dry run, daily budget, caps, one retry, lazy failure.
