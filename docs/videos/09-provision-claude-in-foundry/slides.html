Bicep · parameters

param accountName string = 'sd-ai-uofnt2'
@description('Region that offers the chosen Claude model on Global Standard.')
param location string = 'eastus2'
param deploymentName string = 'claude-sonnet-5'
param modelName string = 'claude-sonnet-5'
@description('Model version 2 is the "Hosted on Azure" build; 1 runs on Anthropic infrastructure.')
param modelVersion string = '2'
@description('Thousands of tokens per minute. Capacity is free; tokens are billed per use.')
param capacity int = 80

Claude is not offered in canadacentral; this is the one resource outside the group's region.

Bicep · Marketplace attestation

@description('Legal name of the organization using Claude.')
param organizationName string
@description('Two-letter ISO country code.')
@minLength(2) @maxLength(2)
param countryCode string
@allowed(['technology', 'finance', 'healthcare', 'education', 'retail',
          'manufacturing', 'government', 'media', 'other'])
param industry string = 'technology'

Claude on Foundry is a Marketplace offer. Sending these under modelProviderData accepts it for the subscription without a portal click. They must describe your real organization.

Bicep · the account

resource account 'Microsoft.CognitiveServices/accounts@2025-10-01-preview' = {
  name: accountName
  location: location
  kind: 'AIServices'
  sku: { name: 'S0' }
  properties: {
    customSubDomainName: accountName
    publicNetworkAccess: 'Enabled'
    // Ingestion authenticates with the account key (x-api-key).
    disableLocalAuth: false
  }
}

disableLocalAuth: false keeps key authentication on. Turn it off and every request is a 401.

Bicep · the deployment

resource claude 'Microsoft.CognitiveServices/accounts/deployments@2025-10-01-preview' = {
  parent: account
  name: deploymentName
  sku: { name: 'GlobalStandard', capacity: capacity }
  properties: {
    model: { format: 'Anthropic', name: modelName, version: modelVersion }
    #disable-next-line BCP037
    modelProviderData: { organizationName: organizationName,
                         countryCode: countryCode, industry: industry }
    // Pin the Azure-hosted version; an automatic upgrade must not move the deployment.
    versionUpgradeOption: 'NoAutoUpgrade'
    raiPolicyName: 'Microsoft.DefaultV2'
  }
}
output baseUrl string = 'https://${account.name}.services.ai.azure.com/anthropic/'

The deployment script

pwsh ./eng/Deploy-Foundry.ps1 -OrganizationName "<legal organization name>"
#   -CountryCode CA  -Industry technology  -ResourceGroup saturdaze-rg
#   -AccountName sd-ai-uofnt2  -Location eastus2  -Capacity 80  -NoKey
  1. az deployment group create with the Bicep file and parameters. A few minutes the first time; idempotent after that.
  2. Prints the endpoint (…/anthropic/, trailing slash) and the deployment name from the outputs.
  3. Reads key1 with az cognitiveservices account keys list and writes ANTHROPIC_FOUNDRY_API_KEY=… into the gitignored .deploy/azure.env. Never printed.

Where the key lands

$key = az cognitiveservices account keys list -g $ResourceGroup -n $AccountName `
    --query key1 -o tsv
$envFile = Join-Path $repoRoot ".deploy\azure.env"
$lines = @(if (Test-Path $envFile) { Get-Content $envFile |
    Where-Object { $_ -notmatch '^ANTHROPIC_FOUNDRY_API_KEY=' } })
$lines += "ANTHROPIC_FOUNDRY_API_KEY=$key"
[System.IO.File]::WriteAllLines($envFile, [string[]]$lines)
Write-Host "Stored ANTHROPIC_FOUNDRY_API_KEY in .deploy\azure.env"

Quota error?

Shared Global Standard Claude quota in the region is exhausted. Retry later, lower -Capacity, or fall back to Provider: Anthropic (video 10).

The portal path (as of October 2026)

  1. Create an Azure AI Foundry resource in eastus2; its name becomes FoundryResource in configuration.
  2. In the Foundry portal, open the model catalog, pick Claude Sonnet 5, choose the Azure-hosted version, deploy with the default name.
  3. Accept the Marketplace terms when prompted.
  4. Open Keys and endpoint; copy key1 into .deploy/azure.env.

Prefer the script: every setting is in a reviewable file and re-running converges. If you clicked, run the script afterwards so the template matches reality.

Checking it works

KEY="$(grep '^ANTHROPIC_FOUNDRY_API_KEY=' .deploy/azure.env | cut -d= -f2-)"
curl -sS https://sd-ai-uofnt2.services.ai.azure.com/anthropic/v1/messages \
  -H "x-api-key: $KEY" -H "anthropic-version: 2023-06-01" -H "content-type: application/json" \
  -d '{"model":"claude-sonnet-5","max_tokens":32,"messages":[{"role":"user","content":"Say hello."}]}'

export ANTHROPIC_FOUNDRY_API_KEY="$KEY"
dotnet run --project backend/src/Saturdaze.Cli -- ingest --type events --dry-run

A 200 with a text block means the three objects line up. ADR-011 recorded the live check: a dry run parsed events after 5 searches.

Rotate and tear down

Rotate

az cognitiveservices account keys regenerate -g saturdaze-rg -n sd-ai-uofnt2 --key-name key1
pwsh ./eng/Deploy-Foundry.ps1 -OrganizationName "…"      # refreshes .deploy/azure.env

Tear down

az cognitiveservices account deployment delete -g saturdaze-rg -n sd-ai-uofnt2 \
    --deployment-name claude-sonnet-5
az cognitiveservices account delete -g saturdaze-rg -n sd-ai-uofnt2
az cognitiveservices account purge  -g saturdaze-rg -n sd-ai-uofnt2 -l eastus2

Update any host setting that carried the old key. Soft-deleted accounts keep holding quota until purged.

Pitfalls

Things to remember

Three objects. Account → base URL, deployment → model, key → x-api-key.
Source of truth. claude.bicep describes; Deploy-Foundry.ps1 applies and stores the key in .deploy/azure.env.
Settings that matter. eastus2, version 2, NoAutoUpgrade, key auth on.
Verify twice. Raw HTTP, then saturdaze ingest --type events --dry-run.
Rotate through the script; tear down with delete and purge.
