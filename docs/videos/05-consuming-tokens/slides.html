Breakpoints live in Sass

$bp-xsmall-max: 379px;
$bp-tablet: 720px;
$bp-desktop: 1024px;

@mixin respond-to($size) {
  @if $size == xsmall {
    @media (max-width: #{$bp-xsmall-max}) {
      @content;
    }
  } @else if $size == tablet {
    @media (min-width: #{$bp-tablet}) {
      @content;
    }
  } /* … desktop … */
}

@media (min-width: var(--x)) does not work — media conditions can't read custom properties.

The reference follows any [sdThemeProvider] above it; the value doesn't.

[sdThemeProvider]

  readonly theme = input.required<PartialTheme>({ alias: 'sdThemeProvider' });

  constructor() {
    effect(() => {
      const el = this.host.nativeElement;
      const vars = themeToCssVariables(this.theme());
      for (const name of this.applied) {
        if (!(name in vars)) this.renderer.removeStyle(el, name, RendererStyleFlags2.DashCase);
      }
      for (const [name, value] of Object.entries(vars)) {
        this.renderer.setStyle(el, name, value, RendererStyleFlags2.DashCase);
      }
      this.applied = Object.keys(vars);
    });
  }

Two notes

  • The app already gets the theme from _tokens.scss — never wrap the root.
  • Changing the bound theme updates properties in place and removes keys it no longer sets.

Consumer rules

  1. No hex in components — missing colour? add an alias token
  2. Pick the token named after the job
  3. Use fills and inks in their pairs
  4. --sd- for component knobs only
  5. respond-to() for breakpoint logic; tokens for sizes
  6. TS: theme for values, tokens for live references

Things to remember

Read tokens by role — works under any theme
Fill + ink pairs: contrast by construction
Composite values from smaller tokens
Breakpoints in Sass, matching the overrides
ThemeProvider writes a partial theme on one element
The cascade does the rest
