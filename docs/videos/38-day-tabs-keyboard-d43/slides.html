D43: the day tabs, by keyboard

The APG Tabs keyboard model: one Tab stop, arrows with wrap, Home and End

What drifted

The mock

Clicks only; no arrow keys; every tab in the Tab order

The app

Roving tabindex and ← →, but no Home / End

Why it matters

  • WCAG 2.1.1 keyboard; 4.1.2 name, role, value
  • A tablist is one Tab stop; arrows move inside it; Home and End jump to the ends
  • Weekend shows one day at a time, so the tabs have to work

1 · Requirement, then mock

L2-139

Only the selected tab is in the Tab order. ← → select and focus (wrapping); Home / End select and focus the first and last tab.

docs/mocks/app.js: tabindex 0 / -1 and a keydown handler

2 · sd-segments

const target =
  event.key === 'ArrowRight' ? index + 1
  : event.key === 'ArrowLeft' ? index - 1
  : event.key === 'Home' ? 0
  : event.key === 'End' ? tabs.length - 1
  : null;
if (target === null) return;
const next = tabs[(target + tabs.length) % tabs.length];
