Design drift · Video 42

D47: four small gaps in the product

Admin landmark, field descriptions, duplicate chips and the skip link

What drifted

sd-admin-nav

aria-label="Admin" on a host with no role: no landmark

sd-text-input

Hint hidden during an error, but still in aria-describedby

sd-chip-input

A duplicate is dropped silently

Skip link

Bare href="#main" vs <base href="/">

Why it matters

  • WCAG 1.3.1 info and relationships; 3.3.1 error identification; 4.1.2 name, role, value
  • A role-less landmark is invisible; a missing described-by target is noise; silent loss looks like a bug
  • The skip link was already correct: it prevents the navigation and focuses main

1 · Requirement L2-140

  • Admin navigation: a navigation landmark named Admin
  • aria-describedby lists only ids in the page
  • A duplicate chip stays, invalid, with "{value} is already in {label}."
  • The skip link stays on the page

2 · Three changes

// admin-nav.ts
role: 'navigation', 'aria-label': 'Admin',
// text-input.ts
if (this.error()) ids.push(this.errorId);
else if (this.hint()) ids.push(this.hintId);
// chip-input.ts
if (exists) {
  this.error.set(`${v} is already in ${this.label() || 'the list'}.`);
  return;                      // the draft stays in the field
}

Things to remember

  • A landmark needs a role as well as a name
  • Describe a field only with elements that exist
  • Never drop input silently: keep it and say why
  • Requirement first, failing tests, then delete the drift record
