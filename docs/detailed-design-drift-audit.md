# Detailed-design drift audit

## Baseline and scope

This audit compares the checked-in implementation at `6441c677a261bb5c40533e68d716ca255780b55c` on `claude/adoring-turing-cuLwA` with the detailed designs and L1/L2 specifications. The audit date is 2026-09-05. The review covers all 38 existing feature designs and adds two ingestion designs, for 40 designs in total.

The approved reconciliation rule aligns specifications and designs with verified product changes while preserving unmet obligations as explicit implementation gaps. Descriptive prose and diagrams describe current code. Normative requirement tables reproduce the L2 requirement paragraph and its L1 parent identifiers exactly; acceptance criteria remain in [L2.md](specs/L2.md). A described implementation limitation does not waive a requirement.

Changes are limited to `docs/specs/`, `docs/detailed-designs/`, and this record. The 12 pre-existing deletions under `docs/user-guide/` are unrelated and remain untouched. No application, workflow, deployment, or security behavior changes as part of this audit.

## Reconciled drift

The principal corrections replace obsolete routed-page names and v1 interaction flows with the current responsive application; distinguish browser filtering from server queries; document actual session refresh and revocation; expose planner, history, and shared-response boundaries; and show the gated Azure deployment chain. The standalone design-system catalog has since been replaced by the Storybook docsite (ADR-012).

[L1.md](specs/L1.md) adds L1-031 for catalog ingestion. [L2.md](specs/L2.md) adds L2-077 through L2-083 for on-demand and scheduled ingestion, L2-084 for Repeat/Remix, L2-085 for day operations, and L2-086 for sharing/calendar export. Existing requirements retain their IDs. Updated clauses reflect accepted v2 routes, event windows, errand placement, responsive chrome, session behavior, CLI safeguards, and conditional deployment. Normative verbs use the design-document house style.

The new ingestion slice separates prompt context, provider research, parser validation, natural-key upserts, audit saves, daily budgets, and dry-run costs. The worker slice separates long-lived UTC cron, immediate startup, disabled, and one-pass behavior. Source artifacts are not described as deployed infrastructure.
