Pattern

Navigation and page structure

Four places, always in the same order: Weekend, Ideas, Past, Family. A thumb-reach pill on phones, a top bar on wider screens, and every page opens with the same header so a parent always knows where they are.

Overview

Each route picks one of four shells (ADR-009, ADR-014). The shell owns navigation; the page owns its header and content.

ShellChromeRoutes
AppBottom nav under 720px, top bar from 720pxWeekend, Ideas, Past, Family, Review submissions
SiteSite bar: brand, Sign in, optional call to actionLanding, Legal, a shared weekend
BareNone; the auth card carries the brandSign in, Create account, Reset password, Verify email
AdminAdmin nav: a bar under 1024px, a sidebar from 1024pxPhoto health, Places, Review queue, Ingestion skips, Activity log

Inside the shell, every page starts with a page header (title, one-line subtitle, actions), and the Weekend page replaces it with the cover photo.

Saturdaze is at most two levels deep for families, so the back link is enough; breadcrumbs appear only in admin.

Bottom nav clearance (ADR-005)

The bottom nav clears whichever bottom obstruction is present, not the sum of them: bottom: calc(12px + max(env(safe-area-inset-bottom, 0px), var(--sd-chrome-bottom, 0px))). --sd-chrome-bottom is written by a VisualViewport listener in the family app's main.ts before Angular starts. Toasts stack above the nav using the same height. Run the bottom-nav regression spec after any change here.

Accessibility

Role and pattern

Each navigation is a <nav> landmark with a distinct label: "Primary", "Admin", "Breadcrumb", "Idea type". Navigation items are plain links with aria-current="page"; they are not ARIA tabs or menus. In-place day switching uses the APG Tabs pattern; breadcrumbs follow the APG Breadcrumb pattern. Landmarks per page: header, nav, main#main, footer.

Keyboard

KeyAction
TabFirst stop is the skip link; then brand, the four places, the account avatar, then the page. The bottom nav comes after main in the DOM, so it is reached last on phones.
EnterFollows a link.
Left / RightMoves between Saturday and Sunday tabs (roving focus); page-switch segments are links and use Tab.

Focus

After a route change, focus moves to the page's h1 (with tabindex="-1") and the document title updates, so screen readers announce the new page. The sticky top bar never covers the focused element: scroll-padding-top equals --layoutTopBarHeight (2.4.11).

Labelling

Labels are the same everywhere (3.2.4): "Weekend", "Ideas", "Past", "Family". Icon-only back buttons say where they go: "Back to Family". The avatar link is "Account menu".

Motion

The top bar's background and shadow fade in over --durationNormal once the page scrolls. Route changes do not animate.

Touch

Bottom nav items are a quarter of a 60px pill each; top bar and admin links are 40px tall; the eyebrow back link is at least 24px tall and the phone back button 40px.

Content

  • Place names are one word and never change: Weekend, Ideas, Past, Family.
  • Page titles say what is here: "This weekend", "Past weekends", "Review submissions". Subtitles give today's context: "Picked for Eli and Mae, under 45 minutes from Port Credit."
  • Back links name the parent ("Family"), not "Back".
  • Admin labels are task nouns: "Photo health", "Review queue", "Activity log".
