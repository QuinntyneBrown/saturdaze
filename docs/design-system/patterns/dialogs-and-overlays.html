Pattern

Dialogs and overlays

Overlays keep a parent on the page they were on: a dialog for a short task or a decision, a sheet for the same thing on a phone, a menu for a handful of actions, a tooltip to name an icon. Anything longer gets a page.

Overview

Every modal surface in Saturdaze is an Angular CDK Dialog; every anchored popover is a CDK Overlay. Nothing hand-rolls a modal, a focus trap or a scrim. One dialog component serves as a centred modal from 720px and a bottom sheet below it; the markup does not change, CSS does.

  • Dialog: edit one thing (D17 Edit Mae), decide (D3 Regenerate the weekend?), confirm a loss (D21), or read a result (D9, D11).
  • Sheet: the same dialog under 720px, rising from the bottom edge where a thumb can reach it.
  • Menu: two to six actions on one trigger, anchored to it (D25 Weekend options, D26 Account).
  • Tooltip: the name of an icon-only button, on hover or focus. Never essential, never interactive.
  • Page: anything long, multi-step, or worth a URL (sign in, Family, an admin place).

States

Stacking

Overlays stack by z-order token, never by an ad hoc number. Popovers sit above dialogs so a select or menu inside a dialog is not hidden; toasts sit above both so "Saved Mae" is visible as the dialog closes.

LayerTokenValue
Sticky day header--zIndexSticky
Top bar, admin nav--zIndexTopBar
Bottom nav--zIndexBottomNav
Dialog and sheet, with scrim--zIndexDialog
Menu, select popover--zIndexPopover
Toast region--zIndexToast
Tooltip, skip link--zIndexTooltip
  • One dialog at a time, with one exception: a confirmation may open over the dialog that asked for it (D21 over D17). Never three deep.
  • Success replaces, it does not stack. D7 closes as D9 opens, so Escape from D9 goes back to the page, not to a stale form.
  • Menus close when an item is chosen, before any dialog the item opens.

Accessibility

Role and pattern

Dialogs follow the APG Dialog (Modal) pattern: role="dialog" or role="alertdialog", aria-modal="true", labelled by the title and described by the sub line. Menus follow the Menu Button pattern; tooltips the Tooltip pattern. CDK Dialog supplies the focus trap, scroll lock and aria-modal; CDK Overlay positions menus.

Keyboard

KeyAction
Tab / Shift+TabCycles within the dialog; never reaches the page behind.
EscCloses the top-most dialog or menu (the same as Cancel); ignored while busy.
Enter / Space / DownOn a menu trigger: opens the menu with focus on the first item.
Up / Down, Home / EndMove between menu items.
Esc on a tooltipHides the tooltip without moving focus.

Labelling

The title is the accessible name; the sub line is the description. The close button is "Close". Menu triggers carry aria-haspopup="menu" and aria-expanded. A tooltip duplicates the button's aria-label, so it is linked with aria-describedby only when it adds a shortcut.

Motion

Dialogs, sheets and menus rise 4px and fade in over --durationNormal; under reduced motion they appear at once. Nothing slides across the screen.

Touch

Sheet rows are 56px; menu items 44px; the close button is 32px with clear space around it; footer buttons 44px on phones.

Content

  • Form titles are the action and the object: "Edit Mae", "Add an errand", "Rename this weekend".
  • Decision and confirmation titles are a question that names the object: "Regenerate Saturday?", "Remove Mae from the family?". The sub line states the consequence: "Sunday will not change."
  • Success titles say what happened, with the specifics: "Added to Sunday at 9:15".
  • Buttons: the verb from the title ("Regenerate", "Remove"), Cancel for the safe way out, "Done" to close a success dialog. D22 uses "Stay signed in" because "Cancel sign out" reads badly.
  • Menu items are verb phrases without descriptions; the sheet version adds a one-line description.
