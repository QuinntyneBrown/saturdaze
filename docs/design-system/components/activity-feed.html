Component · Data display

Activity feed

An ordered list of what changed, newest first: when, who, which place, what kind of change, and the change itself. Each record stacks into a few short lines so the admin activity log reads on a phone.

Overview

Use the activity feed for a time-ordered record of changes that people read top to bottom: the admin activity log of every photo change. Each row is one event and every value in it reads on its own ("admin@saturdaze.app", "Removed rec-room-old.jpg"), so it works without column headers at phone width.

  • From 720px, prefer the table for the same records: column headers let the reader compare times or people down the page. The mock keeps the feed at every width and lines it up in five columns from 1024px; that grid has no headers (drift D23).
  • Use a list when each row is a thing to open rather than an event that happened.
  • Use a toast or alert to tell someone about a change as it happens; the feed is the history.

Anatomy

  1. Time.audit-row__time: <time datetime>, monospace 12px, --colorNeutralForeground2, zone written out.
  2. Who.audit-row__who: the account that made the change, --colorNeutralForeground2, breaks anywhere so a long email never overflows.
  3. Place.audit-row__place: link to the place, semibold, underlined, --colorBrandForegroundLink.
  4. ActionA chip naming the kind of change; top right while stacked.
  5. Change.audit-row__change: before → after, full width, --colorNeutralForeground1.

Variants

One row layout; the action chip varies. Its word names the change, and its tone groups like changes for scanning. Keep this mapping so the same tone always means the same action.

Sizes

One size. Rows are padded 12 × 16px; density comes from how much the change says, not from a size modifier.

States

Rows are not interactive; only the place link is. It takes the shared focus ring and, on pointer devices, the link hover. Loading and empty belong to the whole list.

Loading and empty

No changes match

Nobody has changed a photo at Harbour Grill. Try everyone, or all places.

  • Loading: two or three skeleton rows in the same grid, aria-busy="true" on the list. A status line ("Loading activity…") goes to a live region if loading takes over a second.
  • Empty: a compact empty state instead of the list, naming the filter that emptied it and offering to clear it. A log with no changes at all says "No photo changes yet".
  • New rows arriving while the page is open are added at the top on the next load, not pushed in live; the admin is reading.

Responsive behaviour

  • Under 1024px each row is a two-column grid: time, who and the place stack in the left column, the action chip sits top right, and the change takes the full width underneath.
  • From 1024px (mock behaviour) the row becomes one line of five columns: 9.5rem time, 12.5rem who, flexible place, 6rem action, wider change. These columns have no headers, so the design system renders a table from 720px instead (.hide-gte-720 on the feed, .hide-lt-720 on the table). Keep the five-column grid only where the e2e locators still depend on it.
  • Long emails and file names break anywhere (overflow-wrap: anywhere) rather than widening the page at 360px.

Theming

The feed reads alias tokens only and sits on the list's card surface (.list--card). Time and who use --colorNeutralForeground2, the place link --colorBrandForegroundLink, the change --colorNeutralForeground1; rules between rows are --colorNeutralStroke2. The chips bring their own tone pairs. In the dark theme the card becomes warm umber, the link lightens to coral 300 and the chip tints darken with lighter text; nothing in .audit-row changes.

Accessibility

Role and pattern

An ordered list (<ol>) because the order is the meaning: newest first. Each event is an <li>; screen readers announce "list, 5 items" and the position of each. No ARIA pattern applies. The APG Feed pattern is for content that loads as you scroll; this log is paginated, so it stays a plain list.

Keyboard

KeyAction
Tab / Shift+TabMoves from one place link to the next; rows themselves are not tab stops.
EnterOpens the place.

Focus

The place link takes the shared ring (2px --colorStrokeFocus2, 2px offset) on :focus-visible, with a small radius so it hugs the text.

Labelling

Name the list with the page or section heading (aria-labelledby). Times are <time datetime="2026-10-06T14:02Z"> so machines read the instant and people read the zone. Values must make sense without a column header: an email for who, a sentence for the change. The action chip is text, so it is read in order after the place.

Motion

None. Skeleton shimmer stops under prefers-reduced-motion.

Touch

The place link is a line of 14px semibold text; with the row's 12px vertical padding its target clears 24px and no other target sits within 24px of it. The pager buttons are 32px.

Content

  • Time: YYYY-MM-DD HH:MM UTC. Admins work across zones; never "2 hours ago" in a log someone may quote in a bug report.
  • Who: the account email, exactly as stored.
  • Place: the place's catalog name, linked.
  • Action: one capitalised word from the fixed set: Primary, Upload, Edit, Review, Remove.
  • Change: before → after, with an em dash for "was empty": "Alt text: — → Patio tables by the water". Add the reason after a middle dot: "Rejected harbourfest-2024.jpg · Wrong year".
