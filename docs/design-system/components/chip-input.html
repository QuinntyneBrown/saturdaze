Chip input

A chip input collects a short list of free-text tags, one chip per entry: the things the family likes and the things the planner should leave out.

Overview

Use a chip input when the answer is a handful of short, free-text values the person types themselves, and each value is worth seeing and removing on its own. It lives in the D20 Likes and dislikes dialog, where liked tags boost picks and disliked ones are left out.

  • Use a text field for one value, even a long one.
  • Use checkboxes or filter chips when the options are known in advance; picking beats typing.
  • Use a static chip list to show tags that cannot be edited here. There is no disabled chip input.
  • If suggestions are added later, the field becomes a combobox (see Accessibility); the chips and keys stay the same.

Anatomy

  1. Label.field__label, a real <label for> pointing at the text input.
  2. Container.chip-input: looks like a text field (44px minimum, 1px accessible stroke, medium radius) and wraps as chips are added.
  3. Chip.chip with a tone: leaf for likes, warn for dislikes. Text is the value as typed.
  4. Remove button.chip__x: a 16px glyph with a 24px hit area, labelled "Remove Parks".
  5. Text input.chip-input__field: borderless, takes the rest of the row (at least 120px), so it drops to a new line before it gets cramped.

Variants

The chip tone says what the list means; the control is otherwise the same. Pick the tone from the meaning of the list, never per value.

Empty and with a hint

Places and activities the planner should leave out, like "Camping".

With no chips the control is a plain field. The placeholder is a reminder of the key, not the label; the hint carries the explanation.

Sizes

One size. The container is a 44px field that grows in height as chips wrap; chips are the 24px tag size.

States

Pointer and focus states are forced with data-state for review. In the product, the container takes its focus style from :focus-within, and the remove button from :hover (pointer devices only) and :focus-visible.

Both themes

ParksCamping
ParksCamping
  • Field focused uses the text-field focus treatment on the whole container: focus-coloured border plus a soft brand halo, so the box reads as one field while the caret sits after the last chip.
  • Remove focus uses the shared 2px focus ring around the 16px glyph. Remove hover darkens the glyph and fills its circle.
  • Error is for duplicates and conflicts. The typed text stays in the field so it can be fixed, and the message says what to do. Nothing is added silently and nothing is dropped silently.
  • Disabled and read-only are not states of this control. When the list cannot be edited, render the values as plain chips without remove buttons.

Responsive behaviour

  • Chips and the text input share one wrapping row. The input keeps at least 120px (flex: 1 1 7.5rem); when less is left it moves to its own line, so the caret never sits in a sliver.
  • Chips never truncate. A value too long for 360px, such as "Drives over 60 min", still fits; anything longer should be a shorter tag.
  • The control fills its field's width: full width in the D20 bottom sheet on phones, the wide dialog's column from 720px.
  • The remove button's hover fill applies only under (hover: hover); on touch the 24px hit area does the work.

Theming

The container reads the same alias tokens as a text field: --colorNeutralBackground1 fill, --colorNeutralStrokeAccessible border, --colorStrokeFocus2 and --colorBrandStroke2 for focus. Chips bring their own component tokens (--sd-chip-bg, --sd-chip-fg) set by the tone class, and the remove button inherits the chip's text colour.

/* A third list with its own tone: override the chip, not the container */
.chip--maybe { --sd-chip-bg: var(--colorPaletteSkyBackground1); --sd-chip-fg: var(--colorPaletteSkyForeground1); }

In the dark theme the field sits on the raised dialog surface, the leaf and warn tints darken and their text lightens, keeping each chip above 4.5:1. The remove glyph follows the chip text, so it never needs its own dark value.

Accessibility

Role and pattern

A native <input type="text"> labelled by the field label, plus one native <button> per chip. There is no ARIA widget role on the container. If suggestions are added later, the input becomes an editable combobox following the APG Combobox pattern (role="combobox", aria-expanded, aria-controls on a listbox, aria-activedescendant for the highlighted option); Enter then adds the highlighted suggestion, or the typed text when none is highlighted.

Keyboard

KeyAction
Tab / Shift+TabMoves through each chip's remove button, then the text input, in DOM order (chips come first, so Shift+Tab from the input reaches the last chip).
Enter or ,In the input: adds the trimmed text as a chip and clears the input. Enter does not submit the dialog. Empty text does nothing.
BackspaceIn an empty input: removes the last chip. With text in the input it deletes characters as normal.
Enter / SpaceOn a remove button: removes that chip and moves focus to the next chip's remove button, or to the input if it was the last.
EscNo effect on the field; it closes the dialog as usual. Leaving the field (blur) adds any typed text, so nothing typed is lost.

Focus

The text input draws no outline of its own; the container shows focus through :focus-within with the text-field treatment (focus-coloured border and 3px halo). Each remove button shows the shared 2px ring on :focus-visible. Focus never lands on a chip that was just removed: it moves to the neighbour or the input.

Labelling

The visible label ("Likes") names the input through <label for>. Each remove button is "Remove" plus the value: "Remove Short hikes", never just "Remove" or "×". Add and remove announce through a polite live region next to the field ("Zoo added to Likes", "Camping removed"), because the chip appearing is not announced by itself. Errors are linked with aria-describedby.

The remove glyph is the chip's text colour at 75% opacity at rest; it is a 10px icon inside a 24px target, and hover or focus brings it to full strength.

Motion

Chips appear and disappear without animation. The container's border and halo transition over --durationFast, zeroed under prefers-reduced-motion.

Touch

The remove glyph is 16px but its ::before extends the hit area to 24 × 24px (drift D27), clearing the 2.5.8 minimum. Neighbouring chips sit 6px apart, so the enlarged hit areas do not overlap the next chip's text. The container is 44px tall, so tapping anywhere on the empty part of the row is easy; tapping between chips focuses the input.

Content

  • Chips are short nouns or noun phrases in sentence case: "Parks", "Short hikes", "Live theatre", "Drives over 60 min". Keep the person's words; only trim spaces.
  • Placeholder says the key, not the meaning: "Add one, press Enter". The label and hint carry the meaning.
  • Duplicates are refused with a message naming the value: "Parks is already in Likes." A value in the other list says how to fix it: "Parks is in Likes. Remove it there first."
  • Remove buttons read "Remove" plus the value. Announcements read "Zoo added to Likes", "Camping removed".

The Angular component is a form control over string[]. It commits on Enter, , and blur, removes the last value on Backspace in an empty input, and renders each value as sd-chip with removable and removeLabel set to "Remove" plus the value. It trims values and drops case-insensitive duplicates silently; the duplicate message above is not built yet.
