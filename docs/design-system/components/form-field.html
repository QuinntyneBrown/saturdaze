Form field

The field is the frame around every input: a label above, the control, then one line of help or one error below. Every form in Saturdaze, from Sign in to Add an errand, is a stack of these.

Overview

Wrap every text field, textarea, select, chip input and segmented choice in .field. The wrapper owns the label, the help text and the message; the control inside owns only its own box. That keeps labels, hints and errors identical in every form. How fields stack into a whole form, with an error summary and actions, is on Forms.

  • Label (.field__label) is always visible, above the control. Placeholders never replace it.
  • Marker (.field__req) says in words that a field is "Required", "Optional" or "Recommended". Mark whichever is rarer in the form.
  • Hint (.field__hint) explains the field before anyone gets it wrong: "How we greet you."
  • Error (.field__error) replaces the hint when the value is wrong, with an alert icon and a sentence that says how to fix it.
  • Success (.field__success) confirms a check that ran as the person typed, such as matching passwords. Use it sparingly.
  • Foot (.field__foot) puts a hint and a counter (.field__counter) on one line for length-limited fields.
  • Row (.field--row) sets two short fields side by side; with button (.field__with-btn) puts a button beside the control.

Anatomy

  1. Label<label for>, Body 2 medium (13px), --colorNeutralForeground2.
  2. MarkerInside the label so it is read with it. Caption (12px), --colorNeutralForeground3, 6px after the label text.
  3. ControlAny .field__input, select, chip input or seg-radio. 6px below the label.
  4. Hint, error or successCaption (12px), 6px below the control, joined to it with aria-describedby. Only one shows at a time.
  5. Counter (optional)Right-aligned in the foot, tabular figures, --colorNeutralForeground3.

Group label

When the control is a group (seg-radio, a set of checkboxes), the label is not a <label>: use a <fieldset class="field"> with <legend class="field__label">, or a <span class="field__label" id> that the group names itself with (aria-labelledby), as D7 "Which day" does.

Sizes

One size. Fields fill the width of their column; there is no short or long field class. Inside a dialog or auth card the column is narrow enough (at most 560px) that full width reads well. Two short related values (Start and End, Cost and Ages) share a .field--row instead of shrinking a field by hand. See text field sizes for why the control is always 44px tall.

  • Invalid: the error replaces the hint (keep the hint only if it still helps), the control takes aria-invalid="true" and a danger border. Show errors after submit or when the person leaves a field they changed, never while they are still typing the first time.
  • Disabled fades the control to 50%; the label stays readable so the form still makes sense. Prefer read-only when the value matters but cannot change.
  • Read-only drops the border and fills the control with the well colour; the value can be selected and copied.

Responsive behaviour

  • Labels stay above the control at every width. Side-by-side labels would leave the phone layout with almost no room for the value.
  • .field--row keeps two columns down to 360px; only use it for values that fit in half a phone width (a time, a price, an age range).
  • Long hints and errors wrap under the control. The counter stays on the right of the first line of the foot.
  • On admin toolbars (.toolbar) the search field takes the remaining width and the sort select a fixed 240px from 720px; under 720px they stack.

Theming

The wrapper reads alias tokens for its text: --colorNeutralForeground2 (label, hint), --colorNeutralForeground3 (marker, counter), --colorStatusDangerForeground1 (error), --colorStatusSuccessForeground1 (success). The control's border is the component token --sd-field-border, which states override; set it on a scoped class to re-skin fields in one region.

In the dark theme the input stays one step lighter than the dialog it sits in, and the accessible stroke lightens so the edge still clears 3:1.

Accessibility

Role and pattern

No APG widget pattern applies: fields are native form controls with a native <label for>. Groups of radios or checkboxes use <fieldset> and <legend>, or role="radiogroup" with aria-labelledby.

Keyboard

KeyAction
Tab / Shift+TabMoves between controls in visual order; labels, hints and messages are not stops.
EnterIn a single-line field, submits the form.
Click or tap the labelFocuses the control (or toggles a checkbox), which also widens the target.

Focus

The control draws its own focus: the border turns --colorStrokeFocus2 with a 3px soft halo. On submit with errors, focus goes to the error summary at the top of the form, whose links move focus to each field (see Forms).

Labelling

  • Every control has a visible <label for>. The marker sits inside the label, so the name is read as "What is it, Required".
  • Also set required (or aria-required="true") so the requirement is exposed as state, not only as words.
  • Hint, error and success are joined with aria-describedby. When both hint and error show, list the error id first.
  • An error that appears after submit is announced through the error summary; an error that appears on blur is announced by moving it into the described-by list, not with role="alert" on every field.
  • Set autocomplete on name, email and password fields (1.3.5).

Errors never rely on the red border alone: they have an icon and a sentence (1.4.1).

Motion

Border and halo transition over --durationFast; with reduced motion the change is instant. Messages appear without animation.

Touch

Controls are 44px tall. The label is part of the target, so tapping "Password" focuses the password input.

Content

  • Labels are short nouns or questions in sentence case, no colon: "Email", "Family name", "Roughly how long", "Which day".
  • Markers are one word: "Required", "Optional" or "Recommended". Mark the minority: in D10 most fields are optional, so only Title and Starts say "Required".
  • Hints are one short sentence that helps before the mistake: "Under 18 counts as a kid." End with a full stop.
  • Errors say what to do: "Enter a name.", "This address isn't on the image allow-list." Not "Invalid input" or "Error".
  • Placeholders show an example value, never instructions: "Costco run", "Port Credit Buskerfest".
