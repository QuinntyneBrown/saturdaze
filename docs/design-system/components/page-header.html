Page header

Every screen opens with its name, one sentence on what it is for, and the actions that belong to the whole screen. Sections inside the page repeat the pattern at a smaller size.

Overview

Use one .page-header at the top of every app and admin screen, inside the container. Use .section with a .section-header for each group below it (Who's in, Locked in every weekend, Right for this weekend's weather).

  • Title and subtitle are always there. The subtitle says what the screen is for or what shaped it: "Picked for Eli and Mae, under 45 minutes from Port Credit."
  • Back eyebrow (.page-header__eyebrow) appears only on screens one level down (a place in admin Places, Review submissions under Family). It is one link back, not a breadcrumb trail; use the breadcrumb when there are more levels.
  • Actions (.page-header__actions) hold at most two buttons for the whole screen, primary first. More go in the More menu (.page-header__more).
  • The Weekend screen is the exception: its cover photo takes the header's place and .cover-actions holds the buttons. See cover photo.

Anatomy

  1. Back eyebrow (optional).page-header__eyebrow: a link with a left arrow and the parent's name, 13px label in the secondary colour.
  2. Title.page-header__title, the page's only h1, --typographyTitle1 with tight tracking.
  3. Subtitle.page-header__subtitle, --typographyBody1 in --colorNeutralForeground2, capped at the reading measure.
  4. Actions (optional).page-header__actions: primary first, then one quiet button.
  5. More (optional).page-header__more: a quiet icon button that opens a menu; top right on phones, last in the row from 720px.

Sizes

Two levels, one size each. The page header uses Title 1 (--typographyTitle1) for its h1; the section header uses Title 2 (--typographyTitle2) for its h2. There is no third level: a group inside a section is a card or a list with its own title.

Responsive behaviour

  • Under 720px the header is a two-column grid: text on the left, More pinned top right. Actions drop to a second row as a two-column grid of 44px buttons; the primary takes the whole first row, and a lone button is full width. The back eyebrow hides and a 40px back icon button sits beside the title instead.
  • From 720px it becomes one wrapping row aligned to the bottom: the text block grows (at least 20rem), then the actions at 40px, then More last. The eyebrow returns above the title.
  • The title wraps; it never truncates. The subtitle stops at the reading measure (--layoutMeasure).
  • The section header stays one row at every width: the action keeps to the right edge and the title wraps beside it.
  • Space below the page header is 24px; between sections 32px on phones and 40px from 720px (--layoutSpaceSection).

Theming

Headers sit on the page canvas (--colorNeutralBackground2) and draw no surface of their own. The title reads --colorNeutralForeground1, subtitle, eyebrow and section sub --colorNeutralForeground2; both switch with the theme. Action buttons are themed by the button's own tokens. The phone action height is a knob on the buttons (--sd-btn-h: var(--targetComfortable)), not a new size.

Accessibility

Role and pattern

No APG widget pattern. The page header is a <header> inside <main> (so it is not the banner landmark) and holds the page's single <h1>, which matches the document <title>. Each section is <section aria-labelledby="…"> pointing at its <h2>, so it becomes a named region screen-reader users can jump to. The More button follows the APG Menu Button pattern.

Keyboard

KeyAction
TabBack link, then the actions in DOM order, then More. Put the primary first in the DOM so focus order matches the phone layout, where it is drawn first (2.4.3).
EnterFollows the back link; activates an action.
Enter / Space / ↓ on MoreOpens the menu and focuses its first item; Esc closes it and returns focus to More.

Focus

Every control draws the shared 2px ring. The back link has a 24px minimum height and a small radius so its ring wraps the arrow and the text together.

Labelling

The back link's name is the parent page ("Places", "Family"); the arrow is aria-hidden. The phone back button, which has no visible text, says "Back to Family". More names its object: "More weekend options", "More place options". The back link is a real link to the parent URL, not history.back(), so it is predictable when the page was opened from a bookmark.

Motion

None of its own; buttons keep their 120ms hover transition, zeroed under prefers-reduced-motion.

Touch

Phone actions are 44px tall and at least 8px apart. The back eyebrow is at least 24px tall from 720px; on phones the 40px back button replaces it.

Content

  • Page titles are the nav label or the thing's own name: "Ideas", "Past weekends", "The Browns", "Port Credit Memorial Park". Sentence case, no full stop.
  • Subtitles are one sentence about this family or this data, with a full stop: "Picked for Eli and Mae, under 45 minutes from Port Credit." Admin subtitles say how the list is sorted: "Every catalog place, worst photo health first."
  • Section titles say what the group means to the family: "Right for this weekend's weather", "If the weather turns", "Locked in every weekend". Section subs are a short fact: "Sunny Saturday, 22°".
  • Back links are the parent's name alone; the arrow says "back".
