Component · Data display

Description list

A description list sets out the facts about one thing as label and value pairs: where a submitted event is, what it costs, who it suits; a photo's alt text, credit, licence and size. A missing fact says "Not given" rather than leaving a gap.

Overview

Use .details when three or more labelled facts describe one item and a person reads them to decide something: approve a submission, keep a photo. For one or two facts, a meta line does the job ("Sat 20 Jun · 2:00 to 9:00pm"). For many items with the same fields, use a table or a list.

  • Value (.details__value) is plain text and may run to a sentence or two (Notes).
  • Faint value (.details__value--faint) marks a fact the sender left out: "Not given".
  • Link value (.details__link) is a URL the reviewer may want to check.
  • Stacked (.details--stacked) keeps the label above the value at every width, for narrow columns such as admin photo tiles.

Anatomy

  1. Label<dt class="details__label">, --typographyBody2 in the secondary colour; a 96px column from 576px.
  2. Value<dd class="details__value">, --typographyBody1; long words break.
  3. Faint value.details__value--faint in --colorNeutralForeground3: "Not given".
  4. List<dl class="details">: a grid, 8px between rows, 12px between columns.

Responsive behaviour

  • Under 576px each label sits above its value in one column, so long values (a Notes sentence, a URL) get the full width of a phone.
  • From 576px labels take a 96px column and values the rest; the label drops 2px so its smaller text lines up with the value's first line.
  • .details--stacked keeps the phone layout at every width, for narrow containers.
  • Values wrap and break long words and URLs (overflow-wrap: anywhere); they never truncate, because a reviewer needs the whole URL.

Theming

Labels read --colorNeutralForeground2, values --colorNeutralForeground1, faint values --colorNeutralForeground3 and links --colorBrandForegroundLink. All four switch with the theme and keep 4.5:1 on the card and well surfaces they sit on. The list draws no surface of its own.

Accessibility

Role and pattern

No APG widget pattern: a native <dl> with <dt> and <dd> pairs, direct children only (no wrapping <div> per pair, so the grid can place them). Screen readers announce the list and its term count, and read each label with its value. Never fake the pairs with <p><b>Cost:</b> Free</p>.

Keyboard

KeyAction
TabStops only on link values.
EnterOpens the link in a new tab.

Focus

Link values draw the shared 2px ring with a small radius; a wrapped URL gets a ring per line fragment, which is expected.

Labelling

Labels are short nouns that name the value ("Cost", not "How much does it cost?"). A link that opens a new tab says so: visually hidden "(opens in a new tab)" plus the external icon, rather than the arrow used in the mock, which reads as "go to". The faint "Not given" is real text, so a screen-reader user hears that the value is missing rather than nothing.

Motion

None.

Touch

A link value is an inline target; it is exempt from the 24px minimum as text in a sentence-like block (2.5.8), but keep at least 8px between two link values by giving each its own row.

Content

  • Labels: one word where possible, sentence case, no colon: Location, Cost, Ages, Link, Notes; Alt text, Credit, Licence, Size.
  • Values: as the sender wrote them, trimmed. Prices and ages in the product's words: "Free", "All ages", "Ages 5+".
  • Missing: always "Not given". Never a dash, "N/A" or an empty row.
  • Links: show the URL without the protocol (example.com/port-credit-buskerfest-2026) so the reviewer sees where it goes.
  • Keep the same labels in the same order for every item of a kind, so a reviewer can scan down a queue.
