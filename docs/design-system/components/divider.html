Divider

A divider is a 1px line between two groups that nothing else separates. Saturdaze rarely needs one: list rows, cards, day headers and menus already draw their own borders.

Overview

Before adding a divider, check whether a component already separates the content. These do, and should never get an extra line:

  • List rows have a bottom border; cards have their own edge; a .day__header has a border under it; a vote row has a border above it; a menu has .menu__sep.
  • Page sections are separated by space and a heading (--layoutSpaceSection), not by lines.

A divider element is warranted in three places only:

  • Between groups of controls in one row where there is no container: the filter rows on Food and admin Places split "which day" from "which meal" from "which tags" with .filters__divider.
  • Between two unrelated blocks inside one surface with no heading of their own, such as the account details and Sign out at the foot of an account card.
  • Between two alternative ways to do one thing, labelled "or": upload a photo, or add one from a link.

Anatomy

  1. Line1px (--strokeWidthThin) in --colorNeutralStroke2; vertical dividers use the stronger --colorNeutralStroke1 because they are short.
  2. Label (optional)--typographyCaption1Strong in --colorNeutralForeground2, 12px gap to each line.
  3. Space16px above and below a horizontal divider (--spacingVerticalL); 2px each side of a vertical one, plus the row's own gap.

Sizes

One weight (1px) and one length rule: horizontal dividers fill their container, vertical ones are 20px tall.

States

Dividers are not interactive, so they have no hover, focus or disabled state. What changes is the surface they sit on; the line must stay visible on each.

Responsive behaviour

  • Horizontal and labelled dividers fill their container at every width.
  • Vertical dividers travel with the chips. On phones the filter row is a horizontal scroller (.scroller-x), so the divider never wraps to the start of a line; from 720px the row wraps, and a divider that lands at the start of a line is acceptable because the group still reads left to right.
  • Never use a vertical divider to fake columns; use the grid, which stacks on phones.

Theming

Dividers read --colorNeutralStroke2 (horizontal and labelled lines) and --colorNeutralStroke1 (vertical), both of which lighten in the dark theme so the line stays as faint as in light. The label reads --colorNeutralForeground2. The mocks drew the filter divider in --sd-line-strong; it now uses the stroke tokens like every other line.

Accessibility

Role and pattern

No APG widget pattern: a divider is a static separator, never focusable (a focusable separator is the Window Splitter pattern, which Saturdaze does not use). A meaningful horizontal break is a native <hr>, which has the separator role already. A meaningful vertical break is <span class="divider--vertical" role="separator" aria-orientation="vertical">. A purely visual break, like the filter dividers, is aria-hidden="true".

Keyboard

KeyAction
TabSkips the divider; it is never a tab stop.

Focus

Not focusable. A divider must not sit so close to a control that it clips the control's 2px focus ring; vertical dividers keep 2px plus the row gap on each side.

Labelling

The "or" label is real text and is read as "or" between the two alternatives. Do not put role="separator" on a labelled divider: a separator's content is not read. When the groups a vertical divider separates matter (single-choice day filters), say so in the markup with nested role="group" aria-label="Day"; the hidden line cannot.

Contrast

"or" label on page

The lines themselves are decorative: removing them loses no information, because headings, spacing or the "or" label carry the structure. They are exempt from the 3:1 non-text minimum, and they should be: a strong line competes with content.

Motion

None.

Touch

Not a target. A vertical divider adds 2px each side so chips either side keep at least 8px between their edges.

Content

  • The only label is "or", lower case. If the two sides need more explanation than "or", give each its own heading instead.
  • Never label a divider with a section name ("Preferences"); that is a heading.

Sources

The only divider element in the mocks is .filters__divider, in the filter rows of pages/ideas.food, pages/ideas.events and pages/admin.places.
