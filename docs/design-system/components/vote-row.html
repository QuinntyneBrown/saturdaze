Vote row

The vote row sits at the bottom of a food idea and lets each person in the family say yes or no to it. It answers "where do we all want to eat?" without anyone opening a dialog.

WCAG 2.2 AAStatus: stableAngular: sd-vote-rowNative <button aria-pressed>

Overview

Use the vote row when the whole family weighs in on one idea and the answer is yes, no or not yet. Each person gets one cell: their avatar, their name and two toggle buttons. A vote is per person, so it never collapses into a single count.

  • Use it on food idea cards (Ideas → Food), where the parents pick lunch near the planned activity and the kids get a say.
  • Do not use it for a single person's opinion: a favourite is a pressed icon button (the heart on Past), and a weekend's score is a rating.
  • Do not use it as a filter. Narrowing a list is a filter chip.

The vote row only records opinions. Locking an idea into the weekend is still the card's "Lock it in" button, which opens a confirmation.

Anatomy

  1. Group.vote-row, role="group" with aria-label="Family vote for La Marina". Four equal columns, a 1px divider above.
  2. Avatar28px avatar in the person's tone, aria-hidden="true"; the name carries the meaning.
  3. Name.vote-row__name, 12px caption, truncates with an ellipsis rather than wrapping.
  4. Yes and no buttons.vote-row__btn--up and --down, 28px circles, 4px apart, each a toggle with aria-pressed.
  5. Cell.vote-row__cell, one per family member, in family order (parents first, then kids by age).

Sizes

One size. The buttons are 28px circles so four people fit across a 360px card; a larger row would wrap.

  • Not voted: both buttons are outlined, neither is pressed. This is the start state for every person.
  • Yes or No: the pressed button fills with the success or danger tint, its icon fills, and its border takes the ink colour so "on" never depends on a pale fill alone (the same rule as D26 for filter chips).
  • Changing a vote: pressing the other button moves the vote. Pressing the pressed button again clears it back to not voted.
  • Disabled keeps any recorded vote visible at 50% opacity and takes the buttons out of the tab order.

Responsive behaviour

  • The row is a four-column grid of equal cells (repeat(4, minmax(0, 1fr))) at every width. At 360px each cell is about 70px wide, enough for the 60px button pair.
  • Names truncate with an ellipsis rather than wrap, so every cell keeps the same height. The full name is still in each button's label.
  • The cards it sits in go from one column on phones to two from 720px (.grid-cards) and three from 1024px; the row itself does not change.
  • A family of five or more needs another column count. Set grid-template-columns from the member count in the component rather than letting a fifth cell wrap onto its own line.
  • Hover only applies under (hover: hover), so a tap never leaves a sticky outline.

Theming

The vote row reads alias tokens only. "Yes" uses the success role (forest), "No" the danger role (terracotta), and the outlined resting button uses the accessible neutral stroke, so it stays visible on the white card and on the cream canvas. There are no component tokens; the pressed colours come straight from the status roles so a theme change reaches them.

In the dark theme the tints darken, the inks lighten, and the button fill becomes the raised umber card colour. The pressed border keeps its ink colour, so the pressed button reads by its edge and filled icon as well as its tint.

/* Re-skin for a theme: change the alias roles, never .vote-row__btn */
[data-theme="dark"] { --colorStatusSuccessBackground1: …; --colorStatusSuccessForeground1: …; }

Accessibility

Role and pattern

Each vote is a native <button type="button"> toggle with aria-pressed, following the APG Button pattern (toggle button). The row is a role="group" named after the idea. It is deliberately not a radio group: a person can have no vote at all, and clearing a vote by pressing it again is part of the design.

Keyboard

KeyAction
Tab / Shift+TabMoves through the buttons in reading order: Quinn yes, Quinn no, Sara yes, and so on.
Enter / SpaceToggles the focused button. If the other button in the cell was pressed, it is released.

Focus

The shared ring (2px --colorStrokeFocus2, 2px offset) appears on :focus-visible. The offset gap keeps it apart from the button's own border and from the neighbouring button 4px away. After a press focus stays on the button so a person can change their mind straight away.

Labelling

Every button is named for the person and the choice: "Mae votes yes", "Mae votes no". The pressed state is announced by aria-pressed ("Mae votes yes, toggle button, pressed"), so the label never changes with the state. The group label names the idea ("Family vote for La Marina"), which matters when a screen reader user tabs in from the card above. Avatars are hidden; the visible name is enough.

Motion

Fill and icon colour change over --durationFast (120ms). Nothing moves or scales. Under prefers-reduced-motion the duration token is zeroed and the change is instant.

Touch

The buttons are 28px, above the 24px minimum (2.5.8), with 4px between the yes and no of one person and at least 8px to the next person. They are smaller than the 44px comfortable target on purpose so four people fit across a phone card; a mistaken tap is harmless and undone with one more tap.

Content

  • Button labels follow one pattern: "<Name> votes yes" and "<Name> votes no", using the first name the family entered ("Mae votes yes"). This is the copy in the mocks and in sd-vote-row.
  • The group label is "Family vote for <place>", using the place name as the card title shows it.
  • Visible names are first names only. Do not add the role ("Parent", "Kid") or the age; the Family page carries those.
  • No tally text inside the row ("3 of 4 yes"). If the card needs a summary, put it in a chip on the card ("Top pick").
  • When the row is closed, say why on the card ("Dinner is locked in at Jack Astor's"), because disabled buttons cannot explain themselves.
