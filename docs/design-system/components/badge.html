Badge

A badge says where something stands or how many are waiting: "Pending", "Approved", "3" submissions to review. It is read, never pressed, and its words carry the meaning on their own.

Overview

Badges are built from the chip classes. A chip describes a thing ("Outdoor", "45 min drive"); a badge reports a state or a number that changes as people act. Use a badge for:

  • Counts (.chip--count): how many items wait behind a link. "3" submissions on Family › Review submissions, "4 without a photo" on the admin Photo health cards.
  • Status: where a submission, photo or import run stands. Pending (.chip--caution), Approved (.chip--accent), Rejected (.chip--warn), Info (.chip--info) for neutral notes such as "Provider".
  • Tag (.tag): a small uppercase label that marks a whole area, today only "Admin" beside the brand in the admin navigation.

Do not use a badge to filter (use a filter chip) or to explain a problem (use an inline message or alert; the badge can only name the state).

Anatomy

  1. Icon (optional)13px, currentColor, aria-hidden="true". It repeats the word, so it never replaces it.
  2. Label or number--typographyCaption1Strong (12px semibold); counts use tabular figures so "9" and "10" keep their width.
  3. ContainerPill, 24px tall (--targetMin), tinted fill from the tone. Counts are at least 24px wide so a single digit sits in a circle.

Variants

Status

Four tones, one meaning each. Status uses the status palette, never a weather tone: sun means sunny, not "waiting".

Sizes

Default (24px) everywhere a badge sits in a row or card head. Small (20px, .chip--sm) for tight places such as photo tiles with three badges side by side. The tag is always 20px. Text stays 12px at both sizes (drift D12 removed the 11px small chip).

States

A badge has no interactive states of its own. It inherits the state of the row or link that holds it: the row tints on hover, the focus ring wraps the whole link, and the badge keeps its own colours inside. Pointer and focus states are forced here with data-state on the parent link.

  • Zero: on the Photo health cards a zero count stays visible ("0 missing alt text" is good news worth seeing). On Family the Review submissions row hides its count at zero and the sub-line says "Nothing waiting".
  • Changed: when a count changes because of something the person did (approving a submission), announce the result in a role="status" live region ("Approved · Bronte Creek Maple Magic"), not by making the badge itself live.

Responsive behaviour

  • Badges never wrap or truncate (white-space: nowrap, flex: none). The title beside them wraps instead, so labels must stay one or two words.
  • In a card head (.card__head > .chip) the status sits top-right at every width; at 360px the title wraps under it rather than pushing it off the card.
  • In the admin navigation the count follows the link label under 1024px and moves to the right edge of the sidebar row from 1024px (.admin-nav__link .chip--count).
  • On the stacked activity feed the action chip sits in the top-right corner of each row; from 1024px it takes its own column.

Theming

Every badge reads two component tokens, --sd-chip-bg and --sd-chip-fg, which each tone class maps to a status or palette alias (--colorStatusWarningBackground1 / --colorStatusWarningForeground1 for caution, and so on). The tag reads the brand tint directly. A theme changes the aliases; nothing in .chip changes.

/* A count on the inverted toast surface */
.toast .chip--count { --sd-chip-bg: var(--colorNeutralBackground1); --sd-chip-fg: var(--colorNeutralForeground1); }

In the dark theme the tints become deep, low-saturation fills and the labels lighten, so each status keeps at least 4.5:1 and stays distinct from the others by hue and by word.

Accessibility

Role and pattern

A <span> of plain text with no role; no WAI-ARIA APG pattern applies. Screen readers read it in document order as part of the row or link around it, so put it where it makes sense in the sentence: "Review submissions, 3 waiting for review". Do not add role="status" to a badge; announce changes through a separate live region.

Keyboard

KeyAction
TabSkips the badge. Focus lands on the link or row that contains it, which reads the badge as part of its name.

Focus

The badge never takes focus. The parent's ring (2px --colorStrokeFocus2, 2px offset) surrounds the whole row including the badge.

Labelling

The text is the label. A bare number gets its meaning from words beside it ("4 without a photo") or from visually hidden text inside the badge (3<span class="visually-hidden"> waiting for review</span>). Never rely on title, and never on colour alone: "Pending" and "Rejected" say the state in words, and icons inside badges are aria-hidden="true".

Motion

None. A badge appears and changes instantly; it does not pulse, bounce or count up.

Touch

Not a target. The link or row around it supplies the target (at least 40px tall for .stat__link, 56px for list rows).

Content

  • One word, sentence case, a state rather than an action: "Pending", "Approved", "Rejected", "Failed", "Succeeded", "Unreviewed".
  • Use the same word for the same state on every screen. A submission is "Pending" on Review submissions and on Ideas › Events (the mocks say "Pending review" there; shorten it).
  • Counts are digits only. Above 99 show "99+" and put the full number in the hidden text.
  • The tag names an area in one word ("Admin"); it is uppercase by style, typed in sentence case.
