Chip

Chips are the small tags on cards and timeline blocks: "45 min drive", "Outdoor", "Commitment", "Day highlight". Each tone has one meaning across the product, so a family learns to read a card at a glance.

Overview

A chip is a static label. It describes something already decided: how far away a place is, whether it is indoors, that a block is locked. It is not a control. When people choose chips to narrow a list, use a filter chip; when they build a set (likes and dislikes), use a chip input, whose chips carry the removable form shown below; when the chip reports a state or a number, it is a badge.

Tones have fixed meanings. Pick the tone from the meaning, never for variety:

Anatomy

  1. Leading icon (optional)13px, stroke 2, currentColor, aria-hidden="true"; 4px gap.
  2. Label--typographyCaption1Strong (12px semibold), one line, never truncated.
  3. Remove button (chip input only).chip__x: 16px glyph, 24px hit area through ::before (drift D27), aria-label="Remove Parks".
  4. ContainerPill, 24px tall (--targetMin), 10px side padding, fill and label colour from the tone.

Email chip

.email-chip sets an email address apart inside a sentence so it reads as one unit and can break anywhere on a phone. It is 14px, not 12px, because the address is the content.

Sizes

Default (24px) on cards, blocks and in chip inputs. Small (20px, .chip--sm) where three or more chips share a narrow row, such as admin photo tiles. Both use 12px text.

  • Removed: the chip disappears at once, focus moves to the next chip's remove button (or the text field when it was the last), and a polite live region says "Parks removed".
  • Disabled does not exist. A read-only set shows static chips without remove buttons.

Responsive behaviour

  • Chips never wrap their text or truncate. Their container wraps them onto the next line: .card__chips and .block__chips are wrapping flex rows with a 6px gap.
  • Keep a card to two or three chips so the row stays one line at 360px; a fourth chip belongs in the card body text.
  • An email chip is the exception: it may break inside the address (overflow-wrap: anywhere) because long addresses would otherwise overflow a 360px auth card.
  • Chip size does not change with the viewport.

Theming

The chip reads two component tokens, --sd-chip-bg and --sd-chip-fg. Each tone maps them to a palette pair (--colorPaletteSunBackground1 / --colorPaletteSunForeground1) or a status pair. A theme changes the palette aliases; a local re-skin overrides the two component tokens.

/* A neutral chip sitting on a sunk well instead of a card */
.card--sunk .chip:not([class*="chip--"]) { --sd-chip-bg: var(--colorNeutralBackground1); }

In the dark theme the palette fills become deep tints of the same hue and the labels lighten to the 300 to 100 steps, so every tone still reads as its colour and passes 4.5:1.

Accessibility

Role and pattern

A static chip is a <span> of text with no role, read in order with its card. No WAI-ARIA APG pattern applies. A group of chips that describe one card can sit in a plain <div class="card__chips">; it needs no list semantics. The remove button is a native <button type="button">.

Keyboard

KeyAction
TabSkips static chips. Moves to each remove button in a chip input, then to the text field.
Enter / SpaceOn a remove button: removes that chip and moves focus to the next remove button or the field.
BackspaceIn an empty chip-input field: removes the last chip (see chip input).

Focus

The remove button shows the shared ring (2px --colorStrokeFocus2, 2px offset) around its 16px circle on :focus-visible. Static chips never take focus.

Labelling

The chip text is the content; write it so it makes sense read aloud without the icon or colour. "45 min" beside a car icon is heard as just "45 min", so write "45 min drive" (or add <span class="visually-hidden"> drive</span>). Remove buttons name the chip: aria-label="Remove Parks", never just "Remove" or "×".

Motion

None on the chip. The remove button's hover tint is instant. Removing a chip does not animate it out, so focus never lands on something that is leaving.

Touch

Static chips are not targets. The remove glyph is 16px, but .chip__x::before extends the hit area to 24 × 24px (WCAG 2.5.8, drift D27). Chips in a chip input sit 6px apart, so neighbouring hit areas do not overlap the next chip's label by more than its padding.

Content

  • One to three words, sentence case, no full stop: "Outdoor", "Day highlight", "All ages".
  • Numbers with units: "45 min drive", "Sunny · 22°". Use the middle dot to join two facts.
  • Say what the family gets, not internal categories: "Weather-safe", not "Indoor-capable".
  • Likes and dislikes are nouns the family typed; keep their wording and casing ("Rec Room", "Live theatre").
