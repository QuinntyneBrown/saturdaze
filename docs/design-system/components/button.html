Button

Buttons let a family member do something: plan the weekend, lock a block, save a change, remove a member. One primary button per view says what matters most.

Overview

Use a button when activating it changes something: it plans, saves, locks, shares, removes or opens a dialog. Use a link when it only takes the person somewhere. Use a menu when one trigger offers several actions (the Weekend "More" button).

  • Primary (.btn--primary) is the one action the view exists for: "Plan this weekend", "Save", "Add to Sunday". Never two per view.
  • Quiet (.btn--quiet) is the default for every other action: Cancel, Share, Regenerate, Change photo. It is the most-used variant in the mocks (79 uses).
  • Ghost (.btn--ghost) sits inside dense surfaces: dialog close buttons, day-header actions, timeline block actions, icon toolbars.
  • Danger (.btn--danger) confirms a destructive action and only appears inside a confirmation dialog (D21 Remove member, D24 Reject, AD5 Remove photo).
  • Warn text (.btn--quiet.btn--warn-text) is the entry point to a destructive flow: "Remove", "Sign out". It opens the confirmation; it never destroys on its own.
  • Text (.btn--text) looks like a link but acts; reserve it for low-emphasis actions inside a sentence or a card footer.

Anatomy

  1. Leading icon (optional)18px (16px in small), currentColor, aria-hidden="true"; 8px gap to the label.
  2. LabelVerb phrase in sentence case, --typographyLabel (14px semibold). It is the accessible name.
  3. ContainerPill (--borderRadiusCircular), height from --controlHeight*, 1px border, horizontal padding 12 / 16 / 24px.

Variants

Variants change emphasis, not meaning. Pick by how much attention the action deserves on this view, from left to right.

Primary, quiet, ghost, text, warn text (opens a confirmation), danger (inside the confirmation).

With icons, icon-only and block

Icon-only buttons carry aria-label (and a tooltip on pointer devices); toggles add aria-pressed.

Sizes

Medium is the default. Small lives in rows, card footers, day headers and dialog close buttons; large is for auth screens and the landing hero where the button is the whole point. Phone page actions and dialog footers stretch medium buttons to the 44px comfortable target.

Heights --controlHeightSmall/Medium/Large; padding --spacingHorizontalM/L/XXL; label 13 / 14 / 15px.

States

Every variant has the same states. Pointer and focus states are forced here with data-state so they can be reviewed without a mouse; real pages get them from :hover (pointer devices only), :focus-visible, :active, disabled and aria-busy.

Pressed and expanded

Favourite toggle (Past) off and on; menu trigger closed and open.

Both themes

  • Loading keeps the button's width, hides the label, shows a spinner in the label colour, sets aria-busy="true" and ignores further clicks. Use it on the button that was pressed ("Save" in D17), not on the whole dialog.
  • Disabled uses the native attribute: not focusable, 50% opacity. Prefer leaving Save enabled and explaining what is missing on submit; a disabled button cannot say why.
  • Pressed (aria-pressed) turns the icon brand-coloured and filled. Expanded (aria-expanded="true") keeps the hover tint while its menu is open.

Responsive behaviour

  • Page header (under 720px): actions become a two-column grid at 44px tall, and the primary button takes the full first row. From 720px they sit in one row at 40px, primary first. See page header.
  • Dialog footer (under 720px): every button is full width and 44px; primary or danger moves to the top so it sits under the thumb. From 720px they right-align in one row, primary last, and a warn-text action moves to the far left (.dialog__actions-left).
  • Day header buttons are icon-only under 720px (.day__btn-label hidden) and show their label from 720px.
  • Labels never truncate and never wrap. A label that does not fit at 360px is too long: shorten the verb phrase.
  • Hover lift and tint apply only under (hover: hover), so a tap on a phone never leaves a sticky hover state.

Theming

The button reads only alias tokens, mapped into component tokens (--sd-btn-bg, --sd-btn-fg, --sd-btn-border, --sd-btn-bg-hover, --sd-btn-fg-hover, --sd-btn-bg-active, --sd-btn-h, --sd-btn-px) that each variant and size overrides. A theme changes alias tokens; a local re-skin overrides component tokens; neither edits .btn.

/* A button floating on a photo (the cover's "Change photo") */
.cover__edit { --sd-btn-bg: var(--colorNeutralBackgroundAlpha); --sd-btn-bg-hover: var(--colorNeutralBackground1); }

In the dark theme the brand fill lightens to coral 300 and the label flips to near-black coral 950 (--colorNeutralForegroundOnBrand), keeping the pair above 7:1. Danger does the same with the terracotta ramp. Quiet buttons sit on the dark surface with the lighter accessible stroke.

Accessibility

Role and pattern

Native <button type="button">, or type="submit" inside a form. Navigation styled as a button stays an <a href> (the mocks do this for "Plan this weekend" on the landing page); never a <div> with a click handler. Toggles follow the APG Button pattern with aria-pressed; menu triggers follow the Menu Button pattern.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order.
EnterActivates the button.
SpaceActivates on key up, so a mis-press can be cancelled by moving focus away first.
EscNo effect on the button. A menu trigger's open menu closes and focus returns to the trigger.

Focus

The shared ring (2px --colorStrokeFocus2, 2px offset) appears on :focus-visible only, so taps and clicks do not show it. The coral-deep ring is a different colour from the brand fill, and the offset gap shows the surface, so it reads against both the button and the page.

Labelling

The visible label is the accessible name. Icon-only buttons set aria-label with the verb and the object when it is ambiguous: "Close", "More weekend options", "Swap Lavender fields". Loading buttons keep their name and add aria-busy="true"; progress text ("Saving…") goes to a live region, not into the button.

Motion

Background, colour, border and shadow transition over --durationFast (120ms); primary, quiet and danger lift 1px on hover. Under prefers-reduced-motion the token durations are zeroed, so the change is instant. The loading spinner keeps turning: it is a status indicator, not decoration.

Touch

Medium (40px) and large (48px) clear the 24px minimum; phone page actions and dialog footers stretch to 44px. Small buttons (32px) appear only in rows and dialog headers, with at least 4px between neighbours, and still exceed 24px.

Content

  • Verb first, sentence case, no full stop: "Plan this weekend", "Lock it in", "Add to Sunday", "Send reset link".
  • Name the object when context does not: "Remove Mae" in the confirmation, "Remove" on the member's edit dialog.
  • Destructive confirmations name the loss: "Remove Swim lessons", "Reject suggestion". Never "OK" or "Yes".
  • Cancel is always "Cancel". After a success dialog the dismiss is "Done".
  • Two or three words. If it wraps at 360px it is too long.
