Component · Navigation

Bottom nav

On phones the family moves between Weekend, Ideas, Past and Family with a floating bar under the thumb. It stays visible while the page scrolls and clears Safari's toolbar and the home indicator in every state.

Overview

The bottom nav is the phone form of the app's primary navigation. It appears on the five signed-in screens below 720px and carries exactly the four links of the top bar, in the same order, with the same labels. From 720px it is hidden and the top bar takes over, so a page never shows both.

  • Use it only in the app shell (ADR-009). Public pages use the site bar; auth screens have no navigation; Admin has its own sidebar navigation and ADR-005 does not apply there (ADR-014).
  • It is navigation, not a toolbar: every item is a link to a screen. Actions such as "Plan this weekend" belong in the page header.
  • Switching between views inside one screen (Saturday and Sunday, Activities and Food) uses tabs, never the bottom nav.

Anatomy

  1. BarA floating pill, 60px tall (--layoutBottomNavHeight), at most 440px wide, 12px from each side; raised surface, 1px --colorNeutralStroke2 edge, --shadow28.
  2. Icon pill.bottom-nav__icon: 36 × 24px, holds a 20px outline icon. Tinted only for the current item and on hover.
  3. Label12px semibold (--typographyCaption1Strong), always visible, never truncated. The label is the link's accessible name.
  4. Item.bottom-nav__item: a link filling a quarter of the bar, icon over label with a 4px gap; the whole cell is the target.

Variants

One variant: four destinations, one current. The examples use .bottom-nav--static, a documentation modifier that puts the bar in the flow and keeps it visible above 720px.

Both themes

WeekendIdeasPastFamily
WeekendIdeasPastFamily
  • Current has three cues: the darker label, the coral icon (--colorBrandForeground1) and the tinted pill. Never colour alone.
  • Hover tints the icon pill. It only happens on devices that can hover, which at this width is rare (a narrow desktop window).
  • No disabled, loading or badge states. A destination is always reachable; counts live on the page they describe.

Responsive behaviour

  • Under 720px: fixed to the bottom of the viewport, 12px in from each side, centred and capped at 440px so it stays a thumb-sized pill on large phones and small tablets.
  • From 720px: display: none; the top bar shows instead. A landscape phone wider than 720px gets the top bar.
  • Page padding: .app-main reserves the nav height, its 12px offset, 24px of breathing room and env(safe-area-inset-bottom) at the bottom, so the last card or button is never hidden behind the nav.
  • At 320px each item is about 74px wide; "Weekend" at 12px still fits without truncating.

Clearing the iOS chrome (ADR-005)

Two things can cover the bottom of an iPhone screen: Safari's toolbar, which grows and shrinks as the page scrolls, and the home indicator. They overlap rather than stack, so the bar clears whichever is larger, plus a 12px floor:

.bottom-nav {
  /* ADR-005: clear whichever bottom obstruction is present (not additive). */
  bottom: calc(var(--spacingVerticalM)
               + max(env(safe-area-inset-bottom, 0px), var(--sd-chrome-bottom, 0px)));
}

--sd-chrome-bottom is written by a VisualViewport listener that runs before the app starts (trackBottomChrome() in main.ts; the mocks' app.js does the same). The viewport meta must keep viewport-fit=cover. No CSS unit isolates the bottom chrome, which is why this is JavaScript.

Theming

The bar reads alias tokens only: --colorNeutralBackgroundRaised for the surface, --colorNeutralStroke2 for its edge, --shadow28 to lift it off the content, --colorNeutralForeground2 for labels, and the brand pair --colorBrandBackground2 / --colorBrandForeground1 for the current icon pill. It has no component tokens; there is nothing to re-skin locally.

In the dark theme the raised surface is umber 800 over the umber 900 canvas, so the bar still reads as a layer; the current pill becomes a deep coral tint with a coral 300 icon.

Accessibility

Role and pattern

A <nav aria-label="Primary"> landmark holding four plain links; the same label as the top bar, because only one of them exists at a time. It is not an ARIA tablist: each item loads a different screen. See APG landmark regions. In the DOM it comes after <main>, so the skip link and reading order reach the page content first; screen reader users jump to it through the landmarks list.

Keyboard

KeyAction
Tab / Shift+TabMoves through the four items after the page content.
EnterFollows the link.

Focus

The shared 2px --colorStrokeFocus2 ring follows the item's pill shape with a 2px offset. Because the bar is fixed over the content, a focused field or button near the bottom of the page could sit behind it (2.4.11 Focus Not Obscured); the .app-main bottom padding and scroll-padding-bottom equal to the same reserve keep focused content above the bar.

Labelling

Labels are always shown; icons are aria-hidden="true", so each link's name is its label ("Weekend"). The current item carries aria-current="page".

Motion

Only the icon pill's background transitions (--durationFast). The bar itself never animates on scroll; its only movement is the ADR-005 offset following Safari's toolbar, which is the browser moving, not an animation.

Touch

Each item is at least 74 × 60px at 320px wide, well above the 24px minimum (2.5.8) and the 44px comfortable size. The bar's 12px floor keeps it off the screen edge, where iOS reserves the home gesture.

Content

  • One word per label, identical to the top bar link and the page title: Weekend, Ideas, Past, Family.
  • Each label has one fixed icon (home, sparkle, star, user). Never swap an icon to show state; the current pill does that.
  • Four items, always. A fifth does not fit a thumb-width cell at 320px and breaks parity with the top bar.
