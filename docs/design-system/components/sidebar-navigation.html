Sidebar navigation

Saturdaze Admin is a curator's tool, used a few hours a week on a laptop. Its navigation is a side column from 1024px and folds into a top bar on smaller screens, with the same five destinations in both.

Overview

The admin navigation (.admin-nav) is the only navigation in the separate Admin application (ADR-014). It holds the brand with an "Admin" tag, five destinations (Photo health, Places, Review queue, Ingestion skips, Activity log) and the signed-in administrator with "Sign out".

  • Use it only in the Admin app. The family app uses the top bar and bottom nav; ADR-005's bottom-chrome rule does not apply here.
  • Destinations are screens. Filters within a screen (All kinds, Activities, Restaurants) are filter chips; moving back from a place to the list is the page header's back link (see breadcrumb).
  • It is flat: no groups, no nesting, no collapsing. Five links do not need them.

Anatomy

  1. Brand.admin-nav__brand: brand mark and "Saturdaze" (.admin-nav__brand-text, hidden under 720px); links to Photo health.
  2. Admin tag.tag: 12px uppercase on the coral tint, so nobody mistakes Admin for the family app.
  3. Link.admin-nav__link: 18px icon (sidebar only) and a 14px semibold label, 40px tall, 8px radius.
  4. Current linkaria-current="page": a --colorNeutralBackground3 fill, a coral icon and a 3px coral inside edge in the sidebar; a 2px coral underline in the bar.
  5. Count badge (optional).chip--count pushed to the end of the link: how many items wait on that screen.
  6. Account block.admin-nav__account: small avatar, .admin-nav__email (sidebar only) and a ghost "Sign out" button, pinned to the bottom of the sidebar above a 1px rule.

Variants

Sidebar (1024px and up)

A 240px column (--layoutSidebarWidth) the full height of the window, with a 1px right edge; the page sits beside it. The example uses .admin--sidebar, the documentation modifier that shows the sidebar form at any width.

Bar (under 1024px)

The same markup becomes a sticky 64px bar with a bottom edge: brand, links in a horizontal row without icons, account at the end. Current is a 2px coral underline, like the family top bar. The frame below is the mock page itself at tablet width, so its media queries apply.

Mock, 768px: the row already overflows. "Ingestion skips" is cut off and "Activity log" is out of view, with no scrollbar to say so. Under 720px the brand text and "Sign out" hide and more links scroll away.

Sizes

One size. The sidebar is 240px wide (--layoutSidebarWidth); the bar is 64px tall (--layoutTopBarHeight).

States

Sidebar links, forced with data-state; current is the real aria-current="page". The bar form has the same hover and focus, and shows current as an underline instead of a fill.

  • Current in the sidebar is a filled row and a darker label; in the bar it is the underline and a darker label. In the sidebar the current fill (--colorNeutralBackground3) and the hover fill (--colorSubtleBackgroundHover) resolve to the same colour in both themes, so a hovered link looks current. So the current row also gets a coral icon (--colorBrandForeground1) and a 3px coral inside edge (--colorBrandStroke1) on its left.
  • Count appears only when something is waiting. Zero is no badge, not "0".
  • No disabled links. An administrator without access never reaches Admin: the gate (sd-admin-gate) shows a screen instead of the shell.

  • The hidden scrollbar under 720px hides the fact that links continue off screen. The product should scroll the current link into view on load, so the screen the curator is on is never the one cut off.
  • Admin is desktop-first (ADR-014). The phone bar exists so a curator can check a place from a phone, not for daily work.

Theming

The navigation reads alias tokens only: --colorNeutralBackground1 for its surface (a card-white column beside the cream canvas), --colorNeutralStroke2 for the dividing edges, --colorNeutralForeground2 / --colorNeutralForeground1 for links, --colorNeutralBackground3 for the current fill, --colorBrandStroke1 for the bar's underline and the brand tint pair for the Admin tag. There are no component tokens.

In the dark theme the column is umber 850 against the umber 900 page, the current fill is umber 750, and the tag becomes a deep coral tint with light coral text. Admin ships the same token stylesheet as the family app (ADR-014 §6).

Accessibility

Role and pattern

A <nav aria-label="Admin"> landmark with plain links, the brand link first and the account block last. It is not a tree or a menu; Tab moves through it. See APG landmark regions. The page content follows in <main id="main">, which the skip link targets.

Keyboard

KeyAction
Tab / Shift+TabSkip link, brand, the five links, "Sign out", then the page. In the bar under 720px, focusing an off-screen link scrolls the row to it.
EnterFollows the link; activates "Sign out".

Focus

Shared 2px --colorStrokeFocus2 ring with a 2px offset on each link. In the bar the links sit in a scroll container; the ring is drawn outside the link, so the row keeps 2px of block padding to avoid clipping it. In the sidebar the ring sits inside the 16px column padding.

Labelling

The landmark is "Admin", which also tells a screen reader user they are not in the family app. Icons are decorative. A count adds hidden context, so the link reads "Review queue 3 waiting" rather than "Review queue 3". The avatar is aria-hidden: the email next to it is the visible identity. "Sign out" is a link to the sign-in screen in the mock; in the product it is a button that ends the session.

Motion

Link background and colour transition over --durationFast; nothing else moves. Reduced motion zeroes the duration.

Touch

Links are 40px tall in both forms (44px rows with the sidebar's 10px padding), above the 24px minimum. "Sign out" is a 32px small button with space around it.

Content

  • Labels name the screen, in sentence case, one or two words: "Photo health", "Places", "Review queue", "Ingestion skips", "Activity log". The page title matches the label.
  • Order follows the curator's week: what needs attention (Photo health), the catalog (Places), then queues and history.
  • The tag always says "Admin"; never the administrator's role.
  • Counts are whole numbers; above 99 show "99+" and put the exact number on the page.
