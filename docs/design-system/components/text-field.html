Text field

A text field takes one line of typing: an email, a family member's name, an errand, a start time. It is a native <input> with the right type and autocomplete, so phones show the right keyboard and password managers fill it.

Overview

Use a text field for a short value someone types. Always put it in a form field wrapper for its label and messages. Use a textarea for more than one sentence, a select to pick from a fixed list of more than four options, a radio group or seg-radio for two to four, and a chip input for a list of tags.

  • Pick the type for the value: email, password, number, search, time, datetime-local, url. The type sets the phone keyboard and the browser's checks.
  • Set autocomplete on anything about the person: email, current-password, new-password, name. Use autocomplete="off" only for values a browser could not know, such as the family name.
  • The copy field (.copy-field) is not an input: it shows a value to copy, such as the share link.

Anatomy

  1. Container44px tall (--targetComfortable), 1px --sd-field-border, 8px radius (--borderRadiusMedium), card background.
  2. Leading icon (search only)16px magnifier drawn as a background image 12px from the left; text starts 36px in.
  3. Value or placeholderBody 1 (15px), --colorNeutralForeground1; placeholder --colorNeutralForeground3. 12px side padding.

Variants

Variants are input types. They share one look; the type changes the keyboard, the browser's own controls and validation.

Password with show and strength

The show button sits beside the input in .field__with-btn. It is a toggle (aria-pressed) that switches the input between type="password" and type="text"; its name stays "Show password" in both states. Sizes

One height: 44px (--targetComfortable), everywhere, including the admin toolbars. Why one size:

  • Most forms live in dialogs that become bottom sheets on phones. 44px is the comfortable touch target, and a field is tapped, not clicked.
  • Fields sit next to buttons (.field__with-btn, .copy-field). One height means the button can match it exactly.
  • The forms are short (two to six fields), so there is no density to win by shrinking. Admin screens use the same height so the two products feel like one.

Width is set by the column, not the field (see form field). Known issue: field text is 15px (--fontSizeBase400), and iOS Safari zooms the page when a field under 16px takes focus. A 16px minimum for touch devices is proposed in the CSS requests.

States

Hover and focus are forced with data-state; the rest use real attributes. Hover only darkens the border, and only on devices with a pointer.

  • Focus: the border turns --colorStrokeFocus2, doubled by an inset 1px line, with a 3px --colorBrandStroke2 halo outside. It replaces the shared outline so the ring follows the 8px corners.
  • Invalid (aria-invalid="true"): danger border; focused, the halo turns danger too. Always pair with a .field__error message.
  • Disabled: 50% opacity, not focusable, not submitted. Use it only while something else must happen first, and say what in the hint.
  • Read-only: no border, well fill, still focusable and copyable, still submitted. Use it for values that are shown for reference (the place's address on an admin photo).

Responsive behaviour

  • Fields are full width of their column at every breakpoint; the height does not change.
  • Phones show the keyboard for the type: email shows @, number and inputmode="numeric" show digits, URL shows a .com key, search shows a Go or Search key.
  • Time and date-time open the platform picker on phones (a wheel or a calendar). The value format follows the person's locale.
  • In the copy field the value truncates with an ellipsis at narrow widths; the Copy button never shrinks. Screen readers still read the full value, because the ellipsis is only visual.
  • In .field__with-btn the button keeps its width; the input takes the rest.

Theming

The input reads --colorNeutralBackground1 (fill), --colorNeutralForeground1 (value), --colorNeutralForeground3 (placeholder) and the component token --sd-field-border, which defaults to --colorNeutralStrokeAccessible and is overridden by hover, focus, invalid and read-only. Re-skin a field by setting --sd-field-border on a scoped class.

Two parts do not follow the theme: the search magnifier and the select chevron are inline SVG data URIs in a fixed mid grey. It reads on both the light and the dark input fill, but it will not follow a future high-contrast theme. Native time and date pickers follow color-scheme, which each theme sets.

Accessibility

Role and pattern

Native <input>; no APG widget pattern is needed. The show-password button follows the APG Button pattern as a toggle (aria-pressed, constant name). The copy field's value is plain text; the button is the control.

Focus

The field draws its own ring (border plus halo) on :focus-visible, which for text inputs is any focus, including a tap. When an invalid field gets focus the ring turns danger. After submit with errors, focus moves to the error summary, then to the first invalid field from its link.

Labelling

Every input has a visible <label for>, even search (admin.places labels it "Search"). Hints, errors and the strength meter are joined with aria-describedby. The strength label is a polite live region, so changes are read once typing pauses; the bar is aria-hidden. "Copied" is announced through a role="status" line, not by changing the button alone.

Motion

Border and halo transition over --durationFast; reduced motion makes it instant.

Touch

44px tall at every width; show and copy buttons grow to 44px beside them. Paste is never blocked, so password managers and one-time codes work (3.3.8).

Content

  • Placeholders show a realistic example, not an instruction: "Costco run", "Place name", "Memorial Park, Lakeshore Rd".
  • Prefill what Saturdaze already knows: the email on Reset password, the current name in Rename (3.3.7).
  • Password rules go in the strength label, in plain words: "Eight characters or more."
  • Errors name the fix: "Enter a time after 9:00.", "Enter an email like name@example.com."
  • The copy button says "Copy", then "Copied" for a moment.
