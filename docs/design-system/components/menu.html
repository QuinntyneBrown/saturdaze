Menu

A menu keeps a few less-used actions behind one button, so the page shows only what matters: "Regenerate the weekend" and "Add to calendar" behind More, "Family settings" and "Sign out" behind the avatar.

Overview

Use a menu when one trigger offers two to seven actions that do not need to be on screen all the time. The trigger is a button with aria-haspopup="menu"; the menu is an anchored popover from 720px and a bottom sheet (a dialog) below 720px.

  • Do not use a menu for navigation between pages: that is the top bar or bottom nav.
  • Do not use a menu to pick a value in a form: that is a select or a radio group.
  • If there is only one action, show it as a button. If the action is the reason for the page ("Plan this weekend"), it is the primary button, never a menu item.

Anatomy

  1. Header (optional)Context, not an action: the signed-in email. Body 2, --colorNeutralForeground2, rule underneath.
  2. Item18px icon in --colorNeutralForeground2, 10px gap, label at 14px medium. 44px tall, full width, 8px radius.
  3. Separator (optional)<hr class="menu__sep"> between groups; puts distance before a destructive item.
  4. Warn itemDanger foreground for label and icon. Opens a confirmation; it never destroys on its own.
  5. SurfaceRaised background, 1px --colorNeutralStroke2 border, 12px radius, --shadow28, 6px padding, 240 to 280px wide.

Variants

One component with optional parts. The two menus in the mocks are below; the parts after them (checkable items, shortcuts, disabled items) are part of the component but no mock uses them yet.

Checkable, shortcut and disabled items

Show on the plan

Checked items show a tick at the end; a shortcut is a hint, not the only way; "Regenerate Saturday" is disabled because every Saturday block is locked.

Sizes

One size. Items are 44px tall (--targetComfortable) at every width because menus are used with thumbs as often as with a mouse. The surface is 240px minimum and 280px maximum; long labels wrap rather than widening the menu. The phone sheet is full width.

States

Item states, forced with data-state. In a real menu focus and hover look the same (the hover tint), because arrow keys move focus the way a pointer moves hover; the ring is drawn inside the item.

  • Disabled items use aria-disabled="true", not disabled, so arrow keys still reach them and a screen reader can say they exist. Prefer hiding an action that can never apply here; disable it only when it applies sometimes and the reason is visible elsewhere (the locked Saturday header).
  • Checked (role="menuitemcheckbox" aria-checked="true") adds a tick after the label. Toggling keeps the menu open so several can change at once.
  • Open and closed: the menu is not in the layout while closed. Render it only while open (Angular CDK Overlay does this).

Responsive behaviour

The same actions take two forms (D25):

  • Under 720px the trigger opens a bottom sheet: a dialog titled "Weekend options" with one list row per action (icon disc, title, one-line explanation) and a Close button. A thumb-sized list with a sentence of context suits a phone better than a small popover at the top of the screen.
  • From 720px the trigger opens the anchored menu, right-aligned under the trigger (.menu-anchor), 8px below it. Near the bottom of the viewport the overlay flips above the trigger.
  • The account menu (D26) exists only from 720px. On phones the Family tab in the bottom nav covers the same destinations, so the avatar is not a trigger there.

Theming

The menu reads alias tokens only: --colorNeutralBackgroundRaised for the surface, --colorNeutralStroke2 for the edge and separator, --shadow28 for lift, --colorSubtleBackgroundHover and --colorSubtleBackgroundPressed for items, --colorStatusDangerForeground1 for warn items. It has no component tokens.

In the dark theme the raised surface is a lighter umber than the page, so the menu still reads as above the page even though shadows are weaker on dark backgrounds; the 1px border carries the edge.

Accessibility

Role and pattern

APG Menu Button. The trigger is a <button> with aria-haspopup="menu", aria-expanded and aria-controls. The container has role="menu" and an aria-label (or aria-labelledby the trigger). Items have role="menuitem", or menuitemcheckbox with aria-checked. The header is plain text, and separators are <hr> (role separator). The phone sheet is a modal dialog with ordinary buttons, not a menu.

Keyboard

KeyAction
Enter / Space / ↓ on the triggerOpens the menu and focuses the first item.
↑ on the triggerOpens the menu and focuses the last item.
↓ / ↑Next / previous item, wrapping at the ends. Disabled items are focusable.
Home / EndFirst / last item.
A letterMoves to the next item whose label starts with it.
Enter / Space on an itemActivates it and closes the menu. On a checkable item, toggles it and keeps the menu open.
EscCloses the menu; focus returns to the trigger.
TabCloses the menu and moves focus on from the trigger.

Focus

Opening moves focus into the menu (items use tabindex="-1" and receive focus programmatically). The focused item takes the hover tint and the 2px ring drawn 2px inside its edge, so the ring is never clipped by the menu's rounded surface. Activating an item that opens a dialog moves focus into the dialog; closing that dialog returns focus to the menu trigger, not to the vanished item.

Labelling

The icon-only trigger names the object: "More weekend options", "Account menu". The menu has its own name ("Weekend options", "Account"). Item labels are verb phrases or destinations. Icons are aria-hidden. Shortcuts are hidden from the accessibility tree and exposed with aria-keyshortcuts on the item.

Motion

The anchored menu appears without animation. The phone sheet rises over --durationNormal; under prefers-reduced-motion the duration is zero and it appears in place.

Touch

Every item is 44px tall and full width, with 2px between items. Hover tints apply only under (hover: hover). A tap outside the menu closes it, like Esc.

Content

  • Start with a verb or name the destination: "Regenerate the weekend", "Add to calendar", "Family settings".
  • Two to seven items. More than that is a page, not a menu.
  • Order by frequency, with destructive items last, after a separator.
  • Name the object in a destructive item when the menu does not: "Remove Swim lessons", not "Remove".
  • No trailing ellipsis, even when the item opens a dialog.
  • The header is context, never a label for an action: the account email, or the name of a group of checkable options ("Show on the plan").
