Switch

A switch turns one setting on or off: stay signed in, prefer free picks, get the Friday preview email. It reads as a preference that holds until someone changes it, not as an answer to a question.

Overview

Use a switch for a single setting with two states where "on" is meaningful by itself: the Family page preferences (Budget matters, Try something new each weekend, Friday preview email) save as soon as they flip, and "Remember me" on sign-in keeps the session. The control is a real checkbox with role="switch", so it submits like a checkbox and announces as "on" or "off".

  • Use a checkbox to agree or opt in as part of a form that is submitted later ("I agree to the Terms and Privacy Policy" on Create account), or to pick several items from a list.
  • Use a radio group when the two states are not on and off (Saturday or Sunday).
  • Use a toggle button (aria-pressed) for an action-like state on content, such as Favourite on a past weekend.

Anatomy

  1. Track.toggle__track, 44 × 24px pill. Off: --colorNeutralStrokeAccessible; on: --colorStatusSuccessBackground3. It is the visible control; the real input is visually hidden.
  2. Thumb20px circle (::after), --colorNeutralBackground1 with --shadow4; slides 20px to the right when on.
  3. Label.toggle__label, 14px medium. The whole <label> is the hit target and the accessible name.

Variants

One control, two layouts. Put the switch before a short label inside forms; put it at the end of a settings row so labels line up on the left and switches line up on the right.

Label after the switch

Sign in and Saturdaze Admin sign in use this form for "Remember me".
HTML
<label class="toggle">
  <input class="toggle__input" type="checkbox" role="switch" checked>
  <span class="toggle__track"></span>
  <span class="toggle__label">Remember me</span>
</label>

Settings row: label and description first, switch at the end

.toggle--end reverses the row and spreads it full width; the text and description are part of the label, so tapping either flips the switch.
HTML
<label class="toggle toggle--end">
  <input class="toggle__input" type="checkbox" role="switch" checked>
  <span class="toggle__track"></span>
  <span class="toggle__text">
    <span class="toggle__label">Friday preview email</span>
    <span class="toggle__desc">A draft in your inbox at 6pm Friday</span>
  </span>
</label>

Sizes

One size: a 44 × 24px track with a 20px thumb. The label, not a bigger track, provides the larger target.

States

Hover is forced with data-state="hover" on the .toggle. Focus is forced with data-state="focus" on the track, which is where a real :focus-visible on the hidden input draws the ring. On, off and disabled use the real checked and disabled attributes.

Both themes

  • On fills the track forest green and moves the thumb right. Position and colour both change, so the state never relies on colour alone.
  • Hover (pointer devices only) adds a 4px subtle halo around the track.
  • Disabled uses the native attribute: the track drops to 50% opacity, the cursor shows not-allowed and the input leaves the tab order. Say why nearby (for example, "Ask a parent to change this").
  • Saving: a switch that saves straight away flips at once and saves in the background. If the save fails, flip it back and say so in a toast; do not add a spinner to the track.

Responsive behaviour

  • The switch never changes size. A .toggle--end row spans its container at every width, so switches in a list share one right edge.
  • Long labels and descriptions wrap; the track stays vertically centred on the text block and never shrinks (flex: none).
  • Inside an .auth-card__row the switch and the "Forgot password?" link wrap onto two lines under about 340px of card width.
  • Hover halos apply only under (hover: hover).

Theming

The switch reads alias tokens only: --colorNeutralStrokeAccessible for the off track, --colorStatusSuccessBackground3 for the on track, --colorNeutralBackground1 for the thumb (white in light, dark umber in dark), --colorSubtleBackgroundHover for the hover halo, and --colorStrokeFocus2 for the ring. There are no component tokens; a theme changes the alias values.

In the dark theme the off track is the lighter dark-mode accessible stroke and the on track the lighter forest green, both well above 3:1 against the dark surface. The thumb takes the card surface, so it is dark on the light tracks and stays visible in both positions. The mocks' thumb was a literal #fff, which in dark sat at about 2:1 on the on track. The mocks' off track was the 16% decorative line, invisible on cream (D06); the thumb was a literal #fff (D17).

Accessibility

Role and pattern

A native <input type="checkbox" role="switch">, following the APG Switch pattern. Screen readers announce "Remember me, switch, on". Keep the native checkbox so the value submits with a form and the browser handles keys; never build a switch from a <div> or a <button> without aria-checked.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the switch.
SpaceTurns it on or off.
EnterNo effect on the switch; in a form it submits the form, as with any checkbox.

Focus

The input is visually hidden, so .toggle__input:focus-visible + .toggle__track draws the shared ring (2px --colorStrokeFocus2, 2px offset) around the track. It appears for keyboard focus only.

Labelling

The <label class="toggle"> wraps the input, so .toggle__label is the accessible name and .toggle__desc is read with it. When the visible setting name sits outside the label (the Family preferences list), add a .visually-hidden label inside with the same words, or in Angular pass srLabel; better still, use .toggle--end so the visible text is the label. Never put "on" or "off" in the label; the role announces the state.

Motion

The thumb slides and the track colour changes over --durationNormal with --curveEasyEase. Under prefers-reduced-motion the duration tokens are zero, so the switch jumps to its new state; position still shows the change.

Touch

The track alone is 44 × 24px, which meets the 24px minimum. With a visible label the whole label row is the target. Keep at least 8px between stacked switches; in the Family list each row is 44px or taller.

Content

  • Name the setting, not the action: "Friday preview email", "Budget matters". Not "Turn on the Friday email".
  • The label must make sense with "on" after it. "Remember me" on reads well; "Forget me" would read as a double negative when off.
  • Use the description for the effect: "A draft in your inbox at 6pm Friday". Keep it to one line at 360px where possible.
  • Sentence case, no full stop, no "Enable" or "Allow" prefix.
  • Do not add "On" and "Off" text next to the track.

Sources

Extracted from these mocks:

  • pages/sign-in and pages/admin.sign-in: "Remember me" with a visible label, in .auth-card__row beside "Forgot password?", including the wrong-password state.
  • pages/family: the Preferences list (Budget matters, Try something new each weekend, Friday preview email) with the name in the list row and a visually hidden label in the switch.

Drift fixed during extraction (see the README drift log): D06 the off track used the 16% line (1.36:1), now --colorNeutralStrokeAccessible; D17 the literal #fff thumb, now a token; D13 the raw 14px label. The .toggle--end settings row is the recommended replacement for the Family list's hidden-label pattern; the mocks do not use it yet.

Rules added to components.css for this page: the surface-coloured thumb, position: relative on .toggle (keeps the visually hidden input inside its label), and no shared ring on .toggle[data-state="focus"] so the forced focus state rings only the track.
