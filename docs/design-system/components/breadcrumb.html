Component · Navigation

Breadcrumb

Shows where a page sits and leads back up. Saturdaze is shallow, so most pages need only a single back link ("← Places"); the full trail is for pages three or more levels deep.

Overview

There are two ways up, and the depth of the page decides:

  • Back link (.page-header__eyebrow): one link to the parent, above the page title. Use it on every second-level page: a place in Admin ("← Places"), Review submissions ("← Family"). This is what the mocks use.
  • Breadcrumb (.breadcrumb): the whole trail, for pages three or more levels below a top-level destination, where knowing the path matters (Admin › Places › Port Credit Memorial Park › Photos). No mock is that deep yet; this is a core component ready for when one is.

Neither replaces primary navigation. Top-level screens (Weekend, Ideas, Past, Family; Photo health, Places) have no back link and no breadcrumb: the top bar, bottom nav or sidebar already says where you are. Sibling views use tabs. See navigation and page structure.

Anatomy

  1. Ancestor link13px semibold, --colorNeutralForeground2, underlined in --colorNeutralStrokeAccessible; 24px tall target.
  2. SeparatorA "/" drawn by CSS (li + li::before) in --colorNeutralForeground3; not part of the link text.
  3. Current pagePlain text with aria-current="page" in --colorNeutralForeground1; not a link.

  • Hover darkens the label and turns the soft underline to full colour; the back link gains an underline it does not have at rest.
  • No visited, disabled or loading state: every ancestor exists and is reachable.

Responsive behaviour

  • From 720px the full trail shows and wraps onto a second line if it must; items never truncate.
  • Under 720px every item except the parent hides, and the parent gets a "←" in place of the separator. The trail becomes the back link: one target, one line, the same place the eyebrow sits.
  • The landmark stays a breadcrumb for screen readers at every width, but hidden items are display: none, so on a phone it holds one link. That is intended: the phone layout offers one way up.
  • The mocks hide the Review submissions back link under 720px (hide-lt-720), because the bottom nav's Family tab is the way back there. Do this only when a bottom-nav destination is the parent.

Theming

Alias tokens only: --colorNeutralForeground2 for links, --colorNeutralStrokeAccessible for their resting underline, --colorNeutralForeground3 for separators and --colorNeutralForeground1 for the current page and hover. Breadcrumbs are deliberately neutral, not coral: they are wayfinding, not a call to action. No component tokens. In the dark theme the same roles lighten on the umber canvas.

Accessibility

Role and pattern

The APG Breadcrumb pattern: a <nav aria-label="Breadcrumb"> landmark around an ordered list, the current page marked aria-current="page". The back link is an ordinary link inside the page header and needs no landmark.

Keyboard

KeyAction
Tab / Shift+TabMoves through the ancestor links; the current page is skipped.
EnterFollows the link.

Focus

The shared 2px --colorStrokeFocus2 ring with a 2px offset around the link text, with a small radius.

Labelling

The landmark is "Breadcrumb". Link text is the ancestor page's title, so it matches the heading the person lands on. The separators and the phone "←" are drawn with CSS ::before; some screen readers read generated content ("slash", "left arrow"). The design-system CSS gives the generated content empty alternative text (content: "/" / ""), with the plain declaration first as a fallback, so it is not announced. The back link's arrow is an aria-hidden SVG, so it is read as "Places, link".

Contrast

Link on the page
Current page on the page
Separator on the page
Link underline on the page
Focus ring on the page

Links are distinguished from the current page by their underline as well as their colour (1.4.1).

Motion

None. Hover changes colour without a transition.

Touch

Each link is at least 24px tall (--targetMin), the 2.5.8 minimum, and separated by the 4px gap plus the separator. The back link on phones is the same 24px target; it sits above the title with space around it.

Content

  • Each item is the page's own title, word for word: "Places", not "All places"; "Port Credit Memorial Park", not "Place details".
  • The back link names the destination, not the direction: "← Places", never "← Back".
  • Start the trail at the app's top level ("Admin"), not at a home icon.
  • Long place names wrap; never shorten a name with an ellipsis, because similar places differ at the end ("Port Credit Memorial Park" and "Port Credit Memorial Arena").
