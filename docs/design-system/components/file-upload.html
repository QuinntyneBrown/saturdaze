File upload

File upload lets someone pick a photo from their device: a place photo in Saturdaze Admin, or a profile photo on Family. The native file input is the control; the drop zone around it is an enhancement.

Overview

Saturdaze only uploads photos, one at a time. Two forms cover every case in the mocks:

  • Drop zone (.upload-drop): a dashed, full-width target that wraps a real <input type="file">. Clicking, tapping or pressing Enter opens the device's file chooser; dropping a file on it works too. Used in AD1 Upload a photo.
  • Avatar picker (.photo-picker): a 96px preview of the person's avatar beside a quiet "Choose a photo" button that is the file input's label. Used in D27 Profile photo, where the result is a face, not a scene.

Choosing among photos that already exist is a photo pick; its "Your own photo" tile is the same file input in a 4:3 tile. A link to an image on the web is a text field of type URL (AD2).

Anatomy

  1. Drop zone.upload-drop on the <label>: 1px dashed accessible stroke, medium radius, 120px minimum height, centred content.
  2. Icon20px upload or plus glyph in currentColor, aria-hidden="true".
  3. Label"Choose a photo", --typographyBody2 semibold. It matches the input's accessible name.
  4. Hint or file summary.field__hint in regular weight: accepted types and size before a pick, "memorial-park.jpg · 3.1 MB · 1200 × 675" after.

The file input itself is transparent and covers the whole zone (.photo-pick__opt input), so every click, tap and drop lands on the native control. It is never display: none, which would remove it from the keyboard and the accessibility tree.

Sizes

One size each. The drop zone fills its container's width with a 120px minimum height; the avatar picker's preview is fixed at 96px and its button is the medium quiet button.

States

Hover and focus are forced with data-state. In the product the zone shows focus through :focus-within (the input inside is focused), dragging through a data-dragging attribute set by the drag events, and failure with .upload-drop--failed plus aria-invalid="true" on the input.

Both themes

  • Hover (pointer devices only) tints the zone with the subtle hover fill. Dragging a file over the window switches it to the brand tint and brand border and the label to "Drop to upload", so the target is obvious before release.
  • Uploading disables the input, names the file in the zone and shows a determinate progress bar under it. The dialog's Save button takes aria-busy="true"; the rest of the dialog stays usable (alt text can be typed meanwhile).
  • Failed keeps the zone usable, so the fix is one more pick. The message names the file and the rule it broke, sits under the zone, and is linked with aria-describedby.
  • Disabled is not used. If uploads are not allowed (no rights, quota reached), leave the zone out and say why in a message.

Responsive behaviour

  • The drop zone is always full width and at least 120px tall. Phones and tablets cannot drag files in, so the label leads with "Choose a photo" at every width and dragging is never mentioned in the copy.
  • The avatar picker is a wrapping row: the 96px preview and the field (at least 180px) sit side by side, and the field drops under the preview when the dialog is narrower than about 300px.
  • On phones the file chooser is the system sheet (camera, photo library, files). accept keeps it to images; do not add capture, which would skip the library.
  • Hover tints apply only under (hover: hover).

Theming

The drop zone has no component tokens; it reads alias tokens directly: --colorNeutralStrokeAccessible for the dashed edge, --colorNeutralForeground2 for the label, --colorSubtleBackgroundHover on hover, --colorBrandBackground2 and --colorBrandStroke1 while dragging, and the danger status set when it fails. The avatar picker reuses the avatar person tones and a quiet button.

In the dark theme the zone stays transparent on the raised dialog surface, its dashed edge uses the lighter accessible stroke, and the dragging tint becomes a deep coral with a lighter coral edge. The progress fill and the error colours come from the status ramps, which have dark values of their own.

Accessibility

Role and pattern

A native <input type="file">; no ARIA pattern applies and none should be added. The drop zone is its <label>, so the whole zone is a click target for the input. Drag and drop is an extra path for pointer users and never the only one (2.5.7 Dragging Movements).

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the file input. One stop per zone or picker.
Enter / SpaceOpens the system file chooser.
EscIn the chooser: cancels and returns focus to the input with nothing changed.

Focus

The input is invisible, so the focus ring is drawn on what people see. The drop zone shows the shared 2px ring through :focus-within. In the avatar picker the input is visually hidden and its label is the button, which needs the same ring when the input has focus (.photo-picker__field:has(input:focus-visible) .photo-picker__choose draws it). After a pick, focus stays on the input.

Labelling

The input's name is the visible label: "Choose a photo" (aria-label on the covered input, or the <label for> button in the picker). Accepted types and the size limit, and later the chosen file summary, are tied to it with aria-describedby. Upload progress has a labelled role="progressbar"; completion and failure are announced through the error's role="alert" or a polite live region ("memorial-park.jpg uploaded").

Motion

The hover and dragging tints transition over --durationFast; the progress fill grows over --durationNormal. Both are zeroed under prefers-reduced-motion, so the bar jumps between values instead of sliding.

Touch

The whole zone, at least 120px tall and full width, is the target. The avatar picker's button is 40px. Neither needs a drag gesture.

Content

  • The label is the action: "Choose a photo", "Choose a different photo" once one is set. Not "Browse", "Upload file" or "Drag and drop here".
  • The hint gives the rules in plain words: "JPEG, PNG or WebP, up to 10 MB." Say what happens to the file when it matters: "Location data is removed before it is saved."
  • After a pick, the hint becomes the file summary: name · size · dimensions.
  • Errors name the file and the rule: "memorial-park.tiff is not a JPEG, PNG or WebP.", "beach.jpg is 14 MB. Choose one under 10 MB." Never "Invalid file".
  • While dragging, the label changes to "Drop to upload".
