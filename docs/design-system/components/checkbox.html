Checkbox

A checkbox says yes or no to one thing that takes effect when the form is sent: agreeing to the Terms, getting the Friday preview, or picking who goes to Swim lessons.

WCAG 2.2 AAStatus: stableAngular: sd-checkboxNative <input type="checkbox">

Overview

Use a checkbox inside a form that has a submit button, for a choice that is saved with everything else. Use a switch for a setting that takes effect the moment it is flipped (the Family page's "Friday preview email", Sign in's "Remember me"). Use a radio group when exactly one option must be chosen, and filter chips to narrow a list on the spot.

  • Single: one statement with its own label, such as agreeing to the Terms.
  • With description: a short label and a quieter line that explains the consequence (.check__text, .check__desc).
  • Group: several related checkboxes in a <fieldset class="choice-group"> with a <legend class="choice-group__legend"> that asks the question.

Anatomy

  1. BoxNative input, 18px, tinted with accent-color (forest) when checked; 2px top margin so it lines up with the first line of text.
  2. Label14px regular, --colorNeutralForeground1. The whole <label class="check"> is the hit area; 10px gap to the box.
  3. Description (optional)Body 2, --colorNeutralForeground2, 2px under the label.

Indeterminate is set from script. HTML has no attribute for it: the page sets input.indeterminate = true whenever some but not all of the children are ticked, and clears it when all or none are. This page does that with a two-line script on load. Clicking an indeterminate parent ticks every child; clicking it again clears them.

Sizes

One size. The box is 18px so it reads at the 14px label size; the target is the whole label, which is at least 24px tall and usually much wider. A larger box would look like a different control.

States

Hover is forced with data-state="hover" on the label, focus with data-state="focus" on the input; the rest use real attributes. Indeterminate boxes are set by the script on this page.

Both themes

  • Checked fills the box with forest green (accent-color) and a tick the browser colours for contrast (light on the light theme, dark on the dark theme).
  • Indeterminate shows a dash. It is a display state for a parent, never a value that is submitted.
  • Invalid draws a 2px danger outline 1px outside the box, plus a .field__error line; the colour is never the only signal.
  • Disabled fades the whole row to 50% and shows the not-allowed cursor. Say nearby why it cannot change.

Responsive behaviour

  • Labels wrap under themselves, never under the box: the box stays top-aligned with the first line.
  • Vertical groups at every width. .choice-group--row wraps onto more lines on narrow phones; keep row groups to short labels.
  • Hover tint applies only on pointer devices.

Theming

The box is the browser's own control, tinted with accent-color: var(--colorStatusSuccessBackground3). The browser picks the tick colour for contrast against that fill, and the unchecked border and fill from the theme's color-scheme, so the dark theme gets a dark box with a light edge without extra CSS. Label and description read --colorNeutralForeground1 and --colorNeutralForeground2; the invalid outline reads --colorStatusDangerForeground3.

The unchecked edge is drawn by the browser (Chrome's is a mid grey above 3:1 on white), so its exact colour is outside the token system. If a theme ever needs to control it, replace the native look with appearance: none and draw the box from tokens; do not restyle half of it.

Accessibility

Role and pattern

Native <input type="checkbox"> inside its <label>. Groups use <fieldset> and <legend>. The mixed parent follows the APG Checkbox pattern (tri-state): the native indeterminate property is exposed as "mixed", and aria-controls lists the children.

Keyboard

KeyAction
Tab / Shift+TabMoves to the next / previous checkbox; each one in a group is a tab stop.
SpaceToggles the focused checkbox. On a mixed parent, ticks all children; again, clears them.
EnterSubmits the form (it does not toggle).

Focus

The shared ring (2px --colorStrokeFocus2, 2px offset) around the box on :focus-visible. On submit with errors, focus goes to the error summary, whose link moves focus to the checkbox.

Labelling

The label text is the accessible name; the description is part of the same label, so it is read with it. Required checkboxes set required; the error is joined with aria-describedby. Links inside a label (Terms, Privacy Policy) stay separate tab stops and do not toggle the box.

Motion

None; the browser draws the tick instantly.

Touch

The 18px box alone is under the 24px minimum, so the label is always the target: tapping "Send me the Friday preview" toggles the box. Rows in a group are at least 24px tall and 12px apart.

Content

  • Write the label as what will be true when it is ticked: "Send me the Friday preview", not "Don't send me emails".
  • No negatives. Unticking should never mean yes.
  • Put the consequence in the description: "A draft of the weekend in my inbox at 6pm."
  • Legends ask the question: "Who goes to Swim lessons", "Days".
  • Opt-ins for email start unticked in the product. (The create-account mock shows it ticked to display the state.)
