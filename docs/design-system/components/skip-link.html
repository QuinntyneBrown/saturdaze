Skip link

A keyboard user should not have to tab through the brand and four navigation links on every page. The skip link is the first thing Tab reaches; it appears, and Enter jumps straight to the page content.

WCAG 2.2 AA · 2.4.1Status: core, not in the mocks (D22)Angular: none yet

Overview

Every page in the family app, the public site and Admin starts with <a class="skip-link" href="#main">Skip to content</a> as the first element in <body>, and every page's <main> has id="main" (the mocks already give it that id). It satisfies WCAG 2.4.1 Bypass Blocks.

No mock has one yet (drift D22). This page shows it as it should ship. Try it here: reload, then press Tab once; the real skip link appears at the top left of this page.

  • One skip link per page, to the main content. Saturdaze pages are short enough that "skip to navigation" or "skip to filters" links are not needed.
  • Auth screens have no navigation before <main>; they still carry the skip link so every page behaves the same and the first Tab is predictable.

Anatomy

  1. Label"Skip to content", 14px semibold (--typographyLabel) in --colorNeutralForeground1.
  2. SurfaceA raised box with 8px corners (--colorNeutralBackgroundRaised, --borderRadiusMedium, --shadow28), 44px tall.
  3. Focus ringThe shared 2px --colorStrokeFocus2 ring with a 2px offset; it is always shown, because the link is only visible while focused.

Variants

One variant. At rest it sits 100px above the top of the page; on :focus-visible it moves to 16px from the top and left, above the top bar, the bottom nav and any dialog (--zIndexTooltip). In the examples it is forced visible with data-state="focus", which also puts it in the flow.

  • After activation the link loses focus and returns off screen; focus moves to <main>, so the next Tab reaches the first control in the content (on Weekend, "Plan this weekend" or "Share").
  • It never uses display: none or visibility: hidden at rest: either would remove it from the tab order.

Responsive behaviour

  • Same position and size at every width: 16px from the top and left edge of the viewport.
  • Sticky top bar (720px and up): jumping to #main scrolls the main content to the top of the viewport, where the 64px bar would cover it. scroll-padding-top: calc(var(--layoutTopBarHeight) + var(--spacingVerticalL)) on html stops the jump 80px short, so the page header is visible (the mocks' app.css does this, and components.css does it for a top bar or site bar that is a direct child of <body>).
  • Phones: there is no bar above <main> under 720px (the bottom nav comes after it), so the link mostly helps keyboard users on tablets and desktops, and screen reader users everywhere.
  • Admin: the link skips the sidebar or bar to <main id="main" class="admin-main">.

Theming

Alias tokens only: --colorNeutralBackgroundRaised and --shadow28 lift it above whatever is under it, --colorNeutralForeground1 for the label, the shared focus ring. In the dark theme it is umber 800 with near-white text; the deeper dark shadow keeps it separate from the bar.

Accessibility

Role and pattern

A same-page link (<a href="#main">), the technique in WCAG technique G1. There is no APG widget pattern; landmarks (<header>, <nav>, <main>) give screen reader users a second way past the navigation, but keyboard-only users need the link.

Keyboard

KeyAction
Tab (first press on a page)Focuses the skip link; it appears.
EnterMoves focus and scroll to <main id="main">.
Tab againIgnores it and continues to the brand and navigation.

Focus

Modern browsers move the sequential focus starting point to the target of a fragment link, so <main> does not need tabindex. In the Angular app the link must work despite <base href="/">: a bare href="#main" resolves to /#main and leaves the page. Either build the href from the current URL or handle the click by focusing main (with tabindex="-1" on it) and calling preventDefault(). After a route change, keep focus management separate: the skip link is not a substitute for moving focus to the new page's heading.

Labelling

The text is the name: "Skip to content". It is not hidden from screen readers; they announce it first, which is useful.

Contrast

Motion

It appears instantly; there is no slide-in. Nothing to reduce.

Touch

44px tall (--targetComfortable). Touch users do not reach it without a keyboard or switch device, which is fine; screen reader swipe navigation reaches it first.

Content

  • Exactly "Skip to content" on every page and in both apps, so it is recognised.
  • Not "Skip navigation" (it says what is skipped, not where you land) and not "Jump to main content area".

Sources

No mock has a skip link (drift D22: "No skip link (2.4.1)"); every mock's <main> already has id="main", so adding the link is one line per page. The scroll clearance for the sticky bar comes from styles/app.css (scroll-padding-top: calc(var(--sd-topbar-h) + 16px)). The design-system docs themselves use the same component on every page. The product has no skip link either; the <base href> fragment problem above is the thing to watch when adding it.
