Component · Data display

Table

A table lays out records that people read across and compare down: who changed which photo and when, which places are missing a photo. It is the wide-screen form of the admin activity log; on phones the same records stack as an activity feed.

Overview

Use a table when every record has the same fields and the reader needs to scan one field down many records: the time column of the activity log, the photo count of every place. The column headers do the labelling, so each cell can be short.

  • Use a list when each record is one thing to open (family members, commitments, places to fix) and there is at most a title, a sub-line and a trailing chip.
  • Use a description list for the fields of one record (a submission's Location, Cost, Ages).
  • Use the activity feed for the same records as this table at phone width, where five columns do not fit.
  • Product screens are for families, not spreadsheets. Tables belong to Saturdaze Admin; the family app has none.

No mock uses a <table> yet. The admin activity log (admin.activity) is tabular data drawn as a div grid with no column headers (drift D23); the examples below are that log rebuilt as a table with its real columns.

Anatomy

  1. Caption<caption>, --typographySubtitle1. Names the table for screen readers and labels the scroll region.
  2. Header row<th scope="col"> on --colorNeutralBackground3, 12px caps, sticky to the top of the wrapper. A sortable header holds a <button> and carries aria-sort.
  3. Body rowCells padded 12 × 16px (8 × 12px dense), 1px --colorNeutralStroke2 rule between rows, tinted on hover.
  4. Wrapper.table-wrap: card surface, 1px border, --borderRadiusLarge, scrolls sideways when the columns do not fit.

Variants

One base table; features are added per column. Pick the fewest that do the job: a five-row log needs no sorting.

Sizes

Two densities. Default (12 × 16px cells) is for reading a log; dense (.table--dense, 8 × 12px) is for an admin scanning many short rows on a large screen. Never go denser than this: rows must stay at least 24px tall for the checkboxes and links inside them.

Responsive behaviour

  • Under 720px the activity log is not a table. Render the activity feed (.audit-list) instead: time and who on the first line, the place link, the action chip at the right, the change on its own line. Use .hide-gte-720 on the feed and .hide-lt-720 on the table; display: none keeps only one copy in the accessibility tree.
  • From 720px the table renders. When the columns are wider than the content area, .table-wrap scrolls sideways inside itself; the page never scrolls sideways. The wrapper is a focusable region (tabindex="0", role="region", named by the caption) so keyboard users can scroll it with the arrow keys.
  • Cells wrap long text (the Change column); the time column and header labels do not wrap.
  • The header row is sticky to the top of the wrapper. Give the wrapper a max-height when the table is long and the page has other content below; otherwise let the page scroll.

Theming

The table reads alias tokens only: card surface --colorNeutralBackground1, header well --colorNeutralBackground3, row rules --colorNeutralStroke2, hover --colorSubtleBackgroundHover, selection --colorBrandBackground2. It has no component tokens; restyle it by changing the aliases in a theme, not by overriding .table.

In the dark theme the wrapper sits on the warm umber card surface, the header well is a step lighter, and selection is a dark coral tint under near-white text. Chips inside cells keep their own tone pairs (see chip).

Accessibility

Role and pattern

Native <table> with <caption>, <thead> and <th scope="col">; the identifying cell of each row is <th scope="row">. This is the APG Table pattern; sorting follows its sortable table example: a <button> in the header and aria-sort on the <th>. Never build a table from divs (drift D23): the column headers are what make each cell understandable.

Selection lives in the row checkbox. aria-selected is announced only inside an ARIA grid; if a table needs arrow-key navigation between cells, make it an APG Grid instead. No admin screen needs that yet.

Keyboard

KeyAction
Tab / Shift+TabMoves through the scroll region, then each sort button, checkbox and link in reading order. Rows and cells are not tab stops.
Enter / SpaceOn a sort button: sorts by that column; a second press reverses the order.
SpaceOn a row checkbox: selects or clears the row and updates the "N selected" status.
← →With the scroll region focused: scrolls the table sideways.

Focus

Sort buttons, checkboxes, links and the scroll region use the shared ring (2px --colorStrokeFocus2, 2px offset) on :focus-visible. After a sort, focus stays on the button that was pressed.

Labelling

The caption names the table and, through aria-labelledby, its scroll region. Hide the caption visually (.visually-hidden) only when a visible heading right above says the same. A sort button's name is the column name; the sort state comes from aria-sort, so do not add "sorted descending" to the label. Row checkboxes are labelled with the row: "Select Harbour Grill". Times use <time datetime> with the time zone written out.

Row rules (--colorNeutralStroke2) are decorative: the grid of cells is conveyed by the markup, so they are exempt from 1.4.11.

Motion

The row hover tint is instant. Skeleton shimmer stops under prefers-reduced-motion; the grey bars stay. A re-sort replaces the rows without animation.

Touch

Tables appear only from 720px, mostly with a pointer. Rows are at least 44px tall in the default density, so links and checkboxes inside them keep a 24px target with space around it; dense rows stay above 32px.

Content

  • Caption: what the rows are, plus the filter or order if one applies: "Activity log, newest first", "Places, worst photo health first".
  • Column headers: one or two words, sentence case in the markup (CSS adds the capitals): Time, Who, Place, Action, Change, Photos.
  • Times: 2026-10-06 14:02 UTC in the admin log, always with the zone. Family-facing dates follow content rules ("Sat 17 May").
  • Numbers right-aligned with the unit in the header, not in every cell ("Photos", then "2").
  • An empty cell says why: "—" for "not set" in a Change column, "Not given" in a value column. Never leave a cell blank.
  • Changes read as before → after: "Alt text: — → Patio tables by the water".
