Tabs (segments)

A pill track of two or three choices. It is either a set of tabs that swaps a panel on the same page, like Saturday and Sunday, or a switch between sibling pages, like Activities, Food and Events. Same look, different markup: pick by what the choice does.

Overview

.segments is one visual component with two patterns. The question that decides which: does the address change?

TablistPage switch
Use whenThe choices are views of the same thing on one page, and switching should be instant: Saturday or Sunday of this weekend.Each choice is its own page with its own address, title and back-button entry: Activities, Food, Events; Terms, Privacy.
Markuprole="tablist" on the track, <button role="tab"> with aria-selected and aria-controls, and a role="tabpanel" per tab.<nav aria-label> around <a href> links; the current one has aria-current="page".
KeyboardOne Tab stop; ← → move and select.Every link is a Tab stop; Enter follows it.
In the mocksweekend.htmlideas.html, ideas.food.html, ideas.events.html, legal.html

Do not use segments for more than three choices, for filters that combine (use filter chips), for a value in a form (use the .seg-radio radio group on radio group), or for app-level destinations (use the top bar and bottom nav).

Anatomy

  1. Track.segments: a --colorNeutralBackground3 pill with 4px padding; full width, capped at 420px from 720px.
  2. Selected tabA white (--colorNeutralBackground1) pill with --shadow4, a 1px --colorNeutralStrokeAccessible edge and a --colorNeutralForeground1 label; set by aria-selected="true" or aria-current="page".
  3. Tab.segments__tab: 36px tall, equal width, 15px semibold (--typographyBody1Strong) in --colorNeutralForeground2.
  4. Count (optional).segments__count: 12px tabular figures after the label.

Variants

Tablist: Saturday and Sunday

Weekend shows one day at a time beside the map. The tabs swap the day panel in place; the address and history do not change. Activation is automatic: moving with the arrow keys selects the tab and shows its panel at once, because the panels are already loaded and cheap to show.

Saturday · Swim lessons 9:00 to 10:00, Lavender fields at Terre Bleu 11:30, lunch at La Marina 13:30.

Sunday · Pancakes at home, Riverwood Conservancy walk 10:30, groceries before 16:00.

.segments--narrow tablist; the Sunday panel is hidden until its tab is selected.

Both themes

ActivitiesFoodEvents
ActivitiesFoodEvents
  • Selected is shown by the raised white pill, its shadow and the darker label. The pill against the track is a small luminance step (white on cream 100), so the selected pill also carries a 1px --colorNeutralStrokeAccessible inside edge, which meets 3:1 against the track on its own (1.4.11).
  • Disabled (aria-disabled="true", 50% opacity) exists for a tab whose panel has nothing yet. Prefer showing the panel with an empty state; a disabled tab cannot say why.
  • Exactly one tab is selected (or one link current) at all times.

Responsive behaviour

  • Under 720px the track fills the column and tabs share it equally, so the targets are as wide as possible under the thumb.
  • From 720px the track stops at 420px (default) or 280px (narrow) and aligns to the start of its row. On Weekend it shares a toolbar row with the share and regenerate actions.
  • Labels never wrap or truncate (white-space: nowrap). Three tabs at 360px give each about 105px: enough for "Activities" and a two-digit count, not for longer labels. A fourth choice does not fit; use another pattern.

Theming

Segments read alias tokens only: --colorNeutralBackground3 for the track, --colorNeutralBackground1 and --shadow4 for the selected pill, --colorNeutralForeground2 for labels and counts, --colorNeutralForeground1 for the selected or hovered label. No component tokens.

In the dark theme the track is umber 750 and the selected pill umber 850, so the selected pill is darker than the track rather than lighter; the 1px accessible edge and the near-white label carry the state.

Accessibility

Role and pattern

Tablist: the APG Tabs pattern with automatic activation (example). The track has role="tablist" and a name ("Day"); each tab is a <button role="tab"> with an id, aria-selected and aria-controls; each panel has role="tabpanel" and aria-labelledby pointing back at its tab. Only the selected tab is in the tab order (tabindex="0"; the others -1).

Page switch: a named <nav> landmark of links with aria-current="page". Never put role="tab" on links that load pages: a screen reader would promise in-place panels and arrow keys that do not exist.

Focus

The shared 2px --colorStrokeFocus2 ring wraps the focused tab with a 2px offset, which sits over the track's 4px padding. Moving between tabs moves the ring; the panel itself is focusable (tabindex="0") when it starts with no focusable content, so Tab from the tablist lands in it.

Labelling

The tablist or nav needs a name that says what is being chosen: "Day", "Idea type", "Document". Tab labels are the visible text; a count is read with it ("Events 8"). Panels are named by their tab.

Motion

Background and label colour transition over --durationFast; the pill does not slide between tabs. Panels swap instantly. Reduced motion zeroes the duration.

Touch

Tabs are 36px tall and at least 80px wide at 360px, above the 24px minimum (2.5.8). The track's 4px padding keeps neighbouring tabs from touching the edge.

Content

  • One word per tab where possible, sentence case: "Saturday", "Food", "Privacy". Two or three tabs.
  • Labels are parallel: all days, all kinds of idea, all documents. Do not mix "Events" with "What's on".
  • Order is the natural one: Saturday before Sunday, Terms before Privacy, Activities first because it is the default.
  • Counts are plain numbers, no brackets, and only when they help choose.

Code

// Tablist: automatic activation, roving tabindex
tablist.addEventListener('keydown', (e) => {
  const tabs = [...tablist.querySelectorAll('[role="tab"]')];
  const i = tabs.indexOf(document.activeElement);
  const next = { ArrowRight: i + 1, ArrowLeft: i - 1, Home: 0, End: tabs.length - 1 }[e.key];
  if (next === undefined) return;
  e.preventDefault();
  select(tabs[(next + tabs.length) % tabs.length]);   // sets aria-selected, tabindex, hidden; focuses it
});
