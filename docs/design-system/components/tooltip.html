Tooltip

A tooltip names an icon-only button for people using a mouse or keyboard: "More weekend options", "Favourite this weekend", "Swap Lavender fields". It repeats or adds to the accessible name; it never holds anything a person needs to act on.

Overview

Use a tooltip on an icon-only button whose icon could be read two ways: the More button, the favourite heart, a day header's regenerate icon under 720px, a timeline block's swap and lock icons. The button still has its own aria-label; the tooltip shows the same words to sighted mouse and keyboard users.

  • Do not use a tooltip for anything a person must read to succeed: field rules belong in a hint, consequences in a dialog subtitle.
  • Never put links, buttons or rich text inside. If it needs a control, it is a menu or a dialog.
  • Touch screens have no hover, so tooltips never show on touch. Anything a phone user needs must be visible without one.

No mock uses a tooltip; the button page names it as the companion of icon-only buttons. The product ships it as the [sdTooltip] directive on a CDK Overlay. This page documents its geometry on Fluent tokens (drift D30).

Anatomy

  1. Bubble.tooltip: inverted surface, --borderRadiusSmall, 4 × 8px padding, --shadow16, wraps at 240px.
  2. Gap8px (--spacingVerticalS) between the bubble and its trigger, centred on it.
  3. TriggerThe control inside .tooltip-anchor; it owns the focus and the accessible name.

Variants

One look, two relationships and two placements. The relationship decides what assistive technology hears; the placement only decides where it sits.

Favourite this weekend Locked blocks stay put Swap Lavender fields Switch theme T
Label (icon-only, bubble hidden from assistive tech), description (adds a fact to a labelled button), below, with a shortcut.
HTML
<!-- Label: the button's aria-label is the name; the bubble repeats it -->
<span class="tooltip-anchor">
  <button class="btn btn--ghost btn--sm btn--icon" type="button" aria-label="Favourite this weekend">…</button>
  <span class="tooltip" role="tooltip" id="tip-fav" aria-hidden="true">Favourite this weekend</span>
</span>

<!-- Description: the bubble adds to a named button -->
<span class="tooltip-anchor">
  <button class="btn btn--quiet btn--sm" type="button" aria-describedby="tip-regen">…Regenerate</button>
  <span class="tooltip" role="tooltip" id="tip-regen">Locked blocks stay put</span>
</span>
  • Label (sdTooltipRelationship="label"): for icon-only buttons. The text equals the button's aria-label, and the bubble is aria-hidden so nothing is read twice.
  • Description (the default): the bubble adds a fact to a button that already has a visible name, linked with aria-describedby while it shows.
  • Above is the default; below (.tooltip--below, sdTooltipPlacement="bottom") for triggers at the top of the viewport, such as the top bar. The product flips to the other side when there is no room.
  • With shortcut: a <kbd> after the text, at 75% opacity. Saturdaze has no keyboard shortcuts yet; the docs site's own theme toggle (T) is the example.

Sizes

Tooltips have one size: caption text in a bubble that wraps at 240px.

States

Hidden until the trigger is hovered (after a short delay) or receives keyboard focus (at once). Here the bubble is forced open with data-open and the trigger with data-state; hover the "Hidden" column to see the real behaviour.

Both themes

Add an errand
Add an errand
  • Hover: shows after a delay so a passing pointer does not flash bubbles (300ms in this CSS; the product directive waits 400ms). A second tooltip within 600ms of the last one shows at once. It stays while the pointer moves onto the bubble (100ms grace) and hides when the pointer leaves both.
  • Focus: keyboard focus (:focus-visible) shows it at once; a mouse click that focuses the button does not.
  • Pressed: pressing the trigger hides the bubble so it never covers the result.
  • Disabled: a disabled trigger shows no tooltip. Explain why something is unavailable in visible text instead.

Responsive behaviour

  • Touch input never opens a tooltip (the directive ignores pointerType === "touch"), so on phones the only name is the aria-label and the icon. Choose icons that stand on their own, and give the phone layout text labels where it can (day header buttons show their label from 720px).
  • The bubble keeps 8px from the viewport edge and flips between above and below when it would not fit. It wraps at 240px rather than running off a 360px screen.
  • It closes when the page scrolls, so it never floats away from its trigger.

Theming

The bubble is the inverse of the surface: --colorNeutralBackgroundInverted behind --colorNeutralForegroundInverted. In light that is near-black slate with white text; in dark it flips to a light cream bubble with dark text, so it always reads over any card or photo. The product's tooltip-panel.scss still reads the retired --sd-ink and --sd-bg-elev tokens (D30); moving it to these two Fluent tokens gives it the dark theme for free.

Accessibility

Role and pattern

APG Tooltip. The bubble has role="tooltip" and an id. As a description it is linked from the trigger with aria-describedby, added only while it shows (any descriptions already on the trigger are kept). As a label it is aria-hidden and the trigger's aria-label carries the same words. Focus never moves into a tooltip.

Keyboard

KeyAction
TabFocusing the trigger shows the tooltip at once; moving focus away hides it.
EscHides the tooltip without moving focus. The key stops there, so the same Esc does not also close the dialog the trigger sits in.
Enter / SpaceActivate the trigger and hide the tooltip.

Focus

The trigger draws the shared ring; the bubble sits 8px away so it never covers the ring (2.4.11). Tooltips never trap or take focus.

Labelling

The trigger must be fully named without the tooltip: aria-label on icon-only buttons, visible text elsewhere. The tooltip text for a label must match that name word for word, so voice control users can say what they see (2.5.3).

Contrast

The shortcut <kbd> at 75% opacity stays well above 4.5:1 because the base pair is above 12:1 in both themes.

Motion

Opacity fades in over --durationFast after the delay; there is no movement. Under prefers-reduced-motion it appears without the fade.

Touch

Not shown on touch. It also meets 1.4.13 for pointer users: dismissible (Esc), hoverable (the pointer can move onto the bubble) and persistent (it stays until the pointer or focus leaves). The CSS-only .tooltip used on this page has pointer-events: none and is not hoverable; ship the directive, not the CSS alone.

Content

  • A label tooltip is the button's name: verb plus object, sentence case, no full stop. "Swap Lavender fields", "Add an errand", "More weekend options".
  • A description tooltip adds one short fact: "Locked blocks stay put". Under 60 characters; never two sentences.
  • Never the only place a fact lives, and never a repeat of visible text ("Regenerate" on a button that says Regenerate).

Sources
