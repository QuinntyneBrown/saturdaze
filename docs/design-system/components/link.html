Link

Links take someone to another page, another screen or another site: "Create an account", "Forgot password?", "Directions". They are always underlined, so colour is never the only clue.

Overview

Use a link when activating it only moves the person: to sign in, to the legal page, to a map. Use a button when it changes something (saves, copies, removes, opens a dialog). A link that looks like a button (a.btn, "Plan this weekend" on the landing page) is still a link and keeps link behaviour.

  • Inline (.link) sits inside a sentence or alone in an auth card: "New here? Create an account", "Forgot password?". Brand colour, semibold, underlined.
  • Soft (.link--soft) is for footers and legal rows where many links sit together: "Terms · Privacy · Back to Saturdaze". It takes the colour of the text around it and keeps a quiet underline.
  • With icon (.link.link--icon) is a standalone link with a leading or trailing icon, such as "Back to sign in" or an external link with the external glyph.
  • Details link (.details__link) is a URL shown as a value in a description list (the submitted event's Link on Review submissions). It wraps anywhere so long addresses never overflow.
  • Leg link (.leg__link) is "Directions" on a travel leg between two itinerary blocks. Sky blue to match the drive, with a 24px tall hit area.

Anatomy

  1. LabelNames the destination. Inline links inherit the size of their sentence; weight is semibold (.link) or regular (.link--soft).
  2. Underline1px, offset 3px, in the link colour (soft: --colorNeutralStrokeAccessible). Thickens to 2px on hover.
  3. Icon (optional)16px, currentColor, aria-hidden="true", 4px gap. External links add visually hidden "(opens in a new tab)".

Variants

Pick by where the link sits. Inside running text or an auth card use .link; in a row of utility links use .link--soft; for a URL that is itself the data use .details__link; on a travel leg use .leg__link.

External links

A link that leaves Saturdaze for a map, a menu or an event site opens in a new tab so the plan stays open. It shows the external icon and says so to screen readers. The mocks' Directions, Map and Details links already use target="_blank" rel="noopener" but do not yet announce it.

Sizes

Links take the type size of the text they sit in; standalone links use the size of their row (body in auth cards, caption on travel legs).

  • Hover deepens the colour and thickens the underline to 2px; soft links darken to the body colour and the underline takes the text colour. Details and leg links do not change on hover: they are already underlined and sit in dense rows.
  • Visited is not styled. Families revisit the same few screens every weekend, so a visited colour would mark almost every link.
  • Disabled does not exist for links. If the destination is not available, render plain text and say why nearby.
  • Current page belongs to navigation components (top bar, bottom nav) with aria-current="page", not to inline links.

Responsive behaviour

  • Inline links wrap with their sentence. Link text is never truncated.
  • Details links break anywhere (overflow-wrap: anywhere), so a long event URL wraps inside its column at 360px instead of pushing the page sideways.
  • Soft footer links wrap onto a second centred line on narrow phones; the middots stay between items because each is its own flex item.
  • Leg links keep a 24px tall hit area at every width; the travel leg wraps "Directions" under the time and distance when the column is narrow.
  • Hover styling applies only under (hover: hover); touch screens rely on the underline that is always there.

Theming

Links read alias tokens directly: --colorBrandForegroundLink and --colorBrandForegroundLinkHover for .link and .details__link, --colorPaletteSkyForeground1 for .leg__link, and the inherited text colour plus --colorNeutralStrokeAccessible for .link--soft. There are no component tokens; to re-skin links in one region, set color on a scoped class rather than editing .link.

/* Links on an inverted strip take its foreground */
.strip--inverse .link { color: var(--colorNeutralForegroundInverted); }

In the dark theme the link colour lightens to coral 300, which reads at 8:1 on the dark card. The sky leg link lightens the same way.

Accessibility

Role and pattern

Native <a href>; see the APG Link pattern. Never a <span> with a click handler, and never an <a> without href. If activating it changes data, it is a button.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the link in DOM order.
EnterFollows the link.
SpaceScrolls the page, as in every browser. This is why actions must be buttons.

Focus

The shared ring (2px --colorStrokeFocus2, 2px offset) on :focus-visible, drawn around the link's small radius. On a wrapped inline link the ring follows each line box.

Labelling

The link text is the accessible name and must make sense alone (2.4.4): "Create an account", not "click here". Repeated short links add visually hidden context: each "Directions" on the Weekend page names its destination ("Directions to Lavender fields at Terre Bleu"). Links that open a new tab end with visually hidden "(opens in a new tab)" and show the external icon.

Because links are underlined (drift D20), they do not rely on colour difference from the surrounding text (1.4.1).

Motion

None. The hover change is instant.

Touch

Links inside a sentence are covered by the inline exception of 2.5.8. Standalone links meet the 24px minimum: .leg__link sets min-height: var(--targetMin), and auth-card links sit alone on their own line with space around them.

Content

  • Name the destination, in sentence case: "Create an account", "Back to sign in", "Privacy".
  • Put the link on the words that say where it goes, not on "here" or "this": "New here? Create an account".
  • A question can be the link when it is the destination: "Forgot password?".
  • Show a raw URL only when the URL is the information (an admin reviewing a submitted link). Drop the scheme: "example.com/port-credit-buskerfest-2026".
  • Email addresses are links with mailto:: "hello@saturdaze.app".
