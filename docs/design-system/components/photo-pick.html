Photo pick

A grid of photos where exactly one is chosen. It picks a weekend's cover photo, or the photo a place shows next when its primary is removed. Each tile is a real radio button; the photo is what the family recognises.

Overview

Use photo pick when the choice is a picture and seeing it is how people decide: "Which photo goes on this weekend?" Every option is visible at once, so it suits two to six photos. For a choice between words, use a radio group or the segmented radio. To add a single photo with no alternatives, use file upload.

  • Cover photo (D29): the photos from the weekend's places, plus a "Your own photo" tile that opens the file picker.
  • Next primary (AD5, admin): when a place's primary photo is removed, the admin chooses which photo replaces it, or "No photo".
  • It is a single choice. Never use it to pick several photos; that needs checkboxes and a different selected treatment.

Anatomy

  1. Option tile.photo-pick__opt: a <label> at 4:3, --borderRadiusMedium, wrapping a transparent radio that covers the whole tile.
  2. Selected mark3px inset ring above the photo and a 20px check badge: a ✓ in --colorNeutralForegroundOnBrand on --colorBrandForeground1. Two cues, so selection does not rest on colour.
  3. Name pill.photo-pick__name: 12px caption on --colorBackgroundOverlayStrong, bottom left. It is the visible label.
  4. Upload or empty tile (optional).photo-pick__upload: dashed tile with an icon and a label. Holds a file input ("Your own photo") or a radio ("No photo").

Variants

One component, two jobs. The cover picker ends with an upload tile; the admin picker ends with a "No photo" radio so removing a photo can leave the place without one.

JPEG, PNG or WebP, up to 10 MB. Location data is removed before it is saved.

Cover photo (D29): three photos from the weekend's places and an upload tile.

Sizes

Photo pick has one size: tiles fill the grid columns at 4:3, so their size follows the dialog width, not a size modifier.

States

Hover and focus are forced with data-state on the tile. Selected comes from the real checked attribute; real pages get focus from :has(input:focus-visible) and hover from :hover on pointer devices.

Both themes

  • Selected shows the inset ring and the check badge together. Exactly one tile is selected whenever the dialog opens: the current cover, or the best candidate in AD5.
  • Hover darkens the photo slightly (pointer devices only). It never moves the selection.
  • Disabled is not used: a photo that cannot be chosen is left out of the grid rather than shown dimmed.
  • Uploading: after a file is chosen, a new tile with the preview appears before the upload tile and is selected; while it uploads, the dialog's primary button shows its loading state (see file upload).

Responsive behaviour

  • Under 576px the grid has two columns; from 576px (36rem) it has three. Tiles keep 4:3, so a 360px phone shows tiles about 150px wide.
  • Gap is --spacingHorizontalS (8px) at every width, which keeps neighbouring focus rings apart.
  • Name pills sit inside the tile and truncate by shortening the copy, not with an ellipsis: keep names to two or three words.
  • The dialog that holds the picker is a bottom sheet under 720px; a grid of more than six photos makes it scroll, so cap the options at six.

Theming

The tile reads --colorNeutralBackground3 behind the photo (seen while it loads), --colorBrandForeground1 for the selected ring and badge, and the overlay pair --colorBackgroundOverlayStrong / --colorNeutralForegroundStaticInverted for the name pill. The pill uses static colours because it sits on a photo, not on the theme surface, so it is identical in both themes.

In the dark theme the ring and badge lighten to coral 300 so they stand out against dark photos and the dark dialog. The dashed upload tile uses the accessible stroke, which the dark theme lightens to umber 400.

Accessibility

Role and pattern

Native radio buttons sharing one name, grouped by role="radiogroup" with an accessible name (aria-label, or aria-labelledby pointing at the field label as in AD5). This follows the APG Radio Group pattern, and the browser supplies the keyboard behaviour. The upload tile is a file input, not a radio: it is a separate Tab stop after the photos.

Keyboard

KeyAction
Tab / Shift+TabMoves focus into the group (to the selected photo) and out again. The upload tile is the next Tab stop.
→ / ↓Selects the next photo, wrapping from last to first.
← / ↑Selects the previous photo.
SpaceSelects the focused photo if it is not already selected. On the upload tile, opens the file picker.
EnterOn the upload tile, opens the file picker. On a radio it does nothing; the dialog's Save button confirms.

Focus

The radio is transparent and covers the tile, so the tile draws the ring: .photo-pick__opt:has(input:focus-visible) applies the shared 2px --colorStrokeFocus2 ring with a 2px offset. The ring sits outside the tile and the selected ring sits inside it, so both read at once on a selected, focused tile.

Labelling

Each radio carries an aria-label that starts with the visible name pill ("La Marina"), so speech users can say what they see (2.5.3). Because the radio is named, the photo inside the label takes alt="": a second description would be read twice and add nothing to the choice. When the photo itself must be described (a cover shown on a shared link), the alt text comes from the place's photo record, entered in AD1. The group's name says what is being chosen: "Choose a cover photo", "Next primary".

Over a photo the ring's contrast depends on the image, which is why selection always adds the check badge, a shape cue on its own disc.

Motion

Selection changes instantly; the hover darkening has no transition. Nothing on the tile animates, so reduced motion needs no special case.

Touch

The whole tile is the target. At 360px a tile is about 150 × 112px, far above 24px, and tiles are 8px apart.

Content

  • Name pills use the place's short name: "Lavender fields", "La Marina", "The Rec Room". Two or three words.
  • In admin, lead with the source, then the name: "Curated · The bandshell", "Provider · unreviewed". Write the radio's aria-label in the same order.
  • The upload tile says what it adds: "Your own photo". The empty choice says what happens: "No photo".
  • Put the file rules under the grid in a hint, not in the tile: "JPEG, PNG or WebP, up to 10 MB. Location data is removed before it is saved."
  • The confirm button names the result: "Use this photo", "Remove photo". Never "OK".
