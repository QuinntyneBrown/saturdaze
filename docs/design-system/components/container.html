Container and grid

Eleven small classes lay out every screen: a container that sets the page width and margins, stacks and clusters that space things, and grids that put cards and days side by side as the screen grows.

Overview

These classes own space so components do not have to. A component never sets its own outer margin; the stack, cluster or grid around it sets the gap. The tokens they read (columns, gutter, margin, maximum widths, breakpoints) are defined on the Layout foundation; this page shows how to use them.

  • Container (.container) centres the page at 1120px with a side margin equal to the gutter. .container--stack narrows it to 720px for single-column screens (Review submissions, Legal, the empty states).
  • Stack (.stack) spaces children vertically; cluster (.cluster) spaces them horizontally and wraps.
  • Grid (.grid) is the 4 / 8 / 12-column layout grid. The purpose-built grids (.grid-2, .grid-3, .grid-cards, .grid-days) are one column on phones and add columns at fixed breakpoints; use them first.
  • Scroller (.scroller-x) turns a row of filter chips into a swipeable strip on phones and lets it wrap from 720px. Bleed (.bleed) pulls a child to the screen edges. Sticky top (.sticky-top) pins a bar while its section scrolls.

Anatomy

  1. Margin--layoutMargin: the container's side padding, equal to the gutter (16 / 24 / 32px).
  2. Column--layoutColumns: 4 on phones, 8 from 720px, 12 from 1024px. The demo is live; resize the window.
  3. Gutter--layoutGutter: 16 / 24 / 32px between columns.

Sizes

The container has four widths, each a layout token. Pick by what the screen is for, not by how much content it has today.

WidthTokenUsed for
(1120px)--layoutContentMaxWidth · .containerWeekend, Ideas, Past, Family, every admin page.
(720px)--layoutStackMaxWidth · .container--stackSingle-column screens: Review submissions, empty states.
(680px)--layoutProseMaxWidthLegal text.
(440px)--layoutNarrowMaxWidthAuth column and the bottom nav.

Gaps come from the spacing scale: stacks 8 / 16 / 24 / 32px, clusters 8px, card grids 12px on phones then 16 and 20px.

Responsive behaviour

  • Breakpoints are in rem (23.75 / 36 / 45 / 64rem = 380 / 576 / 720 / 1024px at the default font size), so a person who sets a larger browser font gets the phone layout sooner instead of a squeezed desktop one (D24).
  • Everything is one column at 360px. Columns appear only when each one has room for its content: two cards at 720px, three at 1024px.
  • Margins equal gutters at every size, so the outer edge never looks tighter than the space between cards.
  • The page never scrolls sideways (1.4.10). The only horizontal scroll is .scroller-x, inside the page, and only under 720px.
  • Sticky headers sit under the top bar from 720px (top: var(--layoutTopBarHeight) on the day header) and at the top of the viewport on phones, where the bottom nav replaces the top bar. See Responsive.

Theming

The primitives read only layout and spacing tokens, which do not change between light and dark. A product that wants a denser layout changes --layoutGutter per breakpoint (and the margin follows) or overrides the component knobs --sd-stack-gap and --sd-cluster-gap on one element. Never set gaps with margins on children.

/* A tighter stack for one dialog body */
.dialog__body .stack { --sd-stack-gap: var(--spacingVerticalM); }

Accessibility

Role and pattern

No ARIA pattern: these are <div>s, or <ul> when the children are a collection (<ul class="grid-cards">), so screen readers announce how many items there are. Never put role="grid" on a CSS grid; the APG grid is an interactive widget with arrow-key navigation.

Keyboard

KeyAction
TabFollows DOM order, which must match the visual order at every breakpoint (2.4.3). Do not reorder with CSS order or grid-row beyond the page header's primary-first rule.
Tab in .scroller-xEach chip is a button, so tabbing scrolls the next chip into view; the scroller itself needs no tab stop.

Focus

Grid and stack gaps are at least 8px, enough for a neighbour's 2px ring at 2px offset to show in full. .scroller-x pads its ends by the page margin so the first and last chips' rings are not clipped. A sticky header must not hide the focused element under it (2.4.11): the page sets scroll-padding-top to the header height.

Labelling

A scroller of filters is role="group" with aria-label="Filters". A sticky region that scrolls on its own (like the demo above) needs role="region", a label and tabindex="0" so keyboard users can scroll it; the product's page-level sticky headers do not, because the page scrolls.

Contrast

Text on the page canvas
Secondary text on the page canvas

The primitives draw nothing themselves; a sticky header must carry an opaque background so text scrolling under it never shows through.

Motion

None. The scroller uses native scrolling and overscroll-behavior-x: contain, so a swipe never navigates the browser back.

Touch

Grid and cluster gaps keep at least 8px between targets. The scroller is reachable by swipe and by keyboard; nothing in it is hidden behind a hover.

Content

  • A grid holds items of one kind (all ideas, all past weekends). Mixing a stat card into a grid of idea cards breaks the comparison.
  • Keep card text in a grid to similar lengths (clamp bodies to two lines) so rows line up and footers align.
  • One item does not need a grid; two items in .grid-cards leave a gap at 1024px, so use .grid-cards--2.
