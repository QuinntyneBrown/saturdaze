Foundation

Iconography

Icons in Saturdaze are thin, rounded line drawings that sit beside words. They help a parent scan a weekend (drive, food, outdoors, locked) and they never stand in for a label nobody can read.

Overview

Every icon is a symbol in one inline SVG sprite and is drawn with a <use> reference, so it inherits the text colour and scales with the type around it:

<svg class="icon" aria-hidden="true"><use href="#i-lock"/></svg>

The first 40 icons are copied verbatim from the mocks (docs/mocks/app.js). The design system adds 10 more for core components the mocks do not use yet: alerts, selects, search, uploads and links that leave Saturdaze. The product renders the same paths through sd-icon.

FillNone. .icon--filled swaps the stroke for a fill for "on" states.
ColourcurrentColor: an icon is always the colour of the text beside it, so it follows the theme with no extra tokens.

Sizes

Size follows the text the icon sits beside. Pick the class for the context; never scale an icon with a raw width.

Components also size their own icons: chips 13px, filter chips and field errors 14px, the chip remove glyph 10px inside a 24px hit area. Those are part of each component, not new sizes to reuse.

The set

Each icon has one meaning in Saturdaze. If a new idea needs an icon, add a new one rather than lending an existing one a second job. Icons marked Added come from the design system, not the mocks.

Two meanings to untangle. arrow_right and chevron_right (and arrow_left) draw the same chevron; keep them apart by meaning, so a later redraw of the arrows does not change every row. The admin mocks also use star for "Make primary" photo, a second job for the rating icon; give that action its own icon or the check it already sits beside.

Filled

Line icons are the resting state. A filled icon means "on": a chosen star, a favourite, a vote cast. The change of shape carries the state as well as the colour, so it survives forced colours and colour blindness.

Stars use .icon--filled; pressed buttons fill through aria-pressed="true", with no extra class.

Weather

Weather icons sit in a 40px .weather-disc at the start of each day header. The disc tint matches the sky: sun on the sun palette, cloud and rain on the sky palette. Snow has no tinted disc yet and uses the neutral one.

Saturday · 22° / 14° Sunday · 18° / 12° Rain from 2pm Snow
Here the discs are named (role="img", aria-label) because the text beside them does not say the condition.

In the Weekend mock the disc is aria-hidden, and Sunday's meta says "Cloudy by 2pm", so nothing is lost. Saturday's meta says "22° / 14° · Light breeze" and never says sunny, so the sun is the only place the forecast appears. Either add the condition to the meta ("Sunny · 22° / 14°") or name the disc.

Brand mark

The brand mark is not an icon in the sprite: it is a 26px rounded square in the mock coral (--colorBrandBackgroundStatic) with a coral and sun glow, always beside the word "Saturdaze". It is decorative (aria-hidden="true"); the word is the link text.

Usage

Labelling

  • Decorative icons (beside a visible word) always carry aria-hidden="true" on the <svg>. Screen readers hear the word once.
  • Icon-only buttons name the action with aria-label: "Close", "More weekend options", "Swap Lavender fields". The label names the action, never the icon ("Close", not "X icon").
  • Icons that carry information alone (a weather disc with no condition text, a lock with no "Locked" chip) go on a wrapper with role="img" and an aria-label, or get visible text.
  • Status is never an icon alone: banners pair info, alert or check_circle with a title.
  • On pointer devices, icon-only buttons may add a tooltip with the same words as the label.

Accessibility

Icons that carry meaning need 3:1 against what is behind them (1.4.11). Because they inherit currentColor, they pass wherever their text does; the pairs to watch are tinted discs and the faint chevron at the end of a row.

  • The current bottom-nav icon was coral on coral tint at 2.6:1 (D10); filled stars were 1.57:1 and empty stars 2.54:1 (D09). Both now use the tokens above.
  • In forced-colours mode icons take the system text colour automatically, because they are currentColor strokes, not images.
  • Icons scale with the text size setting because sizes are in rem.

Tokens

Icons have no tokens of their own: they take currentColor from the text they sit beside, and their sizes are component classes.
